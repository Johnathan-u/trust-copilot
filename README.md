# Trust Copilot

AI-assisted questionnaire and evidence platform for security and compliance. Upload customer questionnaires (SOC2, ISO, vendor due diligence), parse them, retrieve relevant evidence from uploaded documents, generate AI draft answers with citations, and export completed responses back into XLSX.

## Quick start

**Easiest:** `.\scripts\start.ps1` (Windows) — starts services, runs migrations, seeds demo.

Or manually:

1. **Start services**
   ```bash
   docker compose up -d
   ```

2. **Run migrations**
   ```bash
   docker compose exec api alembic upgrade head
   ```
   Or locally: `.\scripts\run-migrations.ps1`

3. **Set env** – Copy `.env.example` to `.env`, set `OPENAI_API_KEY` for AI generation and embeddings.

4. **Open** http://localhost:3000 (Caddy serves app and API on port 3000).

## Auth & access

- **Demo login (local only):** `demo@trust.local` with the password from `TC_SEED_DEMO_PASSWORD`, or, if unset, the one generated by the seed script into `apps/api/.seed-credentials.local` (git-ignored). The previously documented demo password is retired (TC-07-001) and does not work.
- **Registration:** `/register` — create account; verification link is sent (email stub in dev). Verify at `/verify-email?token=...`.
- **Password reset:** `/forgot-password` → email link → `/reset-password?token=...`. No auto-sign-in after reset.
- **Workspace switching:** In the dashboard, use the workspace dropdown in the header (when user has multiple workspaces).
- **Roles:** Admin, editor, reviewer, with RBAC on uploads, exports, and Trust Center admin. See [Auth & SSO](docs/security/AUTH_AND_SSO.md).
- **Production:** Set `SESSION_SECRET`, `FRONTEND_URL`; use a real email provider for verification and reset. CSRF uses Origin/Referer; rate limiting on login. See [Production secrets](#production-secrets).

## Workflow

1. **Documents** — Upload evidence (PDF, DOCX, XLSX). Files are parsed, chunked, and embedded for retrieval.
2. **Questionnaires** — Upload questionnaires (XLSX). Questions are parsed and linked to source cells.
3. **Review** — Open a questionnaire, click **Generate answers** (requires `OPENAI_API_KEY`). Edit answers inline, set status, use filters and bulk actions.
4. **Export** — Click **Export XLSX** to produce an XLSX with answers written back into the uploaded workbook. Download from Recent exports. (Exact placement in the original layout is not yet verified; see TC-13-001/TC-13-002.)

## Architecture

```
┌─────────────┐     ┌──────────┐     ┌─────────────────────────────────────┐
│   Browser   │────▶│  Caddy   │────▶│  Web (Next.js)  │  API (FastAPI)    │
│             │     │  :3000   │     │  :3000          │  :8000            │
└─────────────┘     └──────────┘     └─────────────────────────────────────┘
                           │                    │
                           ▼                    ▼
                    ┌──────────┐          ┌──────────┐
                    │ Postgres │          │  MinIO   │
                    │ pgvector │          │  S3      │
                    └──────────┘          └──────────┘
                           ▲
                           │
                    ┌──────────┐
                    │  Worker  │
                    │ (async)  │
                    └──────────┘
```

- **Caddy** — Reverse proxy; `/api/*` → API, else → Next.js.
- **API** — FastAPI; auth, documents, questionnaires, answers, jobs, exports, search, trust articles.
- **Worker** — Polls jobs; runs `parse_questionnaire`, `index_document`, `generate_answers`, `export`.
- **Postgres** — With pgvector for embeddings.

## Environment

### Production secrets

**Operators must generate every secret for each deployment.** No value that was ever committed to this repository
(in code, compose files, `.env.example`, tests, scripts, docs or git history) may be used in production: all of them
are **retired** (owner statement 2026-10-27, TC-07-001) and must never be reused.

- Generate every secret yourself, e.g. `openssl rand -hex 32` (use hex for passwords inside URLs) or `openssl rand -base64 48`. This applies to `SESSION_SECRET`, `POSTGRES_PASSWORD` (and the password in `DATABASE_URL`),
  `MINIO_ROOT_USER`/`MINIO_ROOT_PASSWORD`, `S3_ACCESS_KEY`/`S3_SECRET_KEY`, and every provider client secret.
- Keep them only in `.env.production` (git-ignored) or your secret manager; never commit them.
- Do not run any `seed_*` script against production; demo/QA accounts and their passwords are local-only.
- Production startup validation of these values (refusing unset, placeholder or default values) is defined by TC-03-001's
  config contract: see [docs/release/config-contract.md](docs/release/config-contract.md) and run
  `cd apps/api && python -m app.core.config_contract check`.

### Key rotation

Session signing, OAuth state, MFA and connector encryption can each have a versioned keyring
(`SESSION_KEYRING`, `OAUTH_STATE_KEYRING`, `MFA_KEYRING`, `CONNECTOR_KEYRING`). The first
`kid:secret` is current; the rest are retired. Leave a variable unset to keep deriving
`v0-legacy` from `SESSION_SECRET`. Explicit keyrings must retain the previous root as
`v0-legacy` to read legacy ciphertext; retired session cookies are rejected, including
unprefixed cookies. Rehearse on a copy, never on production:

`cd apps/api && python scripts/rotate_purpose_keys.py --dry-run`

The command prints counts only. An MFA secret it cannot open is marked `reenrol.<kid>`.
Password login then fails with `mfa_reset_required` and does not start a session. An
active administrator of that workspace authorizes enrollment with
`POST /api/members/clear-mfa-reenrol/{user_id}`. The next password login grants only a
five-minute enrollment session; workspace access resumes after successful TOTP confirmation.
See [docs/release/config-contract.md](docs/release/config-contract.md)
and [docs/release/tickets/TC-07-002.md](docs/release/tickets/TC-07-002.md).

See `.env.example`. Required: `DATABASE_URL`, `SESSION_SECRET`, `S3_*`. Optional: `OPENAI_API_KEY` (needed for embeddings and answer generation).

## Commands

| Command | Purpose |
|---------|---------|
| `docker compose up -d` | Start all services |
| `docker compose exec api alembic upgrade head` | Run migrations |
| `cd apps/web && npm run dev` | Run web dev server |
| `cd apps/api && pip install --require-hashes -r requirements-dev.lock && pip install --no-deps -e .` | Install the locked API dependencies (runtime + dev tools; production uses `requirements.lock`) |
| `scripts/lock-python-deps.sh` | Regenerate both API locks after editing `apps/api/pyproject.toml` (needs `uv`; see [TC-02-002](docs/release/tickets/TC-02-002.md)) |
| `cd apps/api && uvicorn app.main:app` | Run API |
| `cd apps/api && pytest tests/ -v -m "not integration"` | Run tests (DB-dependent tests skip without Postgres). |
| `npm run test:e2e` | Run registry lifecycle E2E tests. Starts Postgres, MinIO, migrations, seeds, API, and Web; runs Playwright. Requires Docker and Python. |
