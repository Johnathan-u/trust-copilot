# TC-01-003b acceptance evidence

All data is synthetic: the PDFs are generated by `app/services/synthetic_pdf.py` from
`apps/api/tests/pdf_locator_corpus.py`, plus the repo's own fixture PDF. There are no model calls
and no outside services; the comparison runs used `--network none`.

## Environment
- Branch tests: image `tc-core-api-test:c20f949-sa20-nopymupdf` (Python 3.12, pypdf 6.21.2,
  PyMuPDF not installed), Postgres 16 on an isolated docker network, `OPENAI_API_KEY` empty.
- Backend comparisons: image `tc-core-api-test:c20f949-sa20-pdf`, the same plus pymupdf and
  pdfplumber, used only to produce the comparison tables (not a dependency of the app).

## Files
- `compare_table_rows.py` scores the questionnaire parser on the new same-line table-row corpus
  (`table_row_corpus()`) for each text path: PyMuPDF (pre-TC-01-003a), pdfplumber, plain pypdf
  (PR #11) and this branch. Output: `table_rows_comparison.md`.
  Result: PyMuPDF 22/26 (it splits the justified question word by word and drops two questions),
  pdfplumber 6/26, PR #11 10/26, **branch 26/26 with no wrong questions**.
- `backend_comparison_149.md` is the TC-01-003a script `compare_backends.py` rerun on this
  branch: **pypdf 149/149** (unchanged), PyMuPDF 145/149, pdfplumber 125/149.
- `focused_tests_branch.txt`: PDF, upload, parse, indexing, export, jobs and ingestion tests on
  the branch, with the DB: **171 passed, 0 skipped**.
- `full_base_summary.txt` / `full_branch_summary.txt`: full API suite on `e57b849` and on the
  branch. Base: 1360 passed, 2 failed, 2 skipped, 2 collection errors. Branch: **1433 passed** (+73
  new tests), with the same 2 failures, 2 skips and 2 collection errors. Those exist on master
  too and are unrelated (`test_answer_pipeline::test_partial_completion_progress`,
  `test_p1_multi_tenant_hardening::...quota`, collection errors in `test_alerts_api` and
  `test_coverage_api`).
