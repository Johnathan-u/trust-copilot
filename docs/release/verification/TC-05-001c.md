# TC-05-001c — Enforce target workspace MFA on switch-workspace

This is the implementation decision for independent review. It does not accept
the ticket and it does not change the backlog tracker.

## AC2 decision

Record `mfa_satisfied` on the stored session at challenge time. Switch grants
the target role only when that flag is true. Otherwise it returns the same
`{"requires_mfa": true, "mfa_token": ...}` body password login returns, and it
does not set a cookie.

`UserSession` had no field that said a challenge had succeeded.
`POST /api/auth/mfa/verify-login` inserted an ordinary session row after a
TOTP or recovery code, with the same shape as a password login that never saw
a factor. A cookie reissue on switch cannot be the source of truth: the client
can hold an older cookie, and the row is what `enforce_session_record` already
loads. A boolean column, default false, fails closed for every existing row
and for every new row that is not created by a completed challenge.

The flag is set true in exactly two places, both of which create the session
row only after a code has verified:

- `mfa_verify_login`, including a recovery code, because that endpoint already
  treats the recovery code as completing the login challenge.
- `mfa/confirm` when it deletes the enrol-only session and inserts the
  replacement. That new row exists because the TOTP code just verified.

A voluntary confirm on a session that was already signed in does not replace
the row. That session was established without a challenge, so
`mfa_satisfied` stays false. Switching it into an `mfa_required` workspace
requires a fresh challenge.

The signed cookie does not carry the flag. Switch reads the row. A missing
row, a database error, or false all refuse the target role.

## What switch does

1. Membership and suspension are unchanged. The target revocation cutoff still
   runs before any cookie is issued.
2. `workspace_requires_unmet_mfa` (the login helper) decides enrol-only. No
   enabled factor and `mfa_required` produce the five-minute, non-persistent
   `mfa_enrol` cookie: role `mfa_enrol`, `mfa_enrol_only`, no `Max-Age`.
   Protected routes stay denied. Confirming enrolment still replaces that
   cookie with the member role, and that replacement row is `mfa_satisfied`.
3. An enabled factor (not an administrator re-enrolment and not a reset
   marker) whose row is not `mfa_satisfied` gets `_mfa_challenge_response`.
   That is the function password login now uses: a five-minute
   `MfaLoginToken` for the target workspace and role, audit `auth.mfa_required`,
   and no session cookie. The browser stays on the current workspace.
4. A target with `mfa_required` false is unchanged, including when the user
   has an enabled factor and the session is not satisfied.
5. After a switch that changes the cookie, the client applies the switch
   body and reloads `GET /api/auth/me` when that read names the same workspace.
   That reload is where `mfa_required_for_workspace` is computed. A `/me`
   payload that still names the previous workspace is ignored, so it cannot
   undo the switch. A challenge response does not copy the target role into
   auth state. It opens the existing login challenge on the login page,
   passing the one-time MFA token as a query parameter.

## Migration

`alembic/versions/tc05001c_mfa_satisfied.py` is the single head. It revises
`tc17001_article_versions`. Upgrade adds `user_sessions.mfa_satisfied boolean
not null default false`. Existing rows become false. Downgrade drops the
column. Upgrade again sets every row false; a true value from before the
downgrade is not restored. Losing the flag forces a challenge on the next
switch into an MFA workspace, which is the fail-closed direction.

The round trip is `tests/release/test_tc05001c_mfa_satisfied_migration.py`.
PostgreSQL execution of the same revision is the CI `build` migration step.
Local evidence here is SQLite for the migration module and for the switch
cases. The switch cases are also parametrized for the migrated test database;
that leg skipped locally because no test Postgres was configured.
