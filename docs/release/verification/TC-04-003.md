## Gaps
1. On a successful reset, revoke every unused reset token for that user, not only the row in `auth.py:530`. Decide and record whether verification rows and MFA recovery codes die with the reset. `change_password` (`auth.py:561-571`) should drop the other sessions, and the current session, without waiting for `invalidate_other_sessions`, or the release note should say the flag is the policy and the client always sends it.
2. Extend the reset test. After one reset, a second unused token returns 400. A cookie from before the reset is 401 on a second client. A password change without the flag leaves no usable session. The old password stays 401 and the new password can sign in.
3. Add `apps/api/tests/release/test_password_reset.py`, `artifacts/acceptance/TC-04-003/`, and `docs/release/tickets/TC-04-003.md`. The backlog command is `python -m pytest tests/release/test_password_reset.py -q`.
