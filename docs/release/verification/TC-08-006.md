## Gaps
1. Keep the approved answer visible and mark that revision stale when its source document is archived or replaced. The historical text stays. `Answer` (`answer.py:20-44`) needs a revision bound to the document that supported it, and archive must set the stale marker instead of leaving `status` at `approved`.
2. Stop retrieval from returning chunks whose document is soft-deleted or has been replaced. Keyword search (`retrieval.py:235-256`) and semantic search (`retrieval.py:300-306`) need the `documents.deleted_at` exclusion, and archive needs the corpus-version bump that index already does after a successful reindex (`index_service.py:201-210`). The pre-index `superseded` path (`worker.py:559-562`) stays. It does not remove chunks that are already stored.
3. Block final export while an included answer cites a revoked source or is still the stale revision. `enqueue_export_job` (`export_service.py:51-69`) and `run_export` (`worker.py:766-792`) currently write that text. Allow the file after a new revision is approved against a document that is still active.
4. Add `apps/api/tests/release/test_archive_revalidation.py`, `artifacts/acceptance/TC-08-006/`, and `docs/release/tickets/TC-08-006.md`. The test covers archive and replacement, asserts the old revision is still readable and marked stale, asserts the next retrieval misses that source, and asserts export stays blocked until the new revision is approved. The backlog command is `python -m pytest tests/release/test_archive_revalidation.py -q`.
