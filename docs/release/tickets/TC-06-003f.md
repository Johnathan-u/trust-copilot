## Behavior

The real sync API produced correctly scoped graphs, but later freshness reads
loaded evidence, golden answers, controls and answers by ID alone. After a source
moved to another workspace, the original workspace could still observe its
current timestamps. Chain traversal also looked up predecessor nodes by ID alone,
exposing a moved node's new foreign label/metadata. The cached answer node kept
chains readable after the actual answer parent moved, was archived or was deleted.

Only `_freshness_bucket` and `chain_for_answer` change. Freshness queries now
scope the four source types to the authorized graph node's workspace; answers
resolve their current question/questionnaire ownership. Before using the cached
answer node, chains require a current answer under an active same-workspace
questionnaire. Every traversed node also must belong to that workspace.

Existing session permissions, response fields and route 404 bodies remain.
Unavailable chain roots return `Answer not in proof graph`; direct unavailable
graph nodes retain `Node not found`. Missing or foreign freshness sources use
the existing fallback: `stale` for evidence/golden/control and `aging` for answers.
Own age buckets and golden expiry behavior remain unchanged. An owned archived
answer's direct freshness endpoint retains its existing age behavior; the active
parent requirement applies to the live chain root.

Cached fields of still-owned graph nodes are retained when their source moves;
they no longer read that foreign source's current dates. This does not establish
a new snapshot/history/deletion-retention policy. All routes, remaining service
functions, models, auth, dependencies and existing tests are unchanged.

## Acceptance evidence

The new suite has 69 SQLite cases and the same 69 migrated-PostgreSQL cases.
It creates graphs through actual HTTP sync in two owned workspaces, using real
stored users/memberships/sessions and expiring signed cookies. Only `get_db` is
wired to the fixture. SQLite asserts FK enforcement; PostgreSQL uses the existing
`migrated_db` fixture and actual constraints. No schema, trigger or FK is bypassed,
and no provider, model or storage call is needed.

Cases cover all four age buckets and source kinds, golden expiry, missing-source
fallbacks, current foreign dates, moved graph predecessors, archived/moved/deleted
chain parents, uncached answers, full own output fields, all existing signed-in
read roles and current membership/session denials. Source/node moves and cascading
deletions are ordinary persisted changes to fixture-owned rows. Graph nodes and
edges originate from sync, not a fabricated cross-tenant graph fixture.

Every read/denial compares full-row counts and hashes across twenty source, graph
and authentication tables. SQL observation rejects INSERT/UPDATE/DELETE even if
later rolled back. API flushes record exact created IDs; cleanup deletes only
owned IDs in FK order and compares the complete original snapshot. No sequence
reset or global cleanup is used. Collection creates no fixture stores/connections.
