## Problem

A recorded export hash must match the object or the download is refused. Question rows store content and file hashes. An export with no recorded hash still downloads, and document rows have no hash column. Priority is P1 because the parent is P1.

## Acceptance criteria

1. Store a hash for the document object and for the export record, and make the record and the object agree on hash, version, type, and workspace.
2. Refuse the download when the recorded hash is missing or does not match, and do not stream an export that has no recorded hash.
3. Document the behaviour in this file.

## Scope

P1 follow-up from the #314 review. It does not change the DONE count.

## Behaviour

Document upload stores SHA-256, version 1, and the filename media type on the row and on the object (`documents.py` upload, `file_service.py` `upload_raw`). The export worker stores the same three fields on `export_records` when it writes the object (`worker.py` `run_export`). The download recomputes the hash of the bytes and returns them only when the hash, version, type, and workspace agree.

A missing hash, a mismatch, a missing object, or a disagreement is refused. The body is a fixed error, with `X-Content-Type-Options: nosniff`, and it does not include the key or the hash. `validate_storage_key` still runs first. Session checks are unchanged.

Existing rows keep a null hash and are refused. `python -m app.services.storage_checksum --execute` hashes the current object when the key's workspace matches and the object exists. It does not write a hash for a cross-workspace key, a missing object, or an export whose job hash does not match the bytes. Downgrade drops the columns. The runbook is `docs/ops/storage-checksums.md`. The parent note is `docs/release/tickets/TC-10-006.md`.
