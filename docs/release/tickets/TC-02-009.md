# TC-02-009: Retain redacted release and failure evidence

This file records the implementation. It does not accept TC-02-009. AC1 and AC2 stay unverified until an independent reviewer accepts them. No migration was added. No customer document is in the evidence. The children TC-02-009a and TC-02-009b are implemented here and are not counted toward DONE by this file.

## What the check does

`build` and `web-release-e2e` each print a `TC-02-009 evidence` block. The block names `github.sha`, the container digest or `image: none`, the test command, and passed, failed, and skipped totals. The e2e block also names Playwright and axe totals. Generated passwords stay behind `::add-mask::`. Playwright reports and trace zips are redacted before upload. Every upload keeps `retention-days: 14`.

No workflow deploys GitHub Pages. A `workflow_run` Pages job that ignores `github.event.workflow_run.conclusion` is rejected by the checker. `deploy.yml` does not use `workflow_run` and cannot mark a failed CI run successful.

The runbook is `docs/ops/ci-evidence.md`.

## Contract

The test commands are unchanged: `pytest -rs` in `build`, and the same Playwright and axe commands in `web-release-e2e`. The rules run also writes a JSON report so its totals can be counted. Uploads still use `actions/upload-artifact@v4`. A Playwright upload now waits until redaction has succeeded. No request or response field changes. No migration.

`docs/ops/ci-evidence.md`.
