# TC-10-006: Persist original and export hashes in private storage

This file records the implementation. It does not accept TC-10-006. AC1 and AC2 stay unverified until an independent reviewer accepts them. This change adds migration `tc10006_storage_checksums` and changes document and export downloads. No customer document is in the fixture or the evidence. The children TC-10-006a and TC-10-006b are implemented here and are not counted toward DONE by this file.

## What the check does

A document upload stores a SHA-256 of the object, version 1, and the media type taken from the filename. The worker stores the same three fields on the export record when it writes a completed export, and the job result uses that same hash. The download returns the bytes only when the row and the object agree on hash, version, type, and workspace.

A missing hash, a hash that does not match the bytes, a missing object, or a version, type, or workspace disagreement is refused. The body is not the file. It does not include the storage key or the hash. `X-Content-Type-Options: nosniff` stays on the refusal and on the successful stream. `validate_storage_key` still runs before any read. The session checks from TC-07-008 are unchanged.

Rows that already exist keep a null hash. They are refused until `python -m app.services.storage_checksum --execute` hashes the current object. The command does not bless a cross-workspace key, a missing object, or an export whose job hash does not match the bytes. Downgrade drops the columns. A later upgrade leaves them null, and downloads stay refused until the command runs again.

The runbook is `docs/ops/storage-checksums.md`. There is no new setting.

## Contract

Document and export downloads still require the same roles. A bad storage key is still 400 and still does not echo the key. An export whose bytes do not match is still 409 `export_storage_failed`. An export with no recorded hash is now that same 409, instead of a stream. A document whose hash is missing or does not match is 409 with the fixed detail `The stored file could not be verified.` An id from another workspace is still 404. An archived document is still not streamed. No response field was added to the document list. No presigned URL is returned.
