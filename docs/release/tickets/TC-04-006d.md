## Design and scope

The existing server enforces the earlier of signed expiry and the current tenant
cap measured from the stored session creation time. `GET /auth/me` will expose
that computed deadline as `session_expires_at` plus `server_time`, both Unix
seconds, without changing authentication, lifetime or persistence semantics.

The existing client auth context will carry this additive metadata. A small
dashboard banner warns during the last five minutes; this is a display threshold,
not an idle or absolute lifetime policy. Its countdown uses elapsed monotonic
time and the server timing pair, conservatively accounting for request duration.
The server recheck waits until the response-receipt upper bound on that deadline;
the brief latency gap shows a pending check, never extra remaining lifetime.
It offers no session extension. Existing login redirects remain authoritative
after a server denial.

Revalidation runs at the reported deadline and when a hidden tab becomes visible,
as well as existing explicit refresh/workspace-switch flows. Superseded responses
cannot restore older auth or deadline state. Timers, requests and visibility
listeners are cleaned up. Failed or malformed timing checks suppress a precise
countdown and offer a truthful retry notice. There is no periodic auth polling.

Remote policy shortening/revocation continues to take effect on the next server
request. This display does not claim continuous synchronization, push logout,
idle tracking or idle-timeout qualification. No new dependency, migration,
provider, session extension or unrelated auth-route change is included.
