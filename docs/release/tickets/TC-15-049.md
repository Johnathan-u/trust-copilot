## Delivered behavior

The deals page lists the current workspace and lets an admin create or edit a typed stage, a decimal amount, an explicit currency, and expected and actual close dates. That contract is unchanged from TC-15-049a.

Each row offers **Links and risk**. Opening it reads the existing endpoints:

| Action | Route | Who sees the control |
| --- | --- | --- |
| Read scoped risk | `GET /api/deals/{id}/risk` | any signed-in session |
| Read the deal room | `GET /api/deals/{id}/room` | any signed-in session |
| Link a questionnaire | `POST /api/deals/{id}/link-questionnaire` | admin only (`can_admin`) |

Linked questionnaire ids are the ids already on the deal record. An admin submits one positive whole id. Editor, reviewer, and any other signed-in role without `can_admin` see the reads and do not see the id field or the link button. The page does not invent an owner or viewer role.

The room route mints a new unstored access token on every read. The page requires that token so a partial body fails, and it does not render the token.

Amounts stay decimal strings. A null revenue-at-risk value is shown as not recorded. The page does not add a currency, a zero total, or a pipeline sum.

## States

Loading, empty, denied, not-found, error, partial, and success are separate.

- Risk and room each stay on a loading message until that read returns. A score is not shown early.
- No linked ids, an empty in-workspace room, and no published articles are empty states. A valid zero score is still a score.
- 401 and 403 use the existing failure copy and are distinct from the empty room. 404 is not-found. A 5xx response and a failed connection are errors.
- A risk or room body that does not parse, disagrees with its own summary or counts, or names a different deal is an error for that section only. The other section can still render. Nothing from the bad body is shown.
- A link is acknowledged only when the response is a deal for this id and workspace and the submitted questionnaire id is in `linked_questionnaire_ids`. A malformed body, another workspace, another deal, or a missing id keeps the form and does not say the questionnaire was linked. If the reloaded list omits that id, the success text is replaced.
- After a valid acknowledgment the list reloads. If the reload fails, the message says the questionnaire was linked and the list could not be refreshed.
- A typed id asks for confirmation before the panel closes, and the browser warns before unload.
- Changing workspace or admin permission remounts the page, aborts in-flight work, and drops a late result. Switching deals does not apply the previous deal's read.

An uncertain link retries with the same idempotency key until the id changes. A second submit while the first request is in flight is ignored.

## Runbook

1. Open Deals and choose Links and risk on a row.
2. Read the linked ids, the risk breakdown, and the room's questionnaires and articles.
3. An admin links a questionnaire by entering its id and choosing Link questionnaire. A 404 means the deal or the questionnaire is missing or outside this workspace; nothing is linked. A 403 means this account cannot link.
4. A reader does not get the link form.
5. CRM sync history is not on this page. Do not treat a linked questionnaire as a CRM sync.

No new configuration. No migration.
