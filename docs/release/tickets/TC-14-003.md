# TC-14-003 — Dialog focus and accessible notifications

## Behavior

`Dialog` is the shared modal primitive. Opening it moves focus inside, Tab and Shift+Tab stay inside, Escape closes it, and focus returns to the control that opened it. The rest of the page is `inert` and `aria-hidden` while it is open. The dialog is named by its title (`aria-labelledby`) and, when copy is provided, described by that copy (`aria-describedby`).

Destructive confirms use `role="alertdialog"` and move the first focus to Cancel. `window.confirm` on the dashboard card, alert rule, session, Slack, Gmail and trust-article deletes now uses that confirm. Registry delete and bulk delete, and the member danger/warning confirms, use the same role.

`placement="drawer-start"` and `placement="drawer-end"` are part of the same primitive so the navigation drawer in TC-14-006 (PR #15) can adopt it later. This change does not edit that branch.

Toasts use `role="status"` and `aria-live="polite"` for success, info and warning, and `role="alert"` with `aria-live="assertive"` for errors. They do not take focus. The dismiss control is a button. Errors are not given a dismiss timer. `prefers-reduced-motion: reduce` drops the toast opacity transition. `apiErrorAnnouncement()` keeps `formatApiErrorDetail` and maps a failure onto that persistent error announcement.
