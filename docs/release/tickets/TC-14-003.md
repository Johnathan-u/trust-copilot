# TC-14-003 — Dialog focus and accessible notifications

## Behavior

`Dialog` is the shared modal primitive, used only for real dialogs. Opening it moves focus inside, Tab and Shift+Tab stay inside, Escape closes it, and focus returns to the control that opened it. The rest of the page is `inert` and `aria-hidden` while it is open. The dialog is named by its title (`aria-labelledby`) and, when copy is provided, described by that copy (`aria-describedby`).

Destructive confirms use `role="alertdialog"` and move the first focus to Cancel. `window.confirm` on the dashboard card, alert rule, session, Slack, Gmail and trust-article deletes now uses that confirm. Registry delete and bulk delete, and the member danger/warning confirms, use the same role.

`placement="drawer-start"` and `placement="drawer-end"` are part of the same primitive so the navigation drawer in TC-14-006 (PR #15) can adopt it later. This change does not edit that branch.

The notifications panel is a disclosure popover, not a dialog. It does not trap focus and does not mark the page inert. The bell has `aria-expanded` and `aria-controls` pointing at the panel. Escape and a click outside the panel close it and return focus to the bell.

Toasts use `role="status"` and `aria-live="polite"` for success, info and warning, and `role="alert"` with `aria-live="assertive"` for errors. They do not take focus. The dismiss control is a button. `Toast` owns the dismiss timer. Success, info and warning leave after 4000ms, including the review page's draft-ready and export-ready toasts. A toast that renders an action button (Undo, View, Retry, or any control other than dismiss) does not auto-dismiss. The timer is omitted rather than paused on hover or focus, so the action has no time limit (WCAG 2.2.1 Timing Adjustable). Errors stay until dismissed. `prefers-reduced-motion: reduce` drops the toast opacity transition and does not change the timer. `apiErrorAnnouncement()` keeps `formatApiErrorDetail` and maps a failure onto that persistent error announcement.
