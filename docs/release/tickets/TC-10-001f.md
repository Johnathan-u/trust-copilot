## Acceptance criteria

1. Document the multixact fallback. Under a concurrent key-share lock, detection misses and the code falls back to the `statement_timestamp()` check. That fails safe: the worst case is a `LeaseLost` retry, and never a stale commit. The limitation is not written in the repo today. Add it to the `_transaction_locks_job` docstring in `job_lease.py` and to `TC-10-001.md`.
