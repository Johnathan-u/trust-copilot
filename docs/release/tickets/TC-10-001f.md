# TC-10-001f: document the multixact fallback

Follow-up of TC-10-001. Ruled on issue #85 (R9, [comment 6896794377](https://github.com/Johnathan-u/trust-copilot/issues/85#issuecomment-6896794377)) and in Claude's post-merge review of #219 ([comment 6896797192](https://github.com/Johnathan-u/trust-copilot/pull/219#issuecomment-6896797192)).
Epic E10. Points were not assigned. Docs only. Depends on TC-10-001. Closed by the coordinator. Not an original-parent acceptance.

## Acceptance criteria

1. Document the multixact fallback. Under a concurrent key-share lock, detection misses and the code falls back to the `statement_timestamp()` check. That fails safe: the worst case is a `LeaseLost` retry, and never a stale commit. The limitation is not written in the repo today. Add it to the `_transaction_locks_job` docstring in `job_lease.py` and to `TC-10-001.md`.
