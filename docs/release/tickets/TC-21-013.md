**Status:** implemented locally. Not pushed. Framework catalogs stay **BLOCKED** pending **TC-01-007**. No framework requirement text was added. No migration.

`apps/api/app/api/routes/evidence_gaps.py` was empty and was not mounted. It is now mounted at `/api` plus the router prefix `/evidence-gaps`, so the routes are `/api/evidence-gaps`. There was no previous permission to keep. Every route is review, the same level as reading compliance gaps and verifying a control.

## Resolution

A gap becomes `resolved` only when `compliance_gaps._classify_evidence` says the evidence is clear and the evidence backs the gap. A control gap is backed by a `control_evidence_links` row. A question gap is backed by an answer citation whose chunk belongs to the evidence document. `close_reason` is `CONTROL_CHECK_CLOSE_REASON` (`evidence_sufficient`), not `answer_sufficient`.

Accepted and dismissed rows are not overwritten and are not reopened. A second open row is not inserted for the same control or question plus gap type. If more than one open row already exists, the response names every open id and the lowest id. There is no unique constraint. Concurrent inserts stay with TC-21-006b.

Age, owner, and priority are computed on read. The owner is the control owner when the gap names a control in this workspace, otherwise `owner_user_id` on the row. Priority is `settled` for accepted, dismissed, and resolved; `high` when the evaluation state is failed, unknown, or stale, or the age is at least 14 days; `medium` when the owner is missing; otherwise `low`.

GET does not write. Mutating routes take an optional `Idempotency-Key`, claimed with an owner. A failed request rolls back before the claim is released. A successful commit settles the claim. Notifications are stubbed in tests.

| --- | --- |
| `GET /api/evidence-gaps` | review |
| `GET /api/evidence-gaps/{id}` | review |
| `POST /api/evidence-gaps` | review |
| `POST /api/evidence-gaps/{id}/decision` | admin |
| `POST /api/evidence-gaps/{id}/resolve` | admin |

`POST /api/compliance/controls/{control_id}/verify` uses `require_can_review`, which is below admin. Decision and resolve therefore use `require_can_admin`. That change is a separate commit after the reviewed `6f504c2`.
