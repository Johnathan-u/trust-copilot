# TC-21-013 Evidence gap ownership and resolution

**Status:** implemented. Framework catalogs stay **BLOCKED** pending **TC-01-007**. No framework requirement text was added. No migration.

Routes are mounted at `/api` plus `/evidence-gaps`. The module had no operations before this ticket. No page fetched these routes. `apps/web/lib/evidenceGapConsumer.ts` parses the versioned payload.

## Resolution

A gap becomes `resolved` only when `compliance_gaps._classify_evidence` says the evidence is clear and the evidence backs the gap. A control gap is backed by a `control_evidence_links` row. A question gap is backed by an answer citation whose chunk belongs to the evidence document.

Master's `ck_evidence_gaps_close_reason` allows NULL, `question_removed`, `answer_sufficient`, and `evidence_sufficient`. A question gap that is not `control_check` closes with `answer_sufficient`. A control-check gap closes with `evidence_sufficient`.

Accepted and dismissed rows are not overwritten. A decision or resolve on a gap that is not open returns 409 and does not write. Foreign evidence ids are omitted from responses. Stored `evidence_refs` change only on an open-to-decided or open-to-resolved transition.

Create stores `questionnaire_id` from the question. Question gaps of every type other than `control_check` share one open row. The insert takes `pg_advisory_xact_lock(150015, questionnaire_id)` and, for a control, `pg_advisory_xact_lock(150016, control_id)`. A unique-index conflict returns the open row or 409. The partial unique index itself is PR #82 and is not added here.

Age, owner, and priority are computed on read. The owner is the control owner when the gap names a control in this workspace, otherwise `owner_user_id` on the row. Priority is `settled` for accepted, dismissed, and resolved; `high` when the evaluation state is failed, unknown, or stale, or the age is at least 14 days; `medium` when the owner is missing; otherwise `low`.

GET does not write. Mutating routes take an optional `Idempotency-Key`, stored as `evidence-gaps:{workspace}:{action}:{gap or new}:{raw}` and claimed with an owner. A failed request rolls back before the claim is released. A successful commit settles the claim. A completed create stores a sha256 of the request body in that payload. The same key with a different body is 422.

A legacy create row that has no body hash is replayed only when `gap_type`, `control_id`, and `question_id` on the stored response equal the new request. Those are the gap identity fields. If any of them is missing from the stored response, or any of them differs, the request stays 409 and does not write. Matching on the response text alone is not used, because a different gap could repeat a title or a reason. Decision writes `gap_decided` and resolve writes `gap_resolved`, each with the acting user id. Notifications are stubbed in tests and use a readable label, not the gap id.

## Permissions

`POST /api/compliance/controls/{control_id}/verify` uses `require_can_review`. Resolve uses that same dependency. Decision is admin because that verify dependency is below admin.

| Route | Permission |
| --- | --- |
| `GET /api/evidence-gaps` | review |
| `GET /api/evidence-gaps/{id}` | review |
| `POST /api/evidence-gaps` | review |
| `POST /api/evidence-gaps/{id}/decision` | admin |
| `POST /api/evidence-gaps/{id}/resolve` | review |

## Ambiguities

- List, read, and create are review. Resolve matches control verify (`require_can_review`). Decision is admin.
- No web page fetched `/api/evidence-gaps`. The parser is the consumer.
- PR #82's partial unique index is not in this branch. Create is compatible with it and locks around the insert.
- A question gap with no document citation does not resolve, even when the evidence itself is eligible.

## Migration

None.

## Close reason

`ck_evidence_gaps_close_reason` on master (`bug018b_gap_status_checks`, parent `tc21006_gap_evaluation`) allows NULL, `question_removed`, `answer_sufficient`, and `evidence_sufficient`. Question resolves use `answer_sufficient`. Control-check resolves use `evidence_sufficient`.
