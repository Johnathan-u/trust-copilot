## Behaviour

Line numbers were read on this change.

**Binding.** Approving an answer writes the chunk's `document_id` onto each citation that does not already have one (`apps/api/app/services/answer_support.py:108-141`). `PATCH /api/answers/{id}` does this when the new status is `approved`, inside the same conditional update that TC-12-002 uses for `updated_at` (`apps/api/app/api/routes/answers.py:244-247`). Bulk approve does the same (`answers.py:208-214`). Approving a draft revision does it with `clear_stale=True` (`apps/api/app/services/answer_revisions.py:284-288`). A citation whose chunk does not exist is left unchanged, so a synthetic citation string stays as it was.

**Stale revision.** Soft-delete and bulk soft-delete call `mark_answers_stale_for_document` before commit (`apps/api/app/api/routes/documents.py:543`, `:584`). That sets `support_stale` on citations that name the document or one of its chunks. The answer text and `status` stay `approved`. `updated_at` moves, so an open editor's next save is still the TC-12-002 409 until reload. Restore does not clear the marker. A storage key that no longer matches a chunk's `source_version` is stale on read, because `citations_are_stale` in `active_sources.py` already treats that chunk as ineligible. Export stamps the marker when it sees that case. Reindex stamps it before deleting chunks whose `source_version` is not the current storage key (`apps/api/app/services/index_service.py:76-78`). Reindex of the same key does not.

**Read.** `GET /api/questionnaires/{id}` adds `support_stale` (`apps/api/app/api/routes/questionnaires.py:777-779`). It is true when any citation has the marker or `citations_are_stale` is true (`answer_support.py:84-90`). The review status cell shows `Stale source` when that field is true (`apps/web/app/dashboard/review/[id]/page.tsx:1465-1472`).

**Retrieval and corpus version.** Keyword and semantic search already use `eligible_chunk_query` (`active_sources.py:29-52`). Archive already tombstones chunks and calls `invalidate_after_document_visibility_change`, which bumps the corpus version (`documents.py:584-586`, `apps/api/app/services/retrieval_cache.py:113-124`). This change does not add a second bump.

**Export.** `enqueue_export_job` refuses before it creates a job (`apps/api/app/services/export_service.py:78-81`). The route returns 409 (`apps/api/app/api/routes/exports.py:269-273`). The body is `message` plus `answers`, each `{answer_id, question_id}`. The message lists the answer ids and does not include answer text. An insufficient-evidence placeholder is not included (`answer_support.py:203-209`, `:226-246`). The worker raises `export_support_stale` before it reads the questionnaire file (`apps/api/app/worker.py:913-920`). That code is terminal. A new draft approved against an indexed, not-deleted document clears the marker and export is queued.

**Accept suggested chunk.** After the existing same-workspace check, the chunk must be in `eligible_chunk_query` and the document, when one is named, must be indexed and not soft-deleted (`compliance_controls.py:699-707`, `active_sources.py:82-101`). Otherwise the route is 409 and no evidence row is written. A chunk in another workspace is still 404. An orphan chunk with no document stays eligible.
