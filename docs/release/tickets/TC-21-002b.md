# TC-21-002b: control contract edge cases left by TC-21-002

Follow-up of TC-21-002. It collects the non-blocking items from the independent reviews of #197 (heads `62afe12` and `420d8eb`).
Epic E21. 5 points, P2. Depends on TC-21-002. Branch: `tc/TC-21-002b-contract-edges`.

## Acceptance criteria

1. Remediation bump:
   - An explicit `bump_control_to: "implemented"` on a verified control is either applied or refused with a clear error. It is never silently skipped. Use `model_fields_set` to tell it apart from the default.
   - A remediation submit for a control whose owner has been suspended doesn't fail with 404 `owner_not_in_workspace`.
   - The remediation ticket status endpoint (`remediation_service.py:221-228`) accepts only ticket statuses. `verified` is refused or renamed so it can't be confused with control status.
   - The control lookup in `remediation_loop_service.py` filters by workspace.
2. Create and identity:
   - The compliance-route case "rename A to B, then create A" is tested.
   - An exact-repeat compliance create changes nothing, including `framework_control_id`.
3. Evidence mirroring:
   - Duplicate ids in one `evidence_ids` request are de-duplicated rather than returning 500.
   - Compliance links that existed before TC-21-002 are backfilled with their legacy mirror rows, so `mirrored` is true. This includes a migration with a rollback test.
   - Mirrored evidence with no document doesn't report `exactly_one_target: true` for a row with no target.
4. A legacy PATCH that doesn't change status (for example a rename) doesn't demote a verified pair.
5. Each code item has a test that fails without the fix.

## Evidence and sign-off

CI on both events, plus an independent review. Under OD-14 no separate owner sign-off is needed.
