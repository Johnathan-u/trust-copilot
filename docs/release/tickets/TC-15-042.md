# Framework control library and detail

Status: implementation in progress. Assignment: #85. Base: `5b97a33`.

## Implementation plan

Use page-local Next.js client components and the existing auth, loading, error,
catalog, canonical-control and coverage consumers. No new dependencies or shared
UI changes. The library lists workspace controls and framework availability; the
control detail separates lifecycle from evidence evaluation, lets administrators
assign named workspace members, and lets reviewers inspect and verify evidence.

## Decisions and contract limits

- Framework rights are blocked in the current API. The UI must show this truthfully; synthetic browser fixtures do not qualify licensed framework activation.
- The canonical lifecycle is not an evaluated compliance result. Evidence evaluation comes only from the versioned control-coverage explanation, and absent/failed evaluation remains unknown.
- Member enumeration is admin-only. Administrators choose a named member; other roles see the team or “Assigned member” without numeric ids. The current compliance PATCH ignores null owner ids, so the UI does not offer unsupported owner removal.
- A missing or foreign control is shown through the same not-found state.
- The existing page shell supplies authentication; page content is keyed by workspace and effective grants and old reads are aborted.
- Navigation discovery is coordinated on #85; Sidebar and shared navigation remain outside this branch until assigned.
