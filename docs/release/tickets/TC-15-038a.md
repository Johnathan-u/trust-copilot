## Contract

`GET /api/jobs?workspace_id=<id>&limit=25&before_id=<id>` uses the existing `require_can_review` dependency. Workspace is required; limit is 1–100, default 25; the optional cursor must be positive. Rows are ordered by descending job ID. The response is `{"items": [...], "next_before_id": <id-or-null>}`. A next cursor is returned only when another row exists. Inserting a newer job does not shift an older page's cursor. There is no client memory or cached history to rebuild on reload.

Existing admin/editor/reviewer permissions and current custom-role `can_review` rules apply. No owner/viewer mapping is invented. A requested workspace outside the session returns the same 404 as a nonexistent workspace. An authorized empty workspace returns an empty collection. GET does not update jobs, effects, objects, audit records or sessions.

Each item explicitly allows only:

- `id`, known `kind` and `status`, `attempt`, `max_attempts`, and lifecycle timestamps;
- known `error_code`, the existing safe typed `error_detail` catalog/fallback, and existing retry/charge-uncertain semantics;
- `progress`: integer `generated`/`total` for answer-generation jobs, or null; counters must be nonnegative, ordered and exactly representable by a JavaScript number;
- `outcome`: `already_applied`, `reconciled`, `superseded`, or null;
- `object_ref`: `{type, id}` for a current authorized document or questionnaire, or null.

Document indexing/evidence parsing references a document. Questionnaire parsing, answer generation and export reference the questionnaire. An export reference grants no download access. Stored input IDs must be positive database-range integers; booleans and coerced strings are rejected. The target must currently exist in the job's workspace and have no `deleted_at`. Missing, deleted, moved, foreign or malformed targets produce null. No filename, original, evidence excerpt, storage address or arbitrary URL is returned.

Raw payload, raw result, arbitrary provider error text, stored request IDs, idempotency keys, input versions and lease data never enter this projection. Unknown kind/status/code strings are not echoed. Malformed or non-object stored JSON produces no progress/reference. A failed job's typed error uses the current request's ID rather than copying untrusted stored payload text.

The prior detail, cancel and retry serializers and handlers are unchanged. History uses its own serializer because the legacy detail response includes raw result/error fields.

## Acceptance and evidence

[`verification.json`](../../../artifacts/acceptance/TC-15-038a/verification.json) records exact commands, the tested implementation SHA and limitations. `apps/api/tests/release/test_job_history.py` contains:

- 16 explicitly labelled SQLite control-path cases for real route/query/projection behavior. These use an injected principal and do not qualify PostgreSQL or real authorization.
- 32 PostgreSQL cases using the real application, signed stored sessions and permission dependencies: all three built-in roles; every custom permission combination; missing/foreign custom roles, suspended and unauthenticated callers; current custom-role changes; default/max pagination, new inserts and a new client; every current job kind's object reference; malformed JSON, safe lifecycle fields, and unchanged detail/cancel/retry contracts.
- Full-row snapshots before and after each PostgreSQL GET, plus fixture cleanup that deletes created rows in FK-safe order and verifies every original full row and count. No FK/trigger bypass or sequence reset is used.

Run from `apps/api`:

```sh
python -m pytest tests/release/test_job_history.py -m unit -q
TC_REQUIRE_DB=1 python -m pytest tests/release/test_job_history.py -q
python -m pytest tests/release/test_job_cancellation.py tests/release/test_job_retries.py tests/release/test_job_idempotency.py -q
python -m pytest tests/release/test_safe_collection.py -q
```

Four temporary negative controls each caused an assertion failure: removing job workspace filtering, exposing raw payload, removing object workspace filtering, and removing the deleted-object filter. The original source was restored and local control checks rerun successfully. A separate red/green check removed an unintended upper cursor bound so any positive cursor remains valid under the frozen contract.

Local PostgreSQL at port 5432 refuses connections. Required-database mode fails during setup; no PostgreSQL result is claimed. The full backend command also stops at an existing database-dependent test for that same missing service. CI must execute these acceptance cases without a required skip and supply both existing jobs on push and pull request for the final head.
