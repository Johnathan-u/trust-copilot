## Problem

At `69a5230`, `switch-workspace` issued the target membership role without reading that workspace's `mfa_required`. Login applied the policy only to the lowest-id membership. A user with no factor could sign in to a workspace that did not require MFA, switch into one that did, and receive that workspace's role.

## What closed it

PR #309, head `84be2447e6b1ac8bc214953795d7af1f778dbe9d`, squash-merged as `2aea83a64b1a936afc90da9e9793d0fcbb8c7de8`. The decision record is `docs/release/verification/TC-05-001c.md`.

`user_sessions.mfa_satisfied` defaults to false. Switch grants the target role only when that flag is true. No enabled factor and `mfa_required` produce the five-minute enrol-only cookie. An enabled factor on an unsatisfied session gets the login challenge and no role cookie. Claude accepted this on #309 comment 7012449164 at 2026-11-19T14:44:37Z.

## Acceptance criteria

1. A switch into an `mfa_required` workspace does not grant the target role unless the stored session is `mfa_satisfied`.
2. No enabled factor yields the enrol-only cookie. An enabled factor on an unsatisfied session yields the login challenge and does not set the member cookie.
3. `build` and `web-release-e2e` are green on push and pull_request for the head above. The run IDs are in `artifacts/acceptance/TC-05-001c/ci-runs.md`.
