## Behaviour

Line numbers are the ones read at `05ca009fbca03a0993997a429e5a697cf3879065`.

**Cached and uncached generation.** `AnswerWriteGuard.is_protected` is true when `status` is `approved` (`apps/api/app/services/answer_generation.py:672-676`). Those question ids are removed before retrieval and before `answer_cache_get` (`answer_generation.py:756-763`, cache read at `:978`). A cache hit that does run calls `_upsert_answer` (`:1036-1047`). The UPDATE itself requires `Answer.status != "approved"` (`:1770`). Bulk generation still skips an approved answer. It does not insert an `answer_revisions` row.

**Explicit regenerate.** `POST /api/answers/{answer_id}/regenerate` requires review permission (`apps/api/app/api/routes/answers.py:198-221`). Another workspace is 403. A missing answer or question is 404. A row that is not approved is 409. Those denials do not change the row. The call inserts an `answer_revisions` row with status `draft` and that draft's own text and citations (`apps/api/app/services/answer_revisions.py:201-233`). The `answers` row stays unchanged, including status `approved`. A second regenerate marks the open draft `superseded` and inserts a new `draft`. The write takes the existing per-question answer lock.

**Reapproval.** `POST /api/answers/{answer_id}/revisions/{revision_id}/approve` uses the same review and workspace guards (`answers.py:225-241`). The revision must belong to that answer and still be an open `draft`. Approve stores the previous approved text as a `superseded` revision, copies the draft onto the answer, leaves the answer status `approved`, and marks the draft `applied` (`answer_revisions.py:236-287`).

Until that approval, questionnaire read returns the approved row's text, status, and citations, and returns the open draft beside them (`apps/api/app/api/routes/questionnaires.py:732-743`). Export uses the approved row, not the draft (`answer_revisions.py:111-129`, called from `apps/api/app/worker.py:952`). The review page shows the approved text beside the draft and asks for reapproval (`apps/web/app/dashboard/review/[id]/page.tsx:1295-1346`). Editing the draft is not the autosave that writes the approved row (`page.tsx:1348-1359`).

The named test plants an answer-cache row for an approved question and asserts the text, citations, and status stay. It also runs generation with no cache row. It then regenerates explicitly, checks read and export, and approves the draft. A reviewer without review permission, another workspace, and a row that is not approved are refused and the row is unchanged. The fixtures are synthetic.
