## How to operate

```bash
cd apps/web
npm ci --ignore-scripts      # Node 24 (.nvmrc)
npm run quality              # typecheck, lint, format:check, test:unit
npm run format               # rewrite formatting (prettier --write)
npx eslint . --fix           # autofix what ESLint can
cd ../api && TC_REQUIRE_WEB_TOOLCHAIN=1 python -m pytest tests/release/test_web_quality.py -q
```

- Every `eslint-disable` must name its rule and give a reason after `--`. The release test rejects blanket disables.
- New pure modules in `lib/` must be imported by a test in `tests/unit/`. The release test enforces this for any module with runtime exports.
- Do not add generated output to `.prettierignore` under `app/`, `components/`, `contexts/`, `lib/` or `tests/`. The release test rejects it. The only allowed generated path under a source directory is `e2e/.auth/` (Playwright storage state).

## Release test

`apps/api/tests/release/test_web_quality.py` has 26 tests.

- **Static checks:**
  - scripts are present and are not no-ops;
  - the ESLint config extends the required rule sets and does not turn off core rules;
  - disables are scoped to rules;
  - the unit suite covers every runtime module with real assertions and no skip, only or todo;
  - vitest does not pass when there are no tests;
  - the ignore files are tight;
  - CI runs every gate and records versions;
  - the tools are exact-pinned and match the lock.
- **Denial cases:** every policy function is checked against synthetic bad inputs.
- **Execution checks:** these run the real binaries.
  - The committed code passes vitest, lint and format.
  - Each of these must fail:
    - an empty test selection;
    - a failing test;
    - a hooks, unused or `any` violation;
    - a Next `<img>` violation;
    - an unformatted file.
  - Installed versions must equal the pins.
- **Skips:** without Node 24 and `node_modules` the execution checks skip with an explicit reason. CI sets `TC_REQUIRE_WEB_TOOLCHAIN=1`, so there they fail instead of skipping.

On the TC-02-003 baseline the result is 8 failed, 8 passed and 10 skipped (no toolchain). At head it is 26 passed, with 0 skipped.

## Decisions and ambiguities (resolved conservatively)

1. **ESLint 10 with a composed config instead of `eslint-config-next`.**
   - ESLint 9 left support on 2026-08-06.
   - `eslint-config-next` 16.4.3 depends on `eslint-plugin-import`, `jsx-a11y` and `react` plugins whose peer range stops at ESLint 9. It also adds `unrs-resolver`, which has an install script.
   - The composed config uses only packages that support ESLint 10 and have no install scripts.
   - The import, jsx-a11y and react plugin rules are therefore not enforced. Re-evaluate them when those plugins support ESLint 10.
2. **`react-hooks/set-state-in-effect` is off.**
   - It would flag 31 pre-existing fetch-on-mount effects (`baseline-eslint-strict.json`).
   - Fixing them is a behavioural refactor that belongs with React Compiler adoption, not a gate ticket.
   - Every other react-hooks v7 recommended rule is on, including `rules-of-hooks` and `exhaustive-deps`.
3. **15 inline, rule-scoped disables with reasons for pre-existing code.**
   - 6 `no-location-assign-relative-destination`, where a full page load is intentional.
   - 2 `no-html-link-for-pages`, for OAuth `/api` links.
   - 2 `exhaustive-deps`.
   - 2 `static-components`.
   - 1 `refs`.
   - 2 `no-explicit-any`.
   - All other baseline findings (16 unused vars and others) were fixed in a behaviour-neutral way.
4. **Prettier 3.4.2 to 3.9.10 and a one-time mass format** in its own commit (`apply prettier 3.9.10 … (mechanical)`). The only manual edit in that commit moves three disable comments that the reflow had separated from their target lines.
5. **Out of scope and untouched:**
   - the root `package.json` (overlaps TC-02-001);
   - `.github/workflows/deploy.yml` (targets a `main` branch that does not exist);
   - `apps/api/Dockerfile`, `pyproject.toml` and `conftest.py`;
   - `apps/web/playwright.config.ts` and `scripts/` (TC-02-001);
   - CI's unpinned `pip install ruff pytest` (backend).
6. **Possible merge conflicts with TC-02-001** if it edits apps/web files that the format commit touched. Resolve by keeping TC-02-001's content and re-running `npm run format`.
