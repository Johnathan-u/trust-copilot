# TC-13-003a: CSV injection in the compliance audit export

Follow-up of TC-13-003. This is a security finding from the independent post-merge review of #210 (`4d68f47`), filed under release-decisions §2 rule 1.
Epic E13. 2 points, P1. Depends on TC-13-003.

## Why

TC-13-003 makes answer exports write formula-like text as literal text. The compliance audit CSV (`compliance_audit.py:90-118`) still writes `actor`, `email`, `action` and other user-controlled columns raw. A value starting with `=`, `+`, `-`, `@`, tab or CR (or a full-width equivalent) can run as a formula when an auditor opens the file in a spreadsheet.

## Acceptance criteria

1. Every text cell in the audit CSV passes through `neutralize_csv_cell` (`fallback_export.py`), the same neutralizer the TC-13-003 answer export uses. The neutralizer is applied once and never twice.
2. A test feeds the same payload set as `tests/release/test_export_literal_text.py` through the audit export. It asserts one `'` prefix per flagged cell and unchanged text otherwise, and fails without the fix.
3. The related surfaces are recorded under TC-21-009 AC1, which already covers them:
   - the three `DictWriter` sites in `compliance_export.py` (`:94`, `:167`, `:224`);
   - the web escape in `gap-report.tsx:116`, which misses full-width prefixes, tab and CR.

## Evidence and sign-off

CI on both events, plus an independent review.
