## Preserved contract

The existing route requires a current session. Admin, editor, reviewer and a
current custom role without review/edit/admin/export flags retain read access.
The same signed admin cookie is reused after stored membership changes; suspended,
removed or moved membership and removed/reassigned stored sessions are denied.
An anonymous request is denied. Denial bodies retain their existing shapes and
contain no counters. A `workspace_id` query parameter cannot override the session.

The five service queries count questions, answers, questionnaires, documents and
export records within the current workspace. Tests check two disjoint workspaces,
ordinary moves in both directions, a question moved to a foreign questionnaire,
ordinary deletions and actual cascades, and an empty tenant beside populated
foreign data. Existing archived-row counts and the labelled time-saving heuristic
are preserved. These fixture counts are authorization and behavior-preservation
controls, not a claim that indexed/delivered/reused lifecycle semantics are ready.

All production files and the four tests in `tests/test_proof_widgets.py` are
unchanged. There are no provider, model, storage, schema or dependency changes.

## Acceptance evidence

The new matrix contains **30 SQLite and 30 migrated-PostgreSQL cases**. Requests
use the real route and stored users, workspace memberships and user sessions with
expiring signed cookies. Only `get_db` is overridden. SQLite creates actual model
tables and asserts FK enforcement; PostgreSQL uses the existing `migrated_db`
fixture and real constraints. Export links are legitimately null so independent
records can move without bypassing same-workspace triggers. No impossible orphan,
schema substitute, trigger disable or FK bypass is used.

Every request snapshots complete row counts and hashes across fourteen source and
authentication tables. SQL observation permits only SELECT statements during
requests, including denials, and detects writes even if subsequently rolled back.
Fixture creation and API flush observation record exact owned row IDs. Child-first
cleanup deletes only those IDs and compares the complete original snapshot. No
global deletes or sequence resets are used. Collection creates no fixture store
or database connection.
