# TC-15-016 — Finish and polish /dashboard/documents

## Behavior

`/dashboard/documents` is a workspace document list. It reads `GET /api/documents` and does not change backend authorization.

Search waits 300ms, then sends the existing `search` parameter. A newer search aborts the previous request with `AbortController`, and a late response is ignored. The list states its contract: every match comes back in one response, newest first. `GET /api/documents` does not accept `page`, `page_size`, `limit`, `offset`, `sort`, or `order`. The page does not slice or reorder the payload on the client. The server order remains `created_at` descending, then `id` descending.

Selection applies to every document in the current result for the current workspace. Changing the workspace or a committed filter, including the debounced search, clears it. There is no page control, and the page says so.

A successful empty library, a successful search or filter with no rows, and a failed read are three states. The empty library says "No documents yet". A narrowed empty result says "No matching documents". A failed read uses `ErrorState` and does not look like an empty library.

Editors see accepted formats before choosing a file: PDF, DOCX, DOC, XLSX, XLS, and TXT, matching `FileService.ALLOWED_RAW_EXTENSIONS`. The size line says 50 MB, the documented default of `MAX_UPLOAD_BYTES`. The document API does not return the configured limit. The upload button stays on "Uploading" until the upload response. "Uploaded" / "The file is stored." appears only after that response succeeds. If the response includes `job_id`, the page polls `GET /api/jobs/{id}` and shows Queued while the job is queued or running. Indexed appears only after the job is completed and a following document read has `status` `indexed`. Failed appears when the job is failed or cancelled, or the document read says `failed`.

Retry is `POST /api/jobs/{id}/retry`. That route requires an administrator. The document list does not include a job id, so the page reads the newest `GET /api/jobs` page (`limit=25`, which is what the job-history reader accepts) and offers "Retry indexing" only when that page has a failed or cancelled `index_document` for the row. "Indexing queued" appears only after the retry response has `status` `queued`. There is no document reindex route, and the page says reindex is not offered. A source link is rendered only when the row includes a same-origin `source_preview_url`. Otherwise the row says source preview is not available. A matched index job links to `/dashboard/jobs?workspace_id=…`.

Metadata and restore dialogs stay open until the response is acknowledged. The row updates, and "Metadata saved." or "Restored." appears, only when the body has `ok: true`. A failed response stays in the dialog as an alert and does not change the row.

Archive and delete are different. Archive calls the existing soft-delete `DELETE /api/documents/{id}` (and bulk archive calls `POST /api/documents/bulk-delete`). The dialog says the document can be restored, and "Archived." appears only after `ok: true`. Delete opens a separate dialog titled "Delete record?" that explains permanent deletion is not available. Its confirm control stays disabled and does not call the API. The document API has no per-document erase. `POST /api/retention/delete` is a workspace retention operation, not a row action, and this page does not call it.

Mutation controls use `permissions.can_edit` and `permissions.can_admin` from the session. A reviewer (`can_edit` false) does not get the upload control, the file input, row checkboxes, or the row menu. Index retry additionally requires `can_admin`, matching the job retry route. This is display only. The server checks are unchanged.

Source eligibility, freshness, and version render when the list object carries those strings (`source_eligibility` or `eligibility`, `freshness`, `version` or `content_version`). The current list response does not include them, so each row says "Not reported" until it does.

Search, framework, subject area, created from, created to, document status, and the archive filter have labels. Selected values appear as removable chips.

At 360, 768, and 1440 CSS pixels the filters are reachable from the keyboard, long filenames wrap, and the empty and error states stay on screen without horizontal scrolling. axe-core reports no violations for the ready, empty, and error states at those widths.
