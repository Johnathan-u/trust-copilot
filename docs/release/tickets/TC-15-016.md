## Behavior

`/dashboard/documents` is a workspace document list. It reads `GET /api/documents` and does not change backend authorization.

Search waits 300ms, then sends the existing `search` parameter. A newer search aborts the previous request with `AbortController`, and a late response is ignored. The page sends `page`, `page_size=25`, `sort`, and `order`, as the current contract describes. The page does not slice or reorder the payload on the client.

Selection applies to every document in the current page for the current workspace. Changing the workspace, a committed filter, the sort, or the page clears it. Previous and Next appear when `total` is greater than 25.

A successful empty library, a successful search or filter with no rows, and a failed read are three states. The empty library says "No documents yet". A narrowed empty result says "No matching documents". A failed read uses `ErrorState` and does not look like an empty library.

Editors see accepted formats before choosing a file: PDF, DOCX, DOC, XLSX, XLS, and TXT, matching `FileService.ALLOWED_RAW_EXTENSIONS`. The size line uses `max_upload_bytes` from the page payload. 52428800 is shown as `Size limit: 50 MB.` A missing limit is `Size limit: not reported.` The upload button stays on "Uploading" until the upload response. "Uploaded" / "The file is stored." appears only after that response succeeds. If the response includes `job_id`, the page polls `GET /api/jobs/{id}` and shows Queued while the job is queued or running. Indexed appears only after the job is completed and a following document read has `status` `indexed`. Failed appears when the job is failed or cancelled, or the document read says `failed`.

Retry is `POST /api/jobs/{id}/retry`. That route requires an administrator. When a row includes `index_job_id` and `index_job_status`, retry and the job link use that job. Otherwise the page reads the newest `GET /api/jobs` page (`limit=25`, which is what the job-history reader accepts) and offers "Retry indexing" only when that page has a failed or cancelled `index_document` for the row. "Indexing queued" appears only after the retry response has `status` `queued`. There is no document reindex route, and the page says reindex is not offered. A source link is rendered only when the row includes a same-origin `source_preview_url`. Otherwise the row says source preview is not available. A matched index job links to `/dashboard/jobs?workspace_id=…`.

Metadata and restore dialogs stay open until the response is acknowledged. The row updates, and "Metadata saved." or "Restored." appears, only when the body has `ok: true`. A failed response stays in the dialog as an alert and does not change the row.

Archive and delete are different. Archive calls the existing soft-delete `DELETE /api/documents/{id}` (and bulk archive calls `POST /api/documents/bulk-delete`). The dialog says the document can be restored, and "Archived." appears only after `ok: true`. Delete opens a separate dialog titled "Delete record?" that explains permanent deletion is not available. Its confirm control stays disabled and does not call the API. The document API has no per-document erase. `POST /api/retention/delete` is a workspace retention operation, not a row action, and this page does not call it.

Mutation controls use `permissions.can_edit` and `permissions.can_admin` from the session. A reviewer (`can_edit` false) does not get the upload control, the file input, row checkboxes, or the row menu. Index retry additionally requires `can_admin`, matching the job retry route. This is display only. The server checks are unchanged.

The list row carries `source_eligibility`, `freshness`, and `version`. The page renders those strings, or "Not reported" when a value is absent.

Search, framework, subject area, created from, created to, document status, and the archive filter have labels. Selected values appear as removable chips.

At 360, 768, and 1440 CSS pixels the filters are reachable from the keyboard, long filenames wrap, and the empty and error states stay on screen without horizontal scrolling. axe-core reports no violations for the ready, empty, and error states at those widths.
