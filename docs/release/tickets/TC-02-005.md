## What was already true

* `ruff check .` from `apps/api` is green in CI. That directory's `pyproject.toml` has a `[tool.ruff]`
  table with only `line-length`, so it hides the repo-root `ruff.toml` select (`E`, `F`, `I`, `B`).
  The root select is real when ruff is pointed at `ruff.toml` directly. Applying it to all of
  `apps/api` reports on the order of two thousand existing findings (mostly `B008` on FastAPI
  defaults and `E501`). That cleanup is not this ticket.
* There was no Python type checker in the dev extra, the lock or CI.
* Pytest already marks tests that do not touch the database as `unit` (TC-02-001). CI still ran the
  whole suite only after Postgres was up. Nothing failed the build when an unexplained job error
  became retryable, and nothing rejected a code-less `# noqa` or `# type: ignore`.

## Behaviour after this ticket

### Pinned scope (AC1)

The lint and type scope is the `files` list in `[tool.mypy]` (`apps/api/pyproject.toml`):

| Module | Contract |
|---|---|
| `app/core/api_errors.py` | Public API error envelope |
| `app/core/job_errors.py` | Job error classification and retry |
| `app/core/roles.py` | Built-in principal permissions |
| `app/schemas/job.py` | Job response schema |
| `app/services/model_outcomes.py` | Model outcome catalog used by the error envelope |
| `app/services/source_registry_service.py` | Known evidence-source catalog and its service |

CI, from `apps/api`:

* records `python`, `ruff` and `mypy` versions;
* runs `ruff check --select E,F,I,B` on those six paths (the whole-tree `ruff check .` step stays);
* runs `mypy` with no extra arguments, so the `files` list is the scope;
* sets `TC_REQUIRE_API_QUALITY=1` on the backend pytest step.

mypy 2.4.1 is an exact dev pin. It is not in `requirements.lock`. `follow_imports = silent` keeps
reports on the six files; it does not ignore errors inside them. `ignore-without-code` is enabled,
so a bare `# type: ignore` fails. `disallow_untyped_defs` and `warn_unused_ignores` are on.
`ignore_errors` is not set.

Blanket suppressions are rejected in those files: `# noqa` without codes, `# type: ignore` without
`[code]`, `# ruff: noqa` / `# flake8: noqa`, and `# mypy: ignore-errors`. A coded ignore is allowed.
The only ones in the scope are three `# type: ignore[assignment]` on `record_sync` in
`source_registry_service.py`. Those attributes are classic SQLAlchemy `Column()` descriptors, so
mypy treats the assignment as a type error. The values written are unchanged.

Root `ruff.toml` still selects `E,F,I,B` with an empty `ignore`. A category-wide ignore
(`ALL`, `E`, `F`, `I`, `B`) or a per-file ignore of those categories on a critical path fails the
release test. The release test also fails if CI drops a path, drops `mypy`, or sets
`continue-on-error` on the new steps.

### Unit suite (AC2)

`apps/api/tests/unit/` holds 15 tests in five modules. They import the six critical modules, use
`pytest.mark.unit`, and do not name a database fixture or the ASGI app. The release test runs them
with `TC_TEST_DATABASE_URL` on `127.0.0.1:1`. On this run: 15 passed, 0 skipped, 0 failed.

The known regression is job classification: an exception that is not a typed job, model, HTTP or
input error must stay `internal_error` and must not be retried (`test_unknown_exception_is_terminal`).
The release test loads a child pytest plugin that maps that code to `timeout`. The unit test fails
with `unknown failures must stay terminal`.

Other assertions that fail if the contract moves:

* a failed job's client payload uses `job_failed`, is not retryable, and does not copy the raw error text;
* `model_timeout` is retryable and `model_credentials_missing` is fatal;
* a reviewer cannot edit or administer, and an unknown role is not built in;
* `job_response` leaves a missing timestamp null;
* source types are unique, manual auth is `none`, and Azure auth is `service_principal`;
* backoff delay stays inside the cap.

Changing the mypy pin: edit `apps/api/pyproject.toml`, then `scripts/lock-python-deps.sh`, and commit
`pyproject.toml` with `requirements-dev.lock`. Do not add mypy to the runtime dependencies.

## Rulings

* **Scope is the six contract modules, not the whole API.** Enabling `E,F,I,B` on every API file
  is a separate cleanup. This ticket pins the modules the error, job, principal-permission and
  source contracts live in, and makes a later edit to those files pass both checkers.
* **`follow_imports = silent` is the type-scope boundary.** `skip` would treat imported names as
  `Any`. `normal` would report errors in the database and route modules those files import.
  Silent still type-checks the six files.
* **Three coded assignment ignores** on `Column()` writes. No file-wide ignore and no code-less ignore.
* **String and catalog values are unchanged.** Wrapped lines are comments or adjacent string
  literals. `KNOWN_SOURCES` and the two model-outcome messages compare equal to the base revision.
* **Runtime lock is unchanged.** mypy stays in the dev extra.

## Limitations

* `auth_deps` still builds the database-backed principal. This ticket types the pure permission
  helpers in `roles.py`, not the session loader.
* The whole-tree `ruff check .` step does not select `I` or `B`. Pre-commit's ruff hook is unchanged.
* Reviewer sign-off is outstanding. The implementer does not merge this PR.
