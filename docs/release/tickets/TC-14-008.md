# TC-14-008 — Accurate, concise action and error copy

## Behavior

Save, upload, generate, export, and approve controls use one verb form for each phase. The idle label is the bare verb (`Save`, `Upload`, `Generate`, `Export`, `Approve`). While the request has not finished, the label is the progress form (`Saving`, `Uploading`, `Generating`, `Exporting`, `Approving`). The past form (`Saved`, `Uploaded`, `Generated`, `Exported`, `Approved`) appears only after the server has accepted the action: a successful response, or a job whose status is completed. A pending control does not say Done or use the past form.

Those strings live in `apps/web/lib/action-copy.ts`. Success detail does not claim that an answer is evidence-backed or otherwise explain why the result is correct.

`presentActionFailure()` in `apps/web/lib/api-error.ts` maps a mutation payload onto four failures. Anything else stays on the existing detail formatter. The four sentences are fixed. They do not repeat the response body, name a role, or add a cause the payload did not identify.

| Kind                    | When it matches                                                                                                                                        | What the person sees                                                                      |
| ----------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------- |
| Unsupported model       | Code `unsupported_model` or `model_unavailable`, or the detail is exactly "Unsupported model"                                                          | Choose a supported model and try again.                                                   |
| Unsupported file format | Code `unsupported_format`, `unsupported_file_format`, or `extension_not_allowed`, or the detail is the allowed-extension message or "format must be …" | Choose a supported format and try again.                                                  |
| No evidence             | Code `no_evidence`                                                                                                                                     | Add evidence that covers the item, then try again.                                        |
| Permission              | HTTP 403, or a permission / access-denied code, or a detail that is exactly "Access denied" or starts with "Insufficient permissions"                  | This account cannot complete that action. Ask someone who manages access, then try again. |

A model abstention, a generic model error, HTTP 401, and an ordinary validation error are not forced into those four. Page-load failures still use `presentHttpFailure()`. Request and response schemas are unchanged.

The spinner inside a button is decorative. The button's own label is the accessible name, and `aria-busy` is set while `loading` is true.

## What this ticket does not change

No database migration or backfill. Rollback is reverting this change. Reviewer signoff is pending a reviewer other than the implementer.

Onboarding is an invitation screen. It has no save, upload, generate, export, or approve action. The sidebar switches workspaces and links to sections. It has no those actions either. Both were reviewed and left as they are.

`Done` on the dashboard customize toggle, and `Done` after a vendor request has already been created, close a panel. They are not the label of a request that is still open.

`Create` remains the idle label for a new trust article. The pending label is `Saving`, so the button does not say the article exists before the response.

HTTP 401 stays a sign-in problem. It is not shown as the permission failure. A model abstention stays the server's own sentence, so it is not described as missing evidence.

## Ambiguities resolved

- The branch started from `60d8739`, which is newer than `e6a652f`. There were no local commits when that master moved, so the branch fast-forwarded. No merge commit was created.
- Success for generate and export is the completed job, not the enqueue response. The enqueue response only means the request was accepted and the work is still in progress, so the button stays on the progress label.
- Mapped failures use the fixed sentence and do not append a reference id. Unmapped failures keep the previous detail text, including a reference when that text already had one.
- The permission sentence does not use the word "permission" and does not name a role. It is still distinct from the page-load sentence "This section is not available".
- A longer sentence that merely contains the words "unsupported model" is not treated as that failure. The detail has to be that sentence, or the payload has to carry the code.
- Copy does not list file extensions or model names. The pages that already name the formats they accept were left with those lists.
