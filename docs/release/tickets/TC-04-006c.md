## Delivered behavior

The existing Account Security page offers **Sign out everywhere**, including when
only this device has a session. The existing destructive confirmation starts on
Cancel and explains that this device and every other signed-in device will need
to sign in again. Cancellation sends no mutation. Both session actions are disabled
while a mutation is pending; a synchronous local completion promise prevents duplicate
dispatch and keeps repeated confirmation callbacks pending until the original settles.
The existing sign-out-other-devices action and current-session logout remain distinct.

The new action sends the existing bodyless `POST /api/auth/sessions/revoke-all`.
Only an acknowledged response with `ok === true` and a nonnegative safe integer
`revoked` count permits full navigation to `/login`, discarding authenticated client
state. HTTP rejection, network uncertainty, invalid JSON and malformed success stay
visible as errors, release pending state, and do not claim success. Retrying requires
another explicit confirmation. No shared auth context, dialog, middleware, dependency,
backend route, schema or setting changes are included.

## Acceptance evidence

The 18 new happy-dom controls exercise the real page and shared confirmation with
mocked auth/read/mutation responses. They cover cancellation, focus restoration,
synchronous repeated confirmation, shared pending state, 401/403/500, network
uncertainty, seven malformed acknowledgments, valid zero/two counts, the single
current-session case, and the preserved revoke-others request. These are control-path
checks, not browser/API qualification.

The new pytest-owned acceptance harness runs three Chromium cases at 360, 768 and
1440 pixels against actual Next, the actual API and migrated PostgreSQL. Each case
uses two independent contexts for one user (session-only and remembered) and a
third for a different user; every session comes from the real login form. It checks
cancellation, keyboard operation, pending controls, strict acknowledgment, cleared
current cookie, the other context's 401 and redirect on reload, and preserved
foreign access. The only request interception holds outgoing mutation timing and
then continues to the actual API; no positive response is fabricated.

Private local checkpoints let pytest compare complete database rows before and
after each UI mutation. All and only the two own sessions must disappear; foreign
sessions and unrelated users/workspaces/members/tags stay equal; exactly one new
correctly scoped audit event records count two. Fixture teardown deletes only its
explicit owned IDs and verifies complete baseline table hashes. Guarded local
services use the existing process-group lifecycle helpers; outbound calls and
post-readiness storage attempts fail acceptance. Credentials and cookie values are
not captured in traces or reports.

The browser run writes page/dialog screenshots and six fresh axe reports for the
affected sessions section and confirmation, including full `violations` arrays
before asserting zero. Pytest requires exactly three passed browser cases, no
skips/flakes/failures and all six valid reports. Existing backend discovery and
installed Chromium execute this harness; the only CI edit adds artifact uploads.

## Report credential protection

Independent review reproduced a password leak in Playwright step metadata: tracing
being off does not stop `pressSequentially` from placing its text in uploaded report
titles and parameters. The repaired login helper uses the password input's native
value setter and an input event through `locator.evaluate`, passing the credential as
a separate argument omitted by the installed metadata renderer. The real login form
submit and its actual API acknowledgment remain unchanged.

A browserless regression extracts that actual helper, executes its DOM operation,
and uses the installed Playwright metadata renderers and HTML/JSON reporters. It
creates one passing case and one intentional reported failure, verifies both reports
and the HTML's decoded ZIP payloads contain no synthetic credential marker, and
retains the useful failure message. Restoring password typing makes this check fail.
This is reporter/DOM proof, not a Chromium login qualification.

The owning browser harness scans all files in both upload directories, including
embedded HTML report payloads. Credential-bearing or unreadable report files are
withheld and acceptance fails; safe diagnostics remain. The gate also runs when a
browser or database assertion fails. Tracing stays off. All 43 original browser
expectation ASTs, the complete axe writer, and all 21 real-browser/database assertion
ASTs are unchanged, including the three viewport cases and six required axe reports.
