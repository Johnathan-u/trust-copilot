Status: implemented locally; independent review and exact-head PostgreSQL/CI

Parent: [TC-05-003](../../planning/tickets/TC-05-003.md), AC2.
The adopted [product contract](../../planning/PRODUCT_SPEC.md#identity-tenancy-and-security-target)
bounds custom-role grants by their creator's authority. Current-membership
resolution from #120 is already landed.

A custom administrator without edit permission could create a role granting edit
or PATCH its own definition to acquire edit using the same signed session.
Create/update checked `can_admin` but copied other flags without a grant ceiling.

Creation now checks every enabled flag, including request defaults, against the
actor's current workspace permissions. Updates check only false-to-true grants.
The permission snapshot is taken before changing the target or its description,
including when the target is the actor's own role. An unauthorized grant returns
403 before mutation or success audit. Missing/foreign role 404 behavior remains.

Built-in administrators retain all four existing permissions. Limited custom
administrators may grant their held permissions. Description-only updates,
omitted/null fields, explicitly unchanged true flags and revocations retain their
existing behavior. Self-revocation is effective on the next request. Successful
create/update audit events remain intact.

## Acceptance and limits

`test_custom_role_grants.py` defines 24 scenarios each for SQLite and migrated
PostgreSQL. Real stored users, sessions, memberships and definitions drive actual
member/auth HTTP routes. Only the database dependency selects an owned connection;
auth and role behavior are not mocked. Cases cover every flag, defaults, self and
other-role escalation, mixed permitted/forbidden updates, legitimate grants,
partial/unchanged updates, revocation, current DB authority despite a stale admin
cookie, foreign roles, and anonymous/suspended/removed/non-admin contexts.

Full-row hashes including audit records must be unchanged after each denial.
Cleanup is scoped to unique fixture workspace/actor IDs and requires complete
baseline hashes to match. SQLite foreign keys remain enabled; PostgreSQL uses
existing migrations. No sequence reset, global difference deletion, trigger or
foreign-key bypass is used.

Before repair: 11 failed and 13 passed locally. After: all 24 SQLite cases pass;
48 total cases collect. The strict full backend-suite command exits 3 locally on
PostgreSQL connection refusal. See
[evidence](../../../artifacts/acceptance/TC-05-003a/README.md).

```sh
TC_REQUIRE_DB=1 python -m pytest tests/release/test_custom_role_grants.py -q
```

Independent review, actual PostgreSQL execution without required skips and
exact-final-head push/PR build and web-release-e2e checks remain mandatory.

Only custom-role create/update and their small shared helper change. No auth,
model, migration, UI, dependency or CI change is included. Member assignment,
invite and API-key grant ceilings remain explicit follow-up qualification. This
child does not close all escalation paths, full TC-05-003, owner/viewer semantics,
safe role migration, final-owner protection or the wider principal contract.
Publication remains coordinator-owned and respects the three-open-PR limit.
