## Problem

`_provider_login_response` (`auth.py`) issues the member's full role and a session cookie for Google, GitHub, Microsoft, SSO and ID.me logins without reading `UserMfa`. Password login withholds the cookie and returns `requires_mfa` when a factor is enabled. When `Workspace.mfa_required` is true and the user has no factor, password login still issues the full role. The flag is only reported on `/api/auth/me`.

## Acceptance criteria

1. Provider logins honor MFA. If the user has an enabled `UserMfa`, the provider callback must not issue a privileged session. Issue the same pending MFA state as password login (an MFA token, no privileged cookie) and complete it through the existing TOTP or recovery verify. Cover all five providers through the shared `_provider_login_response`.
2. `mfa_required` is enforced. A user in a workspace with `mfa_required` and no enabled factor gets only the zero-permission `mfa_enrol` session on every login path (password and provider), the same as re-enrolment today.
3. Tests in `apps/api/tests/release/test_mfa_enroll.py`: for each provider, an enabled factor means no privileged cookie before the challenge and full access after it; with `mfa_required` and no factor, every path gives `mfa_enrol` with zero permissions; a user with no MFA and no requirement is unchanged.
4. Docs: the ticket doc and the auth runbook.
