## Behavior

XLSX cells that matched both question and heading heuristics were consumed as
headings. A real two-sheet workbook reproduced five lost questions out of seven,
including uppercase, numbered, an imperative with a Q marker, and Ukrainian text.
Those false headings also replaced the section assigned to later questions.

The XLSX parser now resolves these collisions locally. A candidate heading needs
explicit question notation (`?` within the existing question suffix window, or a
`Q`-number marker) before it can be treated as a question. The parser then removes
the leading numeric/Q marker for classification only and checks the remaining
content with the existing question detector. A numbering marker alone cannot
turn `2. ACCESS MANAGEMENT` or `Q3) ACCESS MANAGEMENT` into a question.

The explicit-notation guard also preserves ambiguous labels such as `DOCUMENT
RETENTION`, `LIST OF POLICIES`, `STATE LAWS`, `ADDRESS INFORMATION`, and numbered
title-case versions. Simply preferring the shared question heuristic produced
six heading false positives; the expanded negative corpus caught that approach.

Original question text still goes through the existing normalizer and answer
type inference. Prefixes remain in normalized text. File/sheet/one-based row and
column locations, confidence, one question per row, and sheet-local sections are
unchanged. The shared detector, workbook reader, normalizer, answer type logic,
DOCX/PDF parsers, worker, API, schema, dependencies, and UI are unchanged.

## Remaining scope

This is a conservative fix for the approved seven-question corpus, not complete
natural-language classification. A candidate heading that contains an unmarked,
unpunctuated numbered/uppercase request retains the prior heading interpretation.
It needs broader disambiguation evidence before that behavior can be expanded.
The test corpus proves the listed forms only, not arbitrary languages or layouts.
