## Existing behavior preserved

Contract ingestion requires current admin permission and assigns both the
document and generated promises to the authenticated workspace. Contract lists
require a valid session and filter by current workspace before decoding clauses.
There is no direct contract ID read/update/delete endpoint or soft-delete field.
Existing status visibility is preserved, including an `archived` status string.

Contract-backed promise creation and both singular/plural contract hash aliases
use the existing reference guard. Foreign, moved, hard-deleted and missing IDs
return the same 404 with `Referenced resource not found`, without writes. Own
hash recording and verification remain available. Anonymous callers cannot use
the authenticated contract routes; no public-capability policy changes are made.

All production files, the four existing contract tests and the existing body
reference matrix are unchanged. There are no schema, role, dependency, provider,
storage or extraction changes. Ingestion retains its existing deterministic
clause extractor; this increment does not qualify AI extraction.

## Acceptance matrix

The new suite preserves the intake's 39 checks and adds one pre-decoding isolation
case. All 40 run against FK-enforced SQLite and are also defined for the actual
migrated PostgreSQL database. Four additional PostgreSQL cases exercise default,
multi-clause and forged-scope ingestion plus an own contract-backed promise.
Successful ingestion and promise creation are deliberately PostgreSQL-only:
their real Deal dependency has a PostgreSQL-specific constraint. SQLite never
substitutes, bypasses or mutates that schema.

The fixtures use actual stored users, memberships and sessions, with expiring
signed cookies. Only `get_db` is wired to the test store. Current-role, suspended
membership, removed membership, removed session and anonymous cases exercise
the real authorization dependencies. Foreign/moved records remain present;
hard-deleted and known-missing references are distinct controls.

Read and denial cases compare full-row counts/hashes across ten SQLite tables
and eleven PostgreSQL tables, and observe SQL to reject INSERT/UPDATE/DELETE
even if later rolled back. Positive writes must leave every pre-existing row
unchanged and create only the asserted owned records. Fixture/API flushes record
exact created IDs, including writes into a wrong workspace during a regression;
cleanup deletes only those IDs in FK order and compares the original snapshot.
Collection creates no stores or database connections.
