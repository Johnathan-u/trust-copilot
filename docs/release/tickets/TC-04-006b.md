## Contract

`POST /api/auth/sessions/revoke-all` revokes all stored human sessions belonging
to the authenticated current user, including the current SID, across workspaces.
It has no body-supplied target. Success returns `{"ok": true, "revoked": count}`
and clears `tc_session` with the existing path, HttpOnly, SameSite and production
Secure attributes. Independent clients holding this user's other cookies lose
access on their next authenticated request. Other users' rows and access remain.

The existing required-session dependency still checks signed expiry, the owned
stored row, current membership and MFA restrictions. API-key contexts do not
gain human revocation authority. Pending onboarding and restricted enrollment
credentials do not gain a new allowed route. Revoked, expired, malformed and
foreign-SID credentials cannot revoke any sessions.

Deletion and `auth.sessions_revoked_all` audit persistence share one database
transaction using the existing audit helper's commit. Delete, audit-insert or
precommit database errors roll back, return a safe 503 and leave the cookie
unchanged. Cookie deletion follows successful commit. Existing `/auth/logout`
and `/auth/sessions/revoke-others` behavior is unchanged.

## Evidence and limits

The route was absent on the base: the initial matrix had 21 failures and two
passing controls for the existing current/other actions. The final new matrix
has 54 cases, 27 SQLite and 27 matching PostgreSQL cases. Real password logins
create independent clients and SIDs, including a different active workspace,
remembered/session-only cookies and a foreign user. Tests cover exact revocation
scope, rejected authority, cookie attributes, audit scope, full-row failure
invariants and a successful retry after injected database failure.

Three temporary source negative controls fail as intended: deleting foreign
users' rows, retaining the current SID as a revoke-others alias, and committing
deletion before audit persistence. The production source was restored after each
diagnostic batch. No negative-control code is committed.

Local verification passes 201 related controls, including all 27 new cases;
the unit selection passes 714 with 11 existing skips. Lint, formatting and diff
checks pass. PostgreSQL is unavailable locally: the required run exits 3 rather
than reporting skipped cases as qualified. Independent review, migrated
PostgreSQL execution and all four exact-head CI jobs remain required.

This does not complete the parent logout/lifetime feature. The security-page
action, real multi-browser UI acceptance, idle policy and visible expiration
warning remain separate frozen follow-ups. No UI, schema, setting, middleware,
refresh protocol or idle behavior changes are included. HTTP TestClients are
not real-browser acceptance. Evidence is in `artifacts/acceptance/TC-04-006b/`.
