`apps/api/tests/release/test_approval_regeneration.py` uses synthetic questions and citations:

- A matching `answer_cache` row for an approved question, with different text and citations. Generation leaves the approved text, citations, and status byte-identical and inserts no `answer_revisions` row. `skipped_protected` is 1. An unprotected question in the same questionnaire is still regenerated.
- The same generation with no cache row. The approved text, citations, and status stay. No revision row is inserted.
- `POST /api/answers/{answer_id}/regenerate` keeps the approved row and returns a `draft` revision with its own text and citations. Questionnaire read returns the approved row and that draft beside it. Export uses the approved text. `POST /api/answers/{answer_id}/revisions/{revision_id}/approve` then copies the draft onto the answer, keeps `status` `approved`, stores the previous text as `superseded`, and marks the draft `applied`. Export then uses the new text.
- A member whose role cannot review gets 403. Another workspace gets 403. A row that is not approved gets 409. Those responses do not change the row and do not insert a revision.
