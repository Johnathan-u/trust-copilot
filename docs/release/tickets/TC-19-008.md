**Depends on:** TC-19-001 (`tc/int/TC-19-001`, pull request #12). Merge this after #12.

## Behavior

One dispatcher, `fire_notification`, renders each event from `render_notification` and records a delivery attempt for email, Slack, and in-app.

Channel defaults when the user has no preference row:

| Channel | Default | Missing row |
|---|---|---|
| email | on | delivered, same as before |
| slack | on | delivered when the workspace Slack integration allows the event |
| in_app | off | silent skip. Not `suppressed-by-preference`. Existing feature code still writes its own bell rows. |

An explicit disable, or a `NotificationUnsubscribe` for that event, records `suppressed-by-preference` and does not send. An unsubscribe applies to every channel for that user. Slack is one workspace post: it is skipped only when every resolved recipient opted out, and each opted-out user gets their own suppressed attempt. That skip is a product change from posting anyway. A disabled integration or an event filter that excludes the event still writes no Slack row.

**Owner note:** skipping the Slack channel post when every recipient has opted out is intentional for this ticket and should be confirmed by the owner.

Stored dedupe key: sha256 hex of `{workspace_id}:{event_type}:{event_id}:{channel}:{recipient}`. Occurrence ids are row ids, not content: `invite:{id}`, `audit:{id}` for role, removal, suspension, and compliance breaches, and `job:{id}` for a questionnaire generation. A genuine repeat is a new row and is not dropped. An empty event id skips the claim. Email and Slack take a 15-minute lease in its own transaction before the provider call, and extend it to 24 hours only after the provider accepts. The claim is released only when the post definitely did not go out (a pre-send failure, or a provider rejection). A crash during the send waits out the lease. The in-app claim is in the same transaction as the in-app row. The worker prunes expired or released claims on the hourly pass, using indexes on `expires_at` and `released_at`. Attempt rows stay non-unique. A deduped attempt stores `error_code=claimed`.

Email and Slack retries go through `BoundedRetrySeam` (max 3). Exhaustion and a non-retryable failure become `dead-lettered`. `NotificationLog.status` stays `sent` or `failed`. The new states live on `notification_delivery_attempts` and on additive log fields: `delivery_state`, `delivered_to_provider`, `provider_mode`, `dedupe_key`, `attempt_count`.

The console email provider is the email dev stub: `provider_mode=dev-stub` and `delivered_to_provider=false` even when the local send is accepted. SMTP is the only email path with `delivered_to_provider=true`. A Slack dev stub is not recorded as provider delivery. In-app is `provider_mode=local` and `delivered_to_provider=false`.

Stored subjects, bodies, and errors pass through `redact_notification_text`. Recipient addresses are kept. Tokens, bearer values, live/test secret keys, and evidence or source-quote tails are replaced.

New routes, schema version 1, do not change the existing policy, unsubscribe, or log shapes:

- `GET` and `PUT /api/notifications/channel-preferences` for the signed-in user
- `GET /api/notifications/delivery-attempts` for an admin, with `is_read` taken from the in-app row

The notifications page adds "Your channels" for the signed-in user, including a non-admin. Log rows show the channel, the delivery state, and "Not delivered to the provider" when `provider_mode` is `dev-stub`. This is not a personal inbox.

## Assumptions

- TC-05-004, TC-07-009, and TC-10-002 are not on master. This ticket uses the seams already on #12 (`OutboundHttpSeam`, `BoundedRetrySeam`) and does not add a second retry or egress stack. `OAuthStatePkceSeam` is unchanged.
- Email retries call `BoundedRetrySeam.run_results`. Slack HTTP retries stay inside `MessageProviderHttp` and report `retrying` through `on_attempt`.
- In-app from this dispatcher stays off until the user enables it, so existing member, compliance, and worker bell rows are not duplicated. TC-19-010 still owns the personal inbox.
- Suppressed and deduped attempts are not written to `notification_log`, so an unsubscribed admin still does not appear in the legacy log.
- Master pins `sqlalchemy>=2.0,<2.1`. This ticket does not add a psycopg v3 dependency.
- TC-19-009 rule, template, and log APIs are not built. The notifications page changes only as far as the channel switches and the delivery state on the existing log.
