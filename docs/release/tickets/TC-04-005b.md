## Problem

Creating a key requires `require_can_admin`. `api_keys` has no creator column. Suspension, removal, and demotion below that role leave keys the member created usable. An administrator revoke of browser sessions also leaves them. Claude accepted that as current policy on #271 comment 6962020496 and noted it for the owner. Ruling 6 reverses it.

## Acceptance criteria

1. When a member is suspended, removed, or demoted below the role that may create keys, the keys that member created are disabled.
2. An admin can reassign or re-enable those keys, and that action is audited.
3. Document the behaviour in this file.
