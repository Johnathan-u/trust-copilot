## Problem

A corrupt evidence workbook is swallowed. A legacy `.doc` is sent to the DOCX parser. An empty non-PDF parse stores a message with no next action. Claude's #306 comment 6998916540 notes that with python-docx installed, a `.doc` file raises and ends up with the generic classified message, not the missing-library return.

## Behaviour

A corrupt `.xlsx` raises `WorkbookCorruptError` (`workbook_corrupt`) instead of yielding nothing. `.doc` and `.xls` raise `LegacyOfficeError` (`legacy_office`) before python-docx or openpyxl is imported, so an installed library cannot turn the failure into `Package not found at '<path>'` or `internal_error`. A `.docx` that cannot be opened raises `DocxUnreadableError` (`docx_unreadable`). An empty or whitespace `.docx`, `.xlsx`, `.txt`, or `.csv` raises `EmptyEvidenceError` (`empty_evidence`). Each `str()` is the reason sentence plus the next action. `index_error` and the job `error` store that text. Status is `failed`, not `indexed`.
