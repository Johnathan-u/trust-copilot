## Failure and change

PR #138 run `41015331271`, build job `123930270947`, failed in **Start isolated
Postgres (pgvector) for this run**, before backend installation, migration or tests.
The pinned image pull succeeded. A container identifier appeared at
`06:40:24.3367819Z`; at `06:40:25.7468681Z` the final probe reported
`/var/run/postgresql:5432 - rejecting connections`, then exited 1. Given the
60-attempt shell loop and this elapsed time, an earlier socket probe succeeded
and broke the loop before the final probe rejected.

The upstream official PostgreSQL entrypoint starts a socket-only temporary server
for initialization, stops it, and then starts the final server. This explains how
a default socket probe can succeed during bootstrap without the application's
TCP endpoint being ready. Primary source references and limits are recorded in
the evidence README; this is not a claimed extraction of the pinned image.

Both `pg_isready` calls now explicitly use `-h 127.0.0.1`. The loop therefore waits
for the final TCP server. The 60-attempt bound, one-second retry delay, required
final readiness check, pinned image, local port binding, per-run database name,
generated/masked credential, exports, dependency installation and every existing
CI test remain unchanged. Only these two probe arguments and explanatory comments
change in the workflow.

## Verification and remaining gate

The focused regression executes the actual YAML step under Bash with explicitly
simulated Docker command results. Four scenarios cover socket bootstrap followed
by shutdown/final TCP readiness, an already-ready server, exhaustion, and failure
of the mandatory final check. Exhaustion performs 60 bounded attempts plus the
final probe and exports no database URL. It never starts a real container or
uses real credentials.

The old workflow fails all four new controls, including the reproduced early
socket-success/final-rejection sequence. The corrected workflow passes the four
controls plus 20 existing workflow-permission controls. Deliberately removing
the final probe or increasing the loop bound is caught by its respective control.

No local Docker or Podman is available. Real pinned-container startup and all four
exact-head CI gates remain required, along with independent review. This repair
alone does not qualify every database/storage/browser requirement of TC-02-007.
