# TC-07-008: Harden private bucket and signed downloads

This file records the implementation. It does not accept TC-07-008. AC1 and AC2 stay unverified until an independent reviewer accepts them. No migration was added. No customer document is in the fixture or the evidence. The children TC-07-008a and TC-07-008b are implemented here and are not counted toward DONE by this file.

## What the check does

Original, export, and trust-request attachment bytes are returned only to a current workspace session. The document and attachment routes use `require_can_review`. The attachment route also rechecks that the caller is still a reviewer. The export route uses `require_can_export`. Those dependencies call `require_session`, which rejects a missing session row, a workspace revocation, and a session past the workspace deadline.

The browser receives the bytes from the API. `FileService.get_download_url` can mint a presigned URL, and no route calls it. These routes do not accept a share token. There is no separate public-grant download.

A stored key that fails `validate_storage_key` is a 400. The detail does not echo the key, the response sets `X-Content-Type-Options: nosniff`, and the object is not read. The same `nosniff` header is set on the document stream, both export download responses, and the attachment stream. The document and export media type comes from the filename extension. The attachment type is `application/octet-stream`. Names in `Content-Disposition` are sanitized.

An id that belongs to another workspace is 404. The body does not contain that object's key or bytes. An archived document is not streamed, and its list row has no preview URL.

`ensure_buckets` creates a missing bucket with a private ACL and a full public-access block. An existing bucket is checked and not rewritten. A public ACL or a public policy is refused. In production the block must be fully on when the store can answer, and an unsupported ACL, policy, or public-access-block call fails startup with `BucketNotPrivate`. That error is not turned into a warning. A store that is down remains a startup warning.

`S3_PRIVACY_ATTESTATION` is optional. The only accepted value is `unsupported-store-private`. Any other non-empty value refuses startup. In production that value skips only a call the store reports as unsupported, and logs one warning naming the bucket and the check. A supported call that shows public access still raises `BucketNotPrivate`. Cloudflare R2 is the store the production compose file names that cannot answer those calls. The operator confirms in R2 that public access and the r2.dev URL are off before setting it. The runbook is `docs/ops/private-downloads.md`.

## Contract

The three download routes still require the same roles. A bad key is now 400 instead of a storage 404 on the attachment route. An archived document content request is now 404. A public bucket now refuses startup. The optional attestation does not add a request or response field. No presigned URL is returned.
