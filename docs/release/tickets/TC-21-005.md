# TC-21-005 Versioned human-reviewed control mapping overrides

**Status:** implemented. Framework catalogs stay **BLOCKED** pending **TC-01-007**. No framework requirement text was added.

Routes are mounted at `/api` plus the router prefix `/compliance/control-mappings`.

## Precedence

A human override beats a confirmation, which beats a proposal. Suggest returns the current saved decision. A confirmation does not replace an active override. Rollback restores the previous version from append-only history.

Two consecutive rollbacks cancel each other out. The first rollback restores the prior version and keeps the version it left behind in history. The second rollback restores that version, so the current decision is back where the first rollback started.

Override requires a rationale. Confirm accepts an empty `control_ids` list. Existing rows that had no state are backfilled as `overridden`, version 1, with `reviewed_at` copied from `created_at`. A row that already had a state, rationale, reviewer, or version keeps those values across downgrade and upgrade.

`GET` list and `GET` suggest do not write.

## Review and audit

Confirm, override, and rollback store `reviewed_by_user_id` from the authenticated user and `reviewed_at` from the server clock. A reviewer id or timestamp in the body is ignored.

Each state change appends an `audit_events` row, the same store `persist_audit` uses, with actor, timestamp, previous state, new state, and rationale. Actions are `mapping.propose`, `mapping.confirm`, `mapping.override`, and `mapping.rollback`.

The first confirm or override also records the automatic proposal as version 1, then the human decision as version 2, in one transaction.

## Permissions

No existing route permission changed. Rollback is a new admin mutation, the same level as confirm and override.

| Route | Permission |

| `POST /compliance/control-mappings/override` | admin |
| `POST /compliance/control-mappings/rollback` | admin |

## Ambiguities

- Existing saved mappings had no state. They are backfilled as overridden so suggest still treats them as an override.
- `Idempotency-Key` is optional. Requiring it would reject current callers. A present key is claimed with an owner. A failed commit rolls back, then releases the claim. After a successful commit the claim is completed even if a later store fails; a second store failure is logged and does not replace the original error.
- A confirmation does not replace an active override. Rollback is how that override is left behind.
- `GET` suggest does not persist a proposal. The first mutation records the proposal and the human decision together.
- Rollback sets the current reviewer and timestamp to the person and clock of the rollback. History keeps the prior reviewer.
- A missing control id and a control from another workspace both return 404 with the same body. A missing mapping and another workspace's mapping both return 404 with the same body.
- `GET` list still returns stored framework names and control keys. This ticket adds no catalog text. Catalog rights stay blocked.
- No web module calls these routes. No vitest file types them. Response fields already returned are still returned, with the version fields added.
- Workspace controls expose `custom_name`, not `title`. Proposal keyword matching uses `custom_name` when `title` is absent.
