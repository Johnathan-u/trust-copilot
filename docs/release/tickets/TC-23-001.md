# TC-23-001 Typed scoped deals, rooms, and questionnaire links

**Status:** review repair implemented locally; PostgreSQL qualification, independent review, migration re-parenting, and exact-head CI remain required. Framework catalogs stay **BLOCKED** pending **TC-01-007**. Fixtures and amounts are synthetic.

Repair ownership: [#85 claim](https://github.com/Johnathan-u/trust-copilot/issues/85#issuecomment-6512133723). Findings: [PR #96 review](https://github.com/Johnathan-u/trust-copilot/pull/96#issuecomment-6511935044). Original implementation commits and attribution are preserved.

No dashboard page called `/api/deals`. The web contract is `apps/web/lib/dealConsumer.ts`.

## Amount, dates, stage, owner, refs

`deal_value_arr` is `numeric(18,2)`. The API accepts a decimal string or an integer and rejects a JSON float and a boolean. Responses send a two-decimal string. `currency` is three uppercase letters. A create that sets an amount must set a currency. The API does not ship a currency catalog.

`expected_close_date` and `actual_close_date` are dates. `close_date` stays a timestamp. Setting the expected date also sets `close_date` to that UTC midnight so the existing deadline routes keep working. A legacy `close_date` fills `expected_close_date` with its date part.

`stage` is `prospect`, `discovery`, `evaluation`, `negotiation`, `closed_won`, or `closed_lost`. The database check is `ck_deals_stage`.

`owner_user_id` must be a member of the deal's workspace. A missing user and a user from another workspace return the same 404, `Owner not found`.

Linked questionnaires, documents, and the room (`shareable_spaces.id`) must belong to the deal's workspace. A missing id, a foreign id, and a deleted document return one 404 body per ref type: `Questionnaire not found`, `Document not found`, or `Room not found`. `POST /api/deals/{id}/links` checks every ref before it writes. One bad ref leaves the stored links unchanged.

`GET` does not write.

## Response and retry

Deal responses keep the previous fields and add `schema_version` `deals/v1`, `currency`, `expected_close_date`, `actual_close_date`, `linked_document_ids`, and `room_id`. `deal_value_arr` is a decimal string.

Mutations take an optional `Idempotency-Key`. The stored key is `ws:{workspace}:deals:{action}:{deal id or new}:{raw}` and the claim records an owner token. The same raw key on create and update does not replay the other action. The response is written with the existing owner fence in the domain transaction, before one commit. Response persistence failure or a lost owner rolls back the mutation. A retry of a successful create returns the first body and does not insert a second row.

Analytics and revenue-unblocked sum stored amounts only when every non-null amount has the same known currency. Mixed currencies or any unknown currency make the total null. Analytics adds `{revenue_won,revenue_pipeline}_currency` and the corresponding `_unavailable_reason` (`mixed_currency`, `unknown_currency`, or null). Revenue-unblocked adds `currency` and `unavailable_reason`; each detail includes its stored currency. Missing amounts remain excluded, and an empty sum remains `0.00` with no inferred currency. No exchange rate or conversion is introduced. `win_rate` is null when the workspace has no closed deals.

The web consumer accepts nullable aggregate amounts and legacy/CRM records whose amount is present but currency is explicitly null. API create validation still requires currency when an amount is supplied.

## Migration

`tc23001_deal_types` currently revises `tc10001_job_leases` on the original PR branch. This repair leaves that parent unchanged. Per the coordinator's migration reservation, re-parent on the actual landed migration after PR #93, separately from this fix and any pure master merge.

A finite stored float is kept when it is in the numeric range and `round(value::numeric, 2)::double precision` equals the float. Other non-null amounts are copied to durable `tc23001_deal_amount_hold` as text with the reason `float value is not exactly representable as numeric(18,2)`, and the column is set null before conversion. Holds include workspace, row creation, and update checkpoints. `expected_close_date` is backfilled from `close_date::date`. Currency, actual close, document ids, and room id start null for rows with no prior typed snapshot.

Downgrade locks the deals table and stores exact amount text, currency, both dates, linked document text, room, close-date projection, and row identity in `tc23001_deal_state_archive` before the old schema's float projection or column removal. A legacy hold is restored only for an unchanged null amount with matching identity/update checkpoints; it cannot overwrite a correction. The hold table survives downgrade.

Re-upgrade selects the latest snapshot for the same id, workspace, and creation timestamp. An unchanged float projection restores the exact decimal, including `90071992547409.91` and the numeric maximum `9999999999999999.99`. An older-version amount or close-date edit wins; other supported common-field edits stay intact. New older-version rows follow normal backfill. Missing rows are never recreated and changed ownership/identity never receives archived values.

Room and document restoration rechecks current workspace ownership, document deletion, and document-list shape. Unsafe references stay null. Only a fully restored snapshot is removed; conflicts and unavailable references retain all exact typed values plus `restore_issue` for explicit recovery. Older unresolved snapshots remain available across later cycles. Recovery tables have no cascading foreign keys and are deliberately retained on downgrade; do not discard them during rollback cleanup. A stage outside the enum still fails upgrade.

## Ambiguities

- There was no web caller of `/api/deals`, so no page import changed. The consumer and its vitest are the web side of the response schema.
- Currency is the three-letter shape, not a downloaded ISO table.
- Mock CRM sync still stores integer example amounts and does not invent a currency.
- `avg_close_days` stays a day count computed from stored timestamps.
- Typed fields unavailable on the parent schema are retained in the rollback archive and restored only under the rules above.
