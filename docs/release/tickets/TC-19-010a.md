# TC-19-010a: notification inbox acknowledgement

Scope authorized in issue #85, rulings 6504557554 and 6510620603. PR #75 has
landed; the coordinator posted the required shared-UI notice. This is the existing
notification-panel consumer follow-up for TC-19-010, not backend inbox completion.

The panel now checks the server's acknowledgement before changing unread rows.
Rejected and network-failed writes leave those rows and the last confirmed badge
unchanged, with a visible error. An accepted write refreshes `/unread-count`;
loading/reopening the 20-row list also refreshes that endpoint. Neither the
panel heading nor the bell derives a total from the limited page. Mark-all also
uses the returned total rather than assuming no notifications arrived meanwhile.

Existing response contracts and components remain in place. No backend, Sidebar,
dependency, notification delivery, preference, or authorization changes are made.
The seven-case browser spec uses synthetic HTTP fixtures, so it qualifies the
consumer behavior only. Backend per-user receipt coverage remains with #95.
