# TC-20-001 Versioned provider adapter and observation contracts

**Status:** implemented on `tc/int/TC-20-001`. Reviewer sign-off is still open.
**Contract:** `provider-observation` schema version `1` (`finding_status_vocabulary`: `observation-state-v1`).
**Collector version:** `tc-20-001/1`. **Capability version:** `1`.

## Behavior

Every connector adapter returns `ProviderObservation` values with a real `obs_` id, a timezone-aware `observed_at`, an object revision, a collector version, a source-version token, and redacted provenance. The same envelope is `observation_contract` on AWS, GitHub, Google Workspace, GCP, Azure, GitLab, Okta, HRIS, Salesforce, HubSpot, the connector wizard, connector health, credential custody, and the source registry.

Observation state is one of:

| State | Meaning |
| --- | --- |
| `success` | A recorded, redacted value that passed the evidence guard |
| `missing_permission` | The fixture or credential shape says access was not granted |
| `unknown` | Nothing was observed. This includes static catalog signals |
| `failure` | The recorded fixture or sync bookkeeping says the attempt failed |
| `unsupported` | Generic HRIS. TC-20-005 is BLOCKED. No vendor is selected |

Unknown, missing permission, failure, and unsupported are not success and are not an empty compliant result. Default collection does not call a provider. It emits one `unknown` observation per catalog signal (HRIS emits `unsupported`) with provenance `static_catalog` or `absent`. A hand-built `RecordedCollection` can produce success, missing permission, unknown, or failure without network access. HTTP routes do not accept that fixture.

Existing response keys stay in place (`source`, `findings`, `collected_at`, `synced`, `details`, wizard setup fields, health counters, credential fields, registry fields). `findings[].status` now uses the observation-state vocabulary instead of the static token `check_required`. Additive fields include `observation_id`, `observed_at`, `provenance`, `source_version`, `error_code`, `observation_contract`, `adapter_contract`, and `evidence_posture`. `live_collection` is `false` on every descriptor from this ticket.

## Evidence boundary

`store_successful_observation` is the only path that may insert collected provider evidence (`EvidenceItem`, source type `integration`). It rejects, before `Session.add`:

- any state other than `success`
- provenance `demo`, `seeded`, `static_catalog`, `credential_custody`, or `absent`
- a normalized value whose status or flag is `check_required`, `demo`, or `seeded`
- the hand-built CRM ids `sf-opp-001`, `sf-opp-002`, and `hs-deal-001`
- an empty success value
- unredacted provenance

Salesforce and HubSpot sync return `synced: 0` and `details[].action = rejected`. They do not insert demo deals. Manual `ingest_evidence` still stores ordinary titles. It rejects intake whose metadata carries those markers or an observation-shaped success claim. Credential responses and registry seed rows carry observations, and those observations are not stored as collected evidence. A health row whose `last_sync_status` is `success` stays operationally healthy and its evidence posture stays `unknown`, because sync bookkeeping is not collected evidence.

Repeated storage of the same idempotency key does not insert a second row. The default claim set is process-local (see assumptions).

## HRIS

The generic HRIS adapter is on this contract and always returns `unsupported` with `vendor_selected: false` and `accepts_success: false`. A caller-supplied name such as `BambooHR` is still echoed on the legacy `provider` query field and is not a vendor selection. `external_account_id` on the HRIS connection is null. TC-20-005 stays BLOCKED.

## Persistence

No database migration. Observations that pass the guard are stored in the existing `evidence_items.source_metadata` JSON. Upgrade and rollback checks are not required for this change.

## Prerequisites

TC-07-002, TC-10-003, and TC-08-001 are not implemented here. Callers depend on `KeyPurposePort`, `SideEffectIdempotencyPort`, and `SourceVersionPort` in `app/services/provider_adapter/seams.py`. The local defaults only name a key purpose, claim a key in memory, and hash a content-free source token.

## Tests

`apps/api/tests/release/test_connector_adapter.py` covers success, missing permission, unknown, failure, and rejection of `check_required`, demo, and seeded values. Fixtures are hand-built. The test process does not open a socket for collection.

```bash
python -m pytest tests/release/test_connector_adapter.py -q
```

Run that from `apps/api`. Command, SHA, environment, and totals are in `artifacts/acceptance/TC-20-001/`.
