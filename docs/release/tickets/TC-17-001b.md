## Problem

`_viewable_version` lets any member publish the current draft as a side effect of acknowledging. That should be a 400.

## Behaviour

`_viewable_version` (`apps/api/app/api/routes/trust_articles.py`) returns the row at `published_version_id` when `published` is 1. It does not call `approve_current_draft`. A member `POST /trust-articles/{id}/acknowledge` therefore cannot create or approve a version.

When the article is published and `published_version_id` is null, or that id does not point at a `trust_article_versions` row, the acknowledge returns 400 with `Article has no published policy version`. `published_version_id` stays as it was. No version row and no acknowledgment row are written.

An acknowledge of the current published version still returns 200. An administrator create or update with `published: 1` still calls `approve_current_draft` under `require_can_admin`.

The trust-center dashboard already shows this refusal as an error. A policy with no `published_version_id` toasts "This policy has no published version" and does not send the request. A request that comes back 400 toasts the API `detail` on an error alert (`apps/web/app/dashboard/trust-center/page.tsx`, `acknowledgePolicy`). No dashboard change.

## Acceptance criteria

1. A member acknowledge does not call `approve_current_draft`.
2. Acknowledging when there is no published version returns 400.
3. Document the behaviour in this file.
