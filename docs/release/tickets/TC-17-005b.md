## Problem

Create stored `article_ids`, `answer_ids`, and `document_ids` without checking that each id exists in the space's workspace. Token access returned those lists as stored. A share token could not download an original, and the reviewer download route does not read the token or the lists. A listed id from another workspace was therefore both stored and returned, and it did not gate a download.

## Behaviour

`POST /api/shareable-spaces` stays on `require_can_admin`. Before the row is inserted, every article, answer, and document id must be a live row in the caller's workspace (`shareable_space_service.py` `create_space`, `_require_ids`). A missing id, a deleted document, an answer whose questionnaire is deleted, and an id from another workspace are the same 404: `Article not found`, `Answer not found`, or `Document not found`. The route does not commit. No space row is written. Empty lists and omitted lists stay empty. An unpublished article that belongs to the workspace can still be listed on write. Checks run articles, then answers, then documents, and the first failure rejects the whole request.

`PATCH /api/shareable-spaces/{space_id}` is admin-only, the same bar as create. It replaces only the lists the body sends. An explicit null clears that list. Validation finishes before any column changes. A bad id is the same 404 as create, and the saved lists, token hash, and `updated_at` stay as they were. A space in another workspace is 404 with the default not-found body, and that row is not changed. The response does not include a raw token. `has_access_token` is set for the admin, as on deactivate. Editors receive 403 and the row is unchanged. Rotate, deactivate, and list are unchanged.

`GET /api/shareable-spaces/access` still accepts a hashed token, then active, then unexpired, and it still writes `shareable_space.accessed` with the space id only. The three id lists in that response keep stored order and omit an id that is missing, not an integer, deleted, or no longer in the space's workspace. A bad row that was stored before this check is filtered on read. The stored JSON is not rewritten. An article is omitted unless `published` is 1 and a published version row exists. An answer is omitted unless `status` is `approved`.

Token reads and the original download are separate from the reviewer session:

| Route | Who |
| --- | --- |
| `GET /api/shareable-spaces/access/documents/{id}/content?token=` | live token, document listed and still in the space's workspace |
| `GET /api/shareable-spaces/access/articles/{id}?token=` | live token, article listed, `published` is 1, and `_load_version` returns a snapshot |
| `GET /api/shareable-spaces/access/answers/{id}?token=` | live token, answer listed, questionnaire in the workspace and not deleted, `status` is `approved` |
| `GET /api/documents/{id}/content` | `require_can_review` and the caller's workspace. A share token is not read. |

The article read returns the published version's title and content. It does not return the live draft columns. `published` other than 1, or no version, is 404 `Not found`. A later edit of the draft does not change what the token serves. The answer read returns id, text, and status for an approved answer only. A draft, rejected, or other status is the same 404, and that id is not in `answer_ids`. Citations are not included.

An unknown, inactive, or expired token, an unlisted id, a deleted document, and an id from another workspace are the same 404, `Not found`. The body does not contain the other object's bytes or text, and it does not contain the storage key. A listed document is streamed with the same media type, disposition, and nosniff headers as the reviewer download. Removing an id, deactivating the space, or letting it expire makes the previous download fail. A token for a different space cannot download an object listed only on this one.

There is no migration. Existing JSON columns stay.

## Acceptance criteria

- **AC1:** Create and update reject, with 404 and no write, an article, answer, or document id that does not exist or does not belong to the space's workspace.
- **AC2:** Token access returns only listed ids that still belong to that workspace, including when a stored row already contains a bad id. Unpublished or versionless articles and answers that are not `approved` are omitted.
- **AC3:** A token download or read serves only an object listed on that live space. Any other id, including one from another workspace, is 404. An article read serves the published version only. An answer read serves `approved` only. The reviewer content route still requires `can_review`.

## Scope

P1 follow-up from the #323 review. It does not show the lists on the share page, make create idempotent, add `tests/release/test_domain_shareable_spaces.py`, or add `docs/release/tickets/TC-17-005.md`. Those are TC-17-005c. It does not change who may create, list, rotate, or deactivate a space, and it does not return the raw token on any route that did not already return it.
