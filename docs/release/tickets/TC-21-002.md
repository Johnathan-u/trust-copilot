# TC-21-002 Legacy and canonical control contract reconciliation

**Status:** implemented. Framework catalogs stay **BLOCKED** pending **TC-01-007**. This ticket does not add framework control text.

The legacy routes in `apps/api/app/api/routes/controls.py` and the compliance routes in `apps/api/app/api/routes/compliance_controls.py` keep their existing request and response fields. Agreement is an additive `canonical` object, `control-contract/v1`.

## Canonical object

Both list and write responses include:

| Field | Meaning |
| --- | --- |
| `contract_version` | `control-contract/v1` |
| `id` | `framework:control_id` for the shared identity |
| `version` | Always null. Not a licensed catalog version. |
| `content_version` | Always null while TC-01-007 is open. The column is only a slot. |
| `owner_user_id` | Workspace member, or null |
| `owner_team` | Free text, or null |
| `lifecycle` | `not_implemented`, `in_progress`, `implemented`, or `verified` |
| `status_aligned` | False only when both stored lifecycle columns are set and differ |
| `evidence` | `control-evidence/v1` counts and the mirror flag |

Lifecycle is the workspace vocabulary. The legacy `status` column stays `implemented`, `in_review`, or `na`. `verified` is stored as lifecycle `verified` and projected to legacy status `implemented`, because that column has no verified value. The `lifecycle` field is the one status both routes return.

A paired read uses the workspace row's lifecycle when the stored columns differ. GET does not rewrite the drifted column. The next edit writes both columns to the same lifecycle.

## Routes

Legacy, mounted at `/api/controls`:

- `GET /` and `GET ""` require review and do not write
- `POST /`, `PATCH /{id}`, `DELETE /{id}` require edit
- `GET /{id}/evidence` requires review and does not write
- `POST /{id}/evidence` and `DELETE /{id}/evidence/{evidence_id}` require edit

Compliance writes that change a control or an evidence link require edit. `GET` stays review. Suggest-evidence does not persist and stays review.

A control or evidence target in another workspace is 404. An owner who is not a member of the workspace is 404. Repeating `POST /api/controls/` with the same framework and control id updates that row instead of inserting another one. Repeating an evidence target reuses the link and finishes the canonical mirror.

`POST` evidence with a document also creates or reuses an `evidence_items` row and a `control_evidence_links` row on the paired compliance control. If that mirror hits a foreign-key failure, the legacy link stays and the response is `control_evidence_partial_failure` (`control-contract-error/v1`, retryable). The retry does not insert a second legacy link.

A contract-event foreign-key failure after the pair is saved returns `control_contract_partial_failure`. The control stays. The retry writes the event and returns the same row.

Deleting a legacy control also deletes the paired compliance row when that row has no evidence links. Otherwise the compliance row remains the only copy.

## Migration

`tc21002_control_contract` revises `tc10003b_idempotency_owner_token`. It adds nullable columns and `control_contract_events`. It does not rewrite existing status values and does not insert framework rows. Downgrade drops only those additions.

## UI

`apps/web/lib/controlContract.ts` reads the nested object. It rejects a non-null version. The same reader accepts a legacy payload and a compliance payload.

## Ambiguities

- Canonical lifecycle uses the compliance vocabulary. Legacy `status` is unchanged as a stored projection.
- `version` and `content_version` are forced null in responses. Writes clear the slot. No licensed version is accepted on the request.
- GET reports the workspace lifecycle for a drifted pair and does not repair it.
- Historical rows are not backfilled.
- A compliance control with no framework control uses the label `custom` plus the custom name. No catalog text is copied into a new description.
- `verified` projects to legacy `implemented`.
- Delete removes the compliance pair only when it has no evidence links.
- Suggest-evidence stays a non-persistent review route.
- `rights_are_cleared()` was removed because nothing called it. The rights gate remains the catalog paths that already return blocked.
