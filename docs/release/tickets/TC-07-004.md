# TC-07-004 — Enforce trusted origin host and proxy boundaries

Status: the behavior below is the change on this branch. This note does not accept the ticket. Independent review is still open. No migration and no tracker edit.

Evidence: [artifacts/acceptance/TC-07-004/README.md](../../../artifacts/acceptance/TC-07-004/README.md).

Ruling: issue #85, 2026-11-18 15:54Z. Reject an untrusted `Origin` before the Referer and `X-Forwarded-*` fallbacks. Trust `X-Forwarded-*` only from a configured proxy.

## Decision

A state-changing request that carries `tc_session` is checked in `CSRFMiddleware` (`apps/api/app/main.py`). The check is `is_csrf_safe` (`apps/api/app/core/csrf.py`).

- When the `Origin` header has a non-blank value and that value is not an allowed origin, the check returns false immediately. The literal `null` (any letter case) is one of those values. Referer and `X-Forwarded-Host` / `X-Forwarded-Proto` are not consulted.
- A blank `Origin` is treated as absent, which is what the previous normalizer did. Referer can still allow the request.
- When `Origin` is absent, a Referer whose origin is in the allow-list is still accepted.
- `X-Forwarded-Host` and `X-Forwarded-Proto` are used only when the direct peer (`request.client.host`) is listed in `TRUSTED_PROXY_IPS`. The list is comma-separated IP addresses or CIDRs. Unset, empty, and malformed entries trust nothing. An IPv4-mapped IPv6 peer matches the IPv4 address or network. The first forwarded host is the one that is checked, and the synthetic origin must be in the same allow-list as `Origin`.
- The middleware passes the peer and the current `TRUSTED_PROXY_IPS` value. `is_csrf_safe` does not read the environment itself. Callers that omit the new arguments trust no forwarded host.
- The local-host fallback is unchanged. When `Origin` and Referer are both missing and the request host is `localhost`, `127.0.0.1`, `::1`, `::ffff:127.0.0.1`, or `testserver`, the check still returns true. That path does not look at forwarded headers.
- `get_client_ip` uses the same peer matcher for `X-Forwarded-For`. Exact addresses that matched before still match. A CIDR, which previously matched nothing, now matches peers inside it.

## Proxy

`infra/caddy/Caddyfile.production` overwrites `X-Forwarded-Host` and `X-Forwarded-Proto` on every `reverse_proxy api:8000` block. `header_up` without `+` replaces the field. The values are `{http.request.host}` and `{http.request.scheme}`, the host and scheme Caddy received. A client-supplied value does not continue upstream.

The API still ignores those headers unless `TRUSTED_PROXY_IPS` lists the Caddy container's address on `trustnet`, or a CIDR that contains it. The compose file does not default the variable. It is read from `.env.production` through `env_file`. Unset trusts nothing, so a browser request is accepted from its `Origin` (or Referer when `Origin` is absent), not from a forged forwarded host.

## Configuration

| Setting | Meaning |
|---|---|
| `TRUSTED_ORIGINS` | Allow-list for `Origin`, Referer, and a proxy-supplied forwarded origin. Unchanged. |
| `TRUSTED_PROXY_IPS` | Direct peers allowed to set `X-Forwarded-For`, `X-Forwarded-Host`, and `X-Forwarded-Proto`. IPs or CIDRs. Unset trusts none. |

Documented in `.env.example`, `README.md`, `docker-compose.prod.yml`, and `docs/release/config-contract.md`.

## Existing origin test

`tests/test_csrf_origins.py::test_csrf_safe_x_forwarded_host_matches_trusted` used to pass `X-Forwarded-Host` with no peer, so any caller was treated as the proxy. It now passes `client_ip="10.0.0.8"` and `trusted_proxy_ips="10.0.0.8"`. The other seven tests are unchanged. All eight still pass.

## Tests

From `apps/api`, no database:

```sh
python -m pytest tests/release/test_csrf_proxy.py -q
```

The file covers a hostile `Origin` with a matching Referer, a hostile `Origin` with an allowed `X-Forwarded-Host` from a trusted proxy, `Origin: null`, forwarded headers from an untrusted peer, forwarded headers from a trusted proxy (exact IP, CIDR, and an IPv4-mapped peer), an allowed `Origin`, and the same-origin paths that omit `Origin`. It also checks that each production API upstream replaces the two forwarded headers.

`_check` drops keyword arguments the function does not accept. On the pre-fix function, which had no peer argument, the same file fails on the insecure result instead of on an unexpected keyword.

## Rollback

Revert this change. There is no schema change and no backfill. After revert, a hostile `Origin` can again be accepted when Referer or `X-Forwarded-Host` matches the allow-list, and forwarded headers are honoured from any peer. Exact IPs in `TRUSTED_PROXY_IPS` keep their previous `X-Forwarded-For` meaning. A CIDR stops matching until this matcher is restored.

## Not in this change

Verification gap 2 (narrow CORS `allow_methods` and `allow_headers` in `apps/api/app/main.py`) is not part of the 2026-11-18 ruling. CORS is unchanged. `trustnet` has no pinned subnet; the operator chooses the proxy address or CIDR. This note does not mark the ticket done.
