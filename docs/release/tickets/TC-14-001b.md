# TC-14-001b — Run the design-tokens Playwright and axe spec in CI

Status: implemented on `tc/web/TC-14-001b`. Follow-up to TC-14-001 (`705bdde`, PR #6). The spec stays `apps/web/e2e/release/design-tokens.spec.ts`. This ticket runs that spec in GitHub Actions instead of only on a laptop.

## What changed

- `.github/workflows/ci.yml` gains a `web-release-e2e` job. The existing `build` job is unchanged: Node 24 from `apps/web/.nvmrc`, `npm ci --ignore-scripts`, the TC-02-006 web gates (lint, format check, unit tests, typecheck, build, audit), and the TC-07-001 secret tree scan stay in the same order.
- The job installs the locked frontend tree, installs Playwright's Chromium browser with `npx playwright install --with-deps chromium`, and caches `/home/runner/.cache/ms-playwright` on the lockfile hash. No new npm dependencies.
- Playwright starts the Next dev server the way `apps/web/playwright.config.ts` already does (`npm run dev` on port 3000, local `API_UPSTREAM` only). `E2E_SERVER_RUNNING` is not set, so the auth setup project does not run and the API is not required. The showcase at `/design-tokens` is public.
- The job runs an explicit list of release specs and skips a listed path that is not in the tree. The only path on master is `e2e/release/design-tokens.spec.ts`. Later specs (`responsive-shell`, `dialog-toast`) are comments in that list until their files exist.
- `scripts/ci/check-release-e2e-report.mjs` reads the Playwright JSON report and the axe JSON the spec writes. The job fails when Playwright exits non-zero, when the design-tokens spec did not run at least 4 tests, when any test failed, skipped, or flaked, or when any axe report has `violationCount` above zero (any impact, not only serious and critical). `--retries=0` so a failed attempt is not hidden by the config's CI retry count.
- On success and on failure the job uploads the Playwright HTML report (`playwright-html-report`) and the axe JSON (`design-tokens-axe-json`). Checked-in TC-14-001 evidence is not modified by this branch. The runner deletes the checkout's axe JSON before the spec rewrites it, and nothing in the job commits that output.

## How to run it locally

Node 24.22.1 (`apps/web/.nvmrc`), from a clean tree:

```bash
cd apps/web
npm ci --ignore-scripts
npx playwright install --with-deps chromium
npx playwright test e2e/release/design-tokens.spec.ts --retries=0 --reporter=list,html
```

That command rewrites `artifacts/acceptance/TC-14-001/axe-*.json` and the screenshots next to them. Those files are TC-14-001 evidence. Restore them if you do not mean to refresh that ticket (`git checkout -- artifacts/acceptance/TC-14-001`). The HTML report is `apps/web/playwright-report/` and is gitignored.

To check a JSON report the same way CI does:

```bash
node scripts/ci/check-release-e2e-report.mjs \
  --report apps/web/test-results/release-e2e.json \
  --axe-dir artifacts/acceptance/TC-14-001 \
  --html-report apps/web/playwright-report \
  --require-spec e2e/release/design-tokens.spec.ts \
  --min-tests 4
```

A clean run prints `design-tokens.spec.ts: 4 passed, 0 failed, 0 skipped, 0 flaky, 0 axe violations`.

## Evidence

Synthetic showcase only. The page and the axe JSON contain no credentials or customer content.

Local preflight, before CI, from `apps/web` on Node v24.22.1 and npm 11.19.1 with the locked Playwright 1.64.1 and Chromium build 1248:

```text
npx playwright test e2e/release/design-tokens.spec.ts --retries=0 --reporter=list,html,json
4 passed (12.3s)
design-tokens.spec.ts: 4 passed, 0 failed, 0 skipped, 0 flaky, 0 axe violations
```

The generated axe JSON and screenshots were restored afterward so this branch does not replace TC-14-001 evidence. `apps/web/next-env.d.ts` is also unchanged. `next dev` rewrites that file to `.next/dev/types` while the server is running; the production path checked in on master stays.

The proof that CI executed the spec is the `web-release-e2e` job log for this PR: Playwright's list reporter, then the checker's `design-tokens.spec.ts: N passed, … axe violations` line. The uploaded `design-tokens-axe-json` artifact is the axe output from that run.

## Judgment calls

- A separate job, not new steps inside `build`. That keeps the secret scan before installs and leaves the web-quality gate order untouched. Playwright's apt packages stay off the backend job.
- An explicit spec list with skip-if-missing, not a glob of `e2e/release/`. A glob would run a future spec as soon as the file landed, including one that still needs the API and the auth setup project.
- The dev server from the Playwright config, not `next start`. Setting `E2E_SERVER_RUNNING` would also enable `e2e/auth.setup.ts`, which needs the API and seed credentials.
- `--retries=0` and a failure on flaky tests. The shared config retries twice when `CI` is set, for the full-stack suite. This spec is deterministic, and a retry-pass should not count as green.
- The axe gate fails on every impact. The spec itself fails the process only for serious and critical violations. The checker also fails when `violationCount` is non-zero.
- Browser binaries are cached. `playwright install --with-deps chromium` still runs on a cache hit so the OS libraries are installed on a fresh runner.
