## Behaviour

Line numbers were read on this change.

**Revision.** `updated_at` is the loaded revision. `AnswerUpdate.updated_at` carries it (`apps/api/app/api/routes/answers.py:42`). It is not written as the new value. `answer_revision_token` is the ISO form (`answers.py:62-68`). `_expected_answer_revision` runs after the workspace checks and before any column change (`answers.py:76-90`, called from `:228`). Omitting the field, sending it blank, or sending a different value is 409 with `This answer changed since it was loaded. Reload it and try again.` The handler rolls back. The `UPDATE` also requires the loaded timestamp (`answers.py:93-112`), so a second request that read the same row before the first commit does not overwrite it. On 409 the stored text and `updated_at` stay.

A matching revision writes the sent text and status and a new `updated_at`. Changing the text still clears `outcome_code` and `insufficient_reason`. The response stays `id`, `question_id`, `text`, and `status`.

**Lock.** `update_answer` takes the existing per-question advisory lock after authorization and before the revision check (`answers.py:225-226`). The lock is `pg_advisory_xact_lock` (`apps/api/app/services/answer_generation.py:1848-1857`). It serializes commits. It does not detect a stale editor. Create and bulk still take the same lock.

**Read.** `GET /api/questionnaires/{id}` puts `updated_at` on each answer (`apps/api/app/api/routes/questionnaires.py:775-776`). A later read returns the text of the save that committed.

**Editor.** The review save builds the request in `apps/web/lib/answer-save.ts`. A row that already has an answer id is `PATCH` and the body includes the loaded `updated_at` (`answer-save.ts:20-30`). The page sends that request (`apps/web/app/dashboard/review/[id]/page.tsx:295-307`) from the value on the loaded answer (`page.tsx:1372-1377` and `:1431-1437`). `answerRowAfterSave` treats 403, 409, and 500 as not saved (`answer-save.ts:55-72`). The page then clears the save phase and does not reload (`page.tsx:317-326`). The textarea value stays the typed text (`page.tsx:1367`). The label is `rowSaveLabel` of an unset phase, which is `Not saved yet` (`page.tsx:1385`, `apps/web/lib/action-copy.ts:62-67`). `Saved` is set only when the status is 2xx (`page.tsx:328-332`).

**Other writes.** A missing answer is still 404 and another workspace is still 403, before the revision check (`answers.py:216-224`). `POST /api/answers` still creates a row when the question has none, and the existing upsert rules for an empty body are unchanged. `PATCH /api/answers/bulk` does not use this revision.

The named test uses synthetic text. Two clients save one answer. The stale client gets 409. A later questionnaire read returns the winner's text. A save that omits `updated_at` is 409 and the row stays. Web unit coverage is `apps/web/tests/unit/answer-save.test.ts`.
