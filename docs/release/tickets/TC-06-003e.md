# TC-06-003e — Credential authorization acceptance

Parent: frozen TC-06-003. Estimate: 3 points. Base: `46603ee17b686d22d86da14227c58a7dad9a4e94`.
Claim: #85/6516617322; bounded timestamp amendment: #85/6516679370.
Status: local verification complete; independent review and actual PostgreSQL CI pending.

The five existing credential endpoints already scope their queries to the current
authenticated workspace and require current `can_admin`. This child exercises
that contract with stored human sessions and real routes, encryption and database
queries. It introduces no new permission, role, endpoint or credential lifecycle.

The first populated SQLite rotation-due case exposed a `TypeError` comparing a
naive database timestamp with aware UTC `now`. The approved amendment changes only
the comparison in `check_rotation_due`: interpret a naive timestamp as UTC while
preserving an aware timestamp's instant. The stored field, query filters,
interval, status and serialization remain unchanged. This was a reproduced
SQLite failure; no PostgreSQL failure is claimed.

Acceptance:

- Real stored session/current membership/custom grants govern all five endpoints.
  Demotion, suspension, removal, revoked/expired sessions and missing or foreign
  custom grants deny access before a credential query and without SQL writes.
- Own create/update/revoke commits affect only the intended credential. Foreign
  duplicates are inserted first to expose an accidentally unscoped upsert.
  Foreign-only and missing revoke targets produce the same 404 and preserve all rows.
- Lists, populated due/expiring results and empty collections return only the
  current workspace. Ciphertext and plaintext are absent from public fields.
- Every column in seven fixture tables is hashed for equality checks, including
  credential ciphertext and metadata. Cleanup deletes only IDs owned by the
  fixture and credentials in its uniquely owned workspaces; pre-existing rows
  must match the original snapshot.
- The HTTP matrix runs unchanged against SQLite and migrated PostgreSQL. Clock
  boundaries are checked before, at and after expiry; separate service controls
  exercise naive UTC and aware UTC/non-UTC datetime inputs without normalizing
  fixtures or claiming SQLite stores timezone offsets.

Local evidence: 91 cases pass (79 SQLite HTTP cases plus 12 comparison controls);
all 170 cases collect. The other 79 cases require PostgreSQL CI. See
`artifacts/acceptance/TC-06-003e/` for commands, negative controls and limitations.

This does not close the parent authorization ticket, introduce owner/viewer
semantics, qualify external provider credentials, or fix the separately recorded
process-global confidence settings issue (TC-12-012a). PostgreSQL, exact-head CI,
independent review and later master integration remain required.
