# TC-06-002e — Authorize export-job artifact metadata

Child of frozen TC-06-002; 3 points. Claim and technical ruling:
[#85/6515818819](https://github.com/Johnathan-u/trust-copilot/issues/85#issuecomment-6515818819).
Base: `d0ec3fe33233e1cc0aa10b92cd7c8fbf2d2d5b5a`. Depends on the landed human-principal
contract. Status: implemented locally; independent review, PostgreSQL execution,
and exact-head CI remain required. Full TC-06-002 remains open.

The intake reproduced a real stored-session request returning a stored export
record ID and storage key after its questionnaire was foreign, moved, archived,
or deleted. The history list already withheld its object reference. This was
artifact metadata disclosure; no file bytes were downloaded.

The export-only result projection now requires exact integer identifiers, a
payload workspace matching the job, an active questionnaire in that workspace,
and an export record belonging to that job, questionnaire, and workspace. It
returns the authorized record's canonical ID/key and a recognized optional
outcome. Stored keys, arbitrary URLs, nested content, and unknown outcomes are
not copied. An unresolved or malformed artifact parent yields `result: null`;
a database lookup failure propagates without falling back to stored metadata.

The existing lifecycle response fields remain intact. Non-export legacy results,
including the parentless generate-answers fixture, retain their behavior. The
shared renderer also protects export metadata in cancel/retry responses; their
handlers, permissions, and mutation behavior are unchanged. A read-only,
already-cancelled response is covered.

Verification: `artifacts/acceptance/TC-06-002e/`.

The PostgreSQL questionnaire-parent move trigger rejects a cross-workspace move
while the record still points at it (`23514`); the record-side trigger rejects an
inconsistent record workspace (`23503`). Those cases assert rejection and full-row
preservation first, then detach the fixture-owned nullable reference before a
permitted move and require the stale job result to be null. Neither triggers nor
foreign keys are bypassed. These PostgreSQL cases are authored, not locally
qualified: PostgreSQL is unavailable in this environment.

CI fixture correction: push run `41010994109`, build job `123916590609`, failed
the two PostgreSQL move cases at the callers' final commits (2 failed, 4187
passed, 1 skipped). The helper compared the SQLAlchemy dialect name with
`postgres`; the actual name is `postgresql`. Consequently, its expected-rejection
and detach branch never ran. The repair changes only that test-helper literal.
Every trigger, rejection assertion, row invariant, transaction and runtime byte
is preserved. A no-connection probe of the configured SQLAlchemy engine proves
the old condition false and the repaired condition true. The repaired PostgreSQL
cases still require actual CI execution; this probe does not qualify them.

No schema, worker, storage, source-version, export-download, provider, dependency,
or CI changes. Cancel/retry action authority, other job kinds' parent authorization,
and the rest of TC-06-002 remain separate work. No fourth worker PR is authorized;
the coordinator owns review and publication.
