# TC-14-006a — Sidebar landmarks and the shared navigation drawer

## Landmark labels

The sidebar region and the navigation inside it both used `aria-label="Application"`. Screen-reader landmark lists then showed two "Application" entries, one complementary and one navigation.

The aside is labeled **Sidebar**. It is the complementary region that holds the workspace switcher and the navigation, so it needs its own name. Dropping the aside label would leave that region unnamed even though the workspace control sits outside the nav.

The nav stays **Application**. That name is the set of application destinations. **Main** would be confused with the main content landmark. **Primary** is already the wide top-bar nav.

`axe` rule `landmark-unique` treats two landmarks as duplicates only when they share both role and accessible name. These two have different roles, so that rule alone would not have failed the old labels. The browser spec still runs `landmark-unique` (the full axe scan must stay at 0 violations) and also asserts that no two visible landmarks share an accessible name.

## Drawer

`NavDrawer` no longer has its own focus trap. It renders `Dialog` with `placement="drawer-start"`. Focus moves inside on open, Tab wraps, Escape closes, focus returns to Open navigation, and the rest of the page is inert. The panel stays on the start edge. The command palette and the tablet jump list still use `appNavItemsFor`, so Requests and Admin stay behind the same permission flags as the sidebar.

`docs/design/tokens.md` now says the mobile drawer uses that placement. Only that sentence in the dialogs-and-toasts note was changed.

Settings role gating tracked separately.
