# TC-04-001b: OAuth state binding, OIDC nonce and PKCE, provider claim hardening

Follow-up of TC-04-001. It collects the items the independent reviews of #193 (heads `68ed30d`, `75cb6d7` and `138e047`) left as non-blocking. The state, nonce and PKCE gaps predate #193. The unused `OIDC_DEFAULT_WORKSPACE_ID` is a result of #193. None of these is one of the takeover fixes in TC-04-001.
Epic E04. 5 points, P1. Depends on TC-04-001. Branch: `tc/TC-04-001b-oauth-hardening`.

## Acceptance criteria

1. The Google and GitHub callbacks compare the signed `state` with the browser's state cookie and reject a mismatch, which blocks login CSRF. The OIDC flow uses a `nonce` and PKCE (S256), and the callback validates both.
2. Provider claims:
   - OIDC never uses `preferred_username` as an email.
   - ID.me's `verified` claim is not treated as email verification.
   - Linking by email to an existing account revokes that account's sessions, or requires a password reset when the password was set before verification.
3. Duplicate registration takes the same time as a new registration, so response timing doesn't reveal whether an email is registered.
4. `OIDC_DEFAULT_WORKSPACE_ID` is marked deprecated in the config contract, and setting it logs a warning.
5. Resend and lockout abuse:
   - Resend responds in the same time whether or not an unverified account exists.
   - A third party can't use up a victim's resends, or lock the victim's address or user id out of verification.
   - Neither limit weakens brute-force protection.
6. Sessions and links at rollout:
   - Sessions held by unverified accounts at deploy are ended.
   - Provider sign-in through an existing link refuses an unverified account, or verifies it only from a validated provider email.
   - A seed run that marks an existing row verified also resets its password.
7. Microsoft personal accounts: an existing personal-account link, stored under the Graph `id`, either keeps working or gets a clear path back, not a bare 400.
8. Web and docs:
   - `/verify-email` doesn't show "Missing verification link." above the code form when there is no token.
   - The TC-04-001 release doc says the e2e spec mocks the API, and lists OIDC `preferred_username` as outside TC-04-001.
   - The real mailed-link flow is exercised end to end at least once: a real mail sink, the page, then the API.
9. Each item has release tests that fail without the fix.

## Evidence and sign-off

CI on both events, plus an independent review. Under OD-14 no separate owner sign-off is needed.
