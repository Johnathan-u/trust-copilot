# TC-21-006 Explainable compliance gaps and review workflow

**Status:** implemented. Framework catalogs stay **BLOCKED** pending **TC-01-007**. No framework requirement text was added.

Routes are mounted at `/api` plus the router prefix `/compliance/gaps`.

## States

Each applicable control is checked with the TC-21-003 evidence rules: approved, same workspace, not expired, and not tied to a deleted document. A count of linked files is not a pass.

The result is one of `gap`, `unknown`, `stale`, or `failed`. A control with qualifying evidence is clear and is omitted. Missing data and a check error are reported; they are not treated as no gap.

`reason` names the rule and the control and evidence ids. `next_step` carries `owner_user_id` from the control owner, `owner_missing` when that id is null, and an action code. There is no assignee column, so no owner is invented.

Blocked catalog frameworks are not applicable. Questionnaire gaps still count only `approved` and `manual` mappings. Versioned mapping precedence from TC-21-005 is not on this master.

`GET /compliance/gaps` does not persist. `POST /compliance/gaps/scan-and-notify` upserts `evidence_gaps` rows with `gap_type` `control_check`, then notifies. A failed notification leaves those rows in place and is reported. `Idempotency-Key` is optional.

## Permissions

No route permission changed.

## Migration

`tc21006_gap_evaluation` revises `bug018a_gap_closed_at_reason`. It adds nullable explainability columns on `evidence_gaps` and does not import the application package. Downgrade parks those values and upgrade restores them.

## Ambiguities

- `GET /compliance/gaps` does not write. It did not persist before this ticket either.
- `low_confidence_threshold` is still accepted and is not a pass.
- TC-21-005 is not on this master, so applicability does not read override, confirmation, or proposal rows.
- The control owner is `workspace_controls.owner_user_id`. There is no assignee column.
- No web module calls `/api/compliance/gaps`. The dashboard page calls `/api/compliance-coverage`.
- Notification delivery in tests is stubbed. The scan does not call Slack or email.
