# TC-02-007 — Run database, storage and browser tests in CI

**Epic:** E02 Toolchain and continuous integration
**Base:** `354166555acab43576a4e2261eaafbfa8f60cfc9`
**Evidence:** [`artifacts/acceptance/TC-02-007/`](../../../artifacts/acceptance/TC-02-007/README.md)

Children [TC-02-007b](TC-02-007b.md) and [TC-02-007c](TC-02-007c.md) stay as they were.
007b is the PostgreSQL TCP readiness repair. 007c is the session-cookie deadline
repair. Neither one completes this parent.

## Parent behaviour

The `build` job starts three real test dependencies and does not continue until
each one is ready:

* PostgreSQL 16 with pgvector, digest-pinned, on `127.0.0.1:5432`. The loop
  probes TCP with `pg_isready -h 127.0.0.1` at most 60 times, then a final probe
  must succeed before the database URL is exported (007b).
* An S3-compatible object store, [moto](https://github.com/getmoto/moto)
  (`motoserver/moto`, Apache-2.0), digest-pinned, on `127.0.0.1:9000`. Same
  60-attempt bound and a mandatory final HTTP probe, then the step creates
  `test-raw` and `test-exports`. MinIO is not used.
* Chromium, installed with the locked Playwright CLI (`playwright install
  --with-deps chromium`) in `build` before backend tests and again in
  `web-release-e2e` before the release specs. The install command blocks and
  fails the job if the browser is not installed.

Backend tests run with `TC_REQUIRE_DB=1`, `TC_REQUIRE_STORAGE=1`,
`TC_REQUIRE_WEB_TOOLCHAIN=1` and `TC_REQUIRE_API_QUALITY=1`.

* `TC_REQUIRE_DB=1` still turns an unavailable database, or a skip of an
  `integration` test, into a failure. It now also fails the session on a
  collection-time skip (`pytest.skip(..., allow_module_level=True)` or an
  equivalent import skip) unless that module is marked `provider`, `live_stack`
  or `external_data`. `tests/test_trust_scoring_blind.py` (`external_data`)
  remains the only such skip.
* `TC_REQUIRE_STORAGE=1` fails the session when the configured local S3
  endpoint does not answer `StorageClient.ping`, and turns a skip of a
  `storage`-marked test into a failure. The in-memory storage fakes used by
  other tests are unchanged.
* The web-release job no longer drops a missing candidate spec with
  "Skipping … (not on this revision)". A missing file fails the step. Every
  candidate, including `e2e/release/ui-23.spec.ts` (30 tests), is passed to
  the report checker with `--require-spec` and `--min-tests`.

`apps/api/tests/release/test_ci_integration.py` reads the workflow and runs
negative controls: a skipped integration test, an unmarked module-level skip,
a missing release spec, and a closed storage port. Each of those must fail
under the matching gate. A module marked `external_data` may still skip.

## Runbook

### Object store in CI

The service is only the `build` job's `Start isolated S3-compatible storage
(moto) for this run` step. It is not part of production compose.

1. The image is `motoserver/moto:5.2.5` pinned by the digest in `.github/workflows/ci.yml`.
   Moto is Apache-2.0. Do not replace it with MinIO or another AGPL/GPL store.
2. The container name is `tc-ci-s3`. The runner publishes `127.0.0.1:9000` to
   container port `5000`. Nothing else on the runner should bind that port.
3. Readiness is `curl` against `http://127.0.0.1:9000/moto-api/`: up to 60
   attempts, one second apart, each attempt limited to 5 seconds, then the same
   request once more. The second request is required. A failure there stops
   the job before credentials are exported.
4. The step generates `S3_ACCESS_KEY` and `S3_SECRET_KEY` with `openssl rand`,
   masks both, and creates `test-raw` and `test-exports` with those keys.
   It exports `TC_TEST_S3_ENDPOINT`, `TC_TEST_S3_ACCESS_KEY` and
   `TC_TEST_S3_SECRET_KEY` only after the buckets exist.
5. `apps/api/tests/conftest.py` copies those values into `S3_ENDPOINT`,
   `S3_ACCESS_KEY` and `S3_SECRET_KEY` when they are set. Without them, local
   runs still use `localhost:9000` and the synthetic dev pair. The endpoint
   host must be loopback or a compose service name.

`tests/release/test_ci_storage_roundtrip.py` uploads, downloads and deletes one
synthetic object through `StorageClient` in `test-raw`.

### Gates

| Flag | Where set | What fails |
|---|---|---|
| `TC_REQUIRE_DB=1` | Backend test step, and the Python lock step | Database setup failure; skip of an `integration` test; collection-time skip of a module that is not `provider`, `live_stack` or `external_data` |
| `TC_REQUIRE_STORAGE=1` | Backend test step | Object store does not answer `StorageClient.ping`; skip of a `storage` test |
| `TC_REQUIRE_WEB_TOOLCHAIN=1` | Backend test step | Web toolchain missing (unchanged) |
| `TC_REQUIRE_API_QUALITY=1` | Backend test step | ruff, mypy or the unit suite missing (unchanged) |

The release spec list is the `candidates` array in the `web-release-e2e` job.
Adding a spec means adding it to that array and passing `--require-spec` with
`--min-tests` set to that file's current case count. Removing the file, or
leaving it out of `--require-spec`, fails the job.

Focused check, from `apps/api`:

```bash
python -m pytest tests/release/test_ci_integration.py tests/release/test_ci_storage_roundtrip.py -q
```

The storage round-trip needs the disposable service (or any local S3-compatible
endpoint already named by `TC_TEST_S3_*`). The integration file's database
negative controls need the test Postgres when `TC_REQUIRE_DB=1` is set in that
child. The closed-port storage control and the spec-list control do not.

## Rollback

Revert this change. The moto container, its buckets and its generated
credentials exist only on the CI runner and are discarded with the job. No
migration, volume or other persisted state is added. Local MinIO in
`docker-compose.yml` is untouched. Production compose still has no bundled
object store.
