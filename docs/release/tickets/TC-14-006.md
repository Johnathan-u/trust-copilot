# TC-14-006 — Responsive navigation

## Behavior

The authenticated shell no longer reserves a sidebar column below 768px. At that width the same sidebar opens from the header as a dialog: focus moves inside, Tab wraps, Escape or Close dismisses it, and focus returns to Open navigation. The current route keeps `aria-current="page"`. Section toggles expose `aria-expanded`. Main content uses the full viewport width, and the page does not scroll horizontally.

From 768px upward the previous hierarchy stays: header across the top, docked sidebar on the left (200–240px, then 220–260px, then 280px), and a scrolling main region. The header and sidebar stay in view while main scrolls. A skip link targets `#main-content`.

Route labels live in `apps/web/lib/app-navigation.ts` and feed the sidebar, the wide primary links, the tablet jump list, and the command palette. Requests still require edit permission. Account Security stays on the account menu.

Dark remains the default theme. The shell uses `--tc-*` surfaces so the light theme does not put dark text on a hardcoded navy bar. No font file is requested at runtime.

## Ambiguities resolved

- The drawer breakpoint is Tailwind `md` (768px). 360px uses the drawer. 768px and 1440px keep the docked grid. A 1440px frame at 200% zoom is treated as a 720px CSS viewport, which reflows to the drawer instead of overflowing.
- Below 768px the old `<select>` jump list is hidden so the drawer is the only navigation. From 768px to 1023px the select remains beside the docked sidebar, matching the previous top bar.
- The header background is solid `--tc-surface-overlay`, and the shell background is solid `--tc-bg`, so light and dark text sit on token surfaces. The decorative body grid stays on public pages.
- Active matching requires a path boundary (`/dashboard/review` does not match `/dashboard/reviewer`). Home is exact.
- Dashboard card titles on the home page are `h2` under the page `h1`. The class string is unchanged. This clears the axe heading-order finding on the representative authenticated layout.
- Synthetic session cookie plus mocked `/api/auth/me` is how the browser tests pass the middleware. No customer data.
