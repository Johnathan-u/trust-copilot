## Problem

A public read still returns the live columns when `published` is 1 and there is no version. The seed scripts can insert those rows.

## Behaviour

A public read is an anonymous get, a get that names `workspace_id`, or a list with `published_only`.

Those reads require a `trust_article_versions` row at `trust_articles.published_version_id` while `published` is 1. `_load_version` in `apps/api/app/api/routes/trust_articles.py` returns that row. A null id, or an id that points at no row, is no version.

- `GET /api/trust-articles/{id}` is 404. The body does not include the live title, content, slug, category, or `is_policy`.
- A `published_only` list omits the article. It does not return the live columns.

The row stays stored. Nothing in the read calls `approve_current_draft`.

A signed-in get that omits `workspace_id`, and a list that is not `published_only`, still return the draft in `title`, `content`, `slug`, `category`, and `is_policy`. That is the editor view. It is not a public read. Members reading drafts stays TC-17-001i.

`scripts/seed_demo_workspace.py` and `scripts/seed_qa_test_data.py` publish a published article through `approve_current_draft`. The public trust centre can show that version. An unpublished QA seed stays a draft with no version. A QA re-seed of a published row that still has no version publishes it. A demo re-seed writes the seeded text and approves that draft.

No migration. Existing published rows that have no version stay stored. Public reads no longer serve them. A later administrator publish, or a re-seed, stores a version.

This does not change login, session checks, or permission dependencies. Create still defaults `published` to 1. The dashboard save of an already published article still sends `published: 1`. That publish-on-save behaviour is the parked owner question. It is not this change.

## Acceptance criteria

### AC1

A public read requires a published version. `GET /api/trust-articles/{id}` of a published article with no version row is 404. A `published_only` list omits that article.

### AC2

A published row with no version is not served as its live draft columns. A `published_version_id` that points at no row is treated the same way. An editor read that is not a public read still returns the draft.

### AC3

The behaviour is documented in this file. The demo and QA seeds publish a published article through `approve_current_draft`, so a seeded published article has a version the public read can serve.
