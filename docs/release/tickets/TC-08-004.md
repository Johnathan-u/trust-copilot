Keyword and semantic search drop chunks whose document is soft-deleted, not `indexed`, or indexed from a storage key the document has replaced. Soft delete tombstones those chunks and bumps the corpus version. The answer cache key includes the corpus version, the prompt version, and the model id. A stale hit returns `None`. Search applies the caller's existing permission flags.

## Behaviour

Line numbers were read at `445972c4d40e1b7fc2d88e35b7809f47823f7861`. That commit is the product code.

**Source state.** `eligible_chunk_query` keeps orphan chunks and chunks whose document is in this workspace, not soft-deleted, and `status` `indexed` (`apps/api/app/services/active_sources.py:29-52`). A chunk metadata key `retrieval_tombstone` drops the chunk. A `source_version` that is not the document's current storage key drops it. Keyword search uses that query (`apps/api/app/services/retrieval.py:268-273`). Semantic search uses the same predicates in SQL (`retrieval.py:354-367`). The fallback path uses the same query (`retrieval.py:399`). Results omit `source_version`, `retrieval_tombstone`, and `storage_key` (`retrieval.py:210-220`). Indexing records `source_version` as the storage key (`apps/api/app/services/index_service.py:127-130`). Chunks indexed before that field have no `source_version` and stay eligible until they are reindexed. Recording the key does not rewrite old rows. That would be a data migration and is not in this change.

**Soft delete.** `DELETE /api/documents/{document_id}` still sets `deleted_at`, then tombstones the document's chunks and bumps the corpus version (`apps/api/app/api/routes/documents.py:580-583`). Bulk delete does the same (`documents.py:541`, `:554`). Restore clears the tombstone and bumps again (`documents.py:661-663`). The chunk row stays, so restore can return the same chunk. `bump_corpus_version` is the helper the delete path already reaches through `invalidate_after_document_visibility_change` (`apps/api/app/services/retrieval_cache.py:113-124`).

**Answer cache key.** The hash is workspace, question, response style, evidence fingerprint, current corpus version, prompt version, model id, and permission fingerprint (`apps/api/app/services/answer_cache.py:38-61`). `get` reads the corpus version from the workspace and does not take a caller-supplied version (`answer_cache.py:81-90`). A different version, prompt, or model is a miss. Citations of an ineligible source are a miss (`answer_cache.py:106`, `active_sources.py:195`). The prompt version is `ANSWER_PROMPT_VERSION` (`apps/api/app/services/prompt_builder.py:9-12`). Generation passes the resolved model (`apps/api/app/services/answer_generation.py:984`, `:1330`). The default model id is `gpt-4o-mini`, the same value `resolve_model` returns when no model is named (`answer_cache.py:22-23`).

**Invalidation.** A successful index bumps the corpus version and deletes that workspace's retrieval rows and answer rows (`index_service.py:215-223`). The worker's best-effort bump does the same (`apps/api/app/worker.py:755-763`). Soft delete and restore use `invalidate_after_document_visibility_change`, which bumps and deletes both caches (`retrieval_cache.py:122-124`).

**Permission policy.** `policy_for_role` uses `get_builtin_permissions` and, for any other role name, the custom-role lookup routes already use (`apps/api/app/services/retrieval_permissions.py:19-68`). It does not add a role. Search with no policy still reads the workspace, which is how a generation job runs. A policy with neither `can_review` nor `can_admin`, and no document grant, returns no chunks (`retrieval.py:223-247`). A document grant is the only set returned, including when the other document is in the same workspace. `GET /api/search` passes the session role (`apps/api/app/api/routes/search.py:30-37`). The retrieval cache key includes the same fingerprint (`retrieval_cache.py:16-28`).

**Stale retrieval hit.** `retrieval_cache.get` still returns `None` when the stored corpus version is not the current one (`retrieval_cache.py:60-61`) and when the stored rows cite an ineligible source (`retrieval_cache.py:70-71`). `test_retrieval_cache_and_corpus_version` now requires `None` (`apps/api/tests/test_answer_pipeline.py:116`). An empty list is not a hit.

**Existing two-tenant fixture.** `test_concurrent_two_tenant_retrieval_isolated` creates documents that are retrieved. Those rows are now `status` `indexed` (`apps/api/tests/release/test_session_concurrency.py:65-70`) so the new source-state rule still returns them. The isolation assertions are unchanged.

**Model outcome comment.** An answer-cache hit stays `GROUNDED_UNVERIFIED` because claim-level citation checks are still TC-11-003 (`apps/api/app/services/model_outcomes.py:33-37`). The comment no longer says this ticket has not landed.
