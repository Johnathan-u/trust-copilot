## Problem

`POST /api/members/{id}/revoke-sessions` (`apps/api/app/api/routes/members.py`, handler at line 492, delete at lines 510-516) deletes `UserSession` rows filtered by `user_id` only. An admin of workspace A can sign that user out of every workspace, including ones the admin has no rights in.

## Acceptance criteria

1. Scope the revocation to the caller's workspace. Delete only sessions whose active workspace is the caller's, or invalidate access to this workspace only. A global sign-out stays a self-service or super-admin action.
2. A test with a user who is a member of A and B, where an A-admin revoke leaves the B session working and removes A access.
3. Document it in the ticket.
