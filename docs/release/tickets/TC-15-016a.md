# TC-15-016a — Documents list API contract

Child of [TC-15-016](TC-15-016.md). Registered from [issue #85 comment 6901076574](https://github.com/Johnathan-u/trust-copilot/issues/85#issuecomment-6901076574). The contract is the one in [PR #244 comment 6900976379](https://github.com/Johnathan-u/trust-copilot/pull/244#issuecomment-6900976379): server pagination and sort, row metadata, then the documents page consumes them. `ui-15` already runs in `web-release-e2e` from #249. This change does not edit the workflow.

The implementer does not accept the result.

## List

`GET /api/documents` still requires `require_can_review`. A workspace that is not the session workspace returns 403.

With no `page`, `page_size`, `sort`, or `order`, the body stays a JSON array of every match, ordered by `created_at` descending and then `id` descending. Search, filters, and the archive mode are unchanged. Callers that read an array keep working.

When any of those four parameters is present, the body is one page:

| Field | Meaning |
| --- | --- |
| `items` | The page of rows |
| `total` | Filtered count, not the page length |
| `page` | Default 1. Values below 1 are rejected with 422 |
| `page_size` | Default 25. Allowed range 1–100. Outside that range is 422 |
| `sort` | `created_at` (default), `filename`, `status`, or `id`. Anything else is 400 |
| `order` | `desc` (default) or `asc`. Anything else is 400 |
| `max_upload_bytes` | `Settings.max_upload_bytes`. The default is 52428800 |

The secondary order is `id` in the same direction, except when `sort` is `id`.

## Row fields

These fields are on every row, including the legacy array.

| Field | Value |
| --- | --- |
| `source_eligibility` | `eligible` when `deleted_at` is null, which is the citable-document rule in `document_is_citable`. `ineligible` when the row is archived |
| `freshness` | `fresh`, `warning`, or `stale` from the workspace document freshness policy applied to `created_at`. The default policy is 180 days, with a warning 30 days before that. Null when `created_at` is null |
| `version` | Decimal string of the highest `evidence_versions.version_number` for an evidence item in this workspace whose `document_id` is the row. Null when there is none. Another workspace's version is ignored |
| `index_job_id`, `index_job_status` | Newest `index_document` job in this workspace whose payload `document_id` is a positive integer for this row. A bool, a string, or other malformed JSON does not match. An unknown status is null. The payload, storage key, and jobs from another workspace are not returned |
| `source_preview_url` | `/api/documents/{id}/content?workspace_id={workspace}` when the storage key is present and does not escape the bucket. Null otherwise |

## Preview

`GET /api/documents/{id}/content?workspace_id=` uses `require_can_review` and the same workspace check as the list. A document outside the workspace, or one with no storage key, is 404. The bytes come from the raw bucket. The response media type is chosen from the filename extension, not from the stored content type. PDF is `inline`. The other allow-listed extensions are `attachment`. The response sets `X-Content-Type-Options: nosniff` and `Cache-Control: private, no-store`. A missing object is 404 `Document file not found`. The storage key is not in the URL or the error body.

There is no separate reindex route. Retry stays `POST /api/jobs/{id}/retry`, which still requires an administrator.

## Page

`/dashboard/documents` sends `page`, `page_size=25`, `sort`, and `order`. The sort control offers newest, oldest, filename in both directions, and status. Previous and Next appear when `total` is greater than 25. Changing the workspace, a filter, the sort, or the page clears the selection. The size line uses `max_upload_bytes`. 52428800 is shown as `Size limit: 50 MB.` A missing limit is `Size limit: not reported.`

When a row includes `index_job_id` and `index_job_status`, retry and the job link use that job. Otherwise the page still reads the newest jobs page.

## What this does not change

No migration or backfill. Upload authorization, job retry authorization, and the legacy unpaged array are unchanged. `docs/planning/backlog-state.json` and `docs/tracker/` are unchanged. Questionnaires stay on TC-15-017b.
