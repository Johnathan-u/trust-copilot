## Ambiguities

1. The sample is neither a measurement of the workspace nor an estimate of one. It is `basis: not_measured` with `measured: false` and `estimated: false`. Calling it `estimated` would publish a quotable figure. Real counts use `basis: measured`. This ticket emits no estimated number, because there is no reviewed estimation method.
2. `origin: real` means the row is stored in the caller's workspace. It does not mean a customer, a sale, or attested usage. `commercial_traction` is false for those rows too.
3. Test rows inserted by `tests/release/test_domain_demo_proof.py` are labeled "SYNTHETIC TEST PLACEHOLDER" in filenames and titles so a person reading the database can see they are fixtures. The product does not sniff filenames. It counts them as stored records. There is no provenance column on questionnaires, documents or evidence.
4. Naive `created_at` values already stored by older models are read as UTC. That is an assumption about existing columns, not a new measurement.
5. The default window is the span of included rows, not a calendar month. Named time zones are rejected. Only ISO-8601 offsets are accepted, and they are stored as UTC. Storage and reporting stay in UTC. That is an engineering call. A display time zone can come later and is not part of this ticket.
6. Retry recomputes from current rows and returns the existing snapshot when the hash matches. If a failed source recovers, the next request stores a new snapshot. A stale failure is not replayed forever.
7. No `Job` row is created. Generation is synchronous. Idempotency is the unique `(workspace_id, idempotency_key)`. This does not claim exactly-once job execution.
8. `RequestPrincipal` is not a new type. The route uses the existing session or API key and rechecks current membership. API keys have a null `user_id`. A key may read this summary only when `api_keys.role` is `read`, and only for its own workspace. Editor, reviewer, admin and unknown roles are `api_key_not_read_scoped`. Human admin, editor and reviewer sessions are unchanged. The members API still does not mint a `read` key. The first user to materialize a snapshot is `created_by_user_id`; a later retry does not change that. A read key has a null user id, so `created_by_user_id` stays null for a snapshot that key materializes.
9. Existing 401 responses and the suspended-member 403 keep `{"detail": ...}`. New denials and the invalid window use `code`, `message`, `request_id`, `retryable` and optional `field_errors`. A non-integer `workspace_id` still gets FastAPI's 422.
10. TC-01-005 (PR #2, branch `tc/coord/TC-01-005`) also edits `demo_proof_service.py` and is not merged here. This branch adds the same idea (`data_basis: synthetic_example` and a disclaimer) plus the proof summary. Sample answer text is the master text, including the sentence about isolation tests that PR #2 deletes. That sentence sits inside the synthetic placeholder.
11. `live_stats.questions_answered` still counts questions, with an explicit note, so the legacy key stays compatible.
12. `GET /api/demo-proof` writes a snapshot. The write is limited to the caller's workspace and does not grant rights. It exists so a restart has a stored outcome.
13. Database foreign keys on evidence and exports use `ON DELETE SET NULL` or a plain id reference. A deleted parent row often becomes NULL rather than a dangling id, so the tested foreign-reference cases are other-workspace and soft-deleted targets. The missing-target branch is still in the service for a row `Session.get` cannot find.
14. Rollback drops snapshots on purpose. The next read builds a new summary from current rows. It does not restore the deleted snapshot and it does not backfill history.
15. The walkthrough and the synthetic gap recommendation were reworded so they are not buyer-facing proof. The five steps and the legacy response keys remain.

## Coordinator rulings

1. A workspace count is never shown as commercial usage. `commercial_traction` stays false. A consented source would come only from the owner's pending case-study consent decision. That source is not connected here.
2. The legacy sample endpoints stay. Deprecation is follow-up ticket TC-25-011a, logged here and in `docs/release/tickets/TC-25-011.md`. This change does not remove `GET /api/demo-proof/questionnaire`, `/coverage`, `/gaps` or `/walkthrough`.
3. Storage and reporting stay in UTC. That is an engineering call. A display time zone can come later.
4. Cross-workspace foreign keys are report-only. There is no backfill. See `docs/release/bugs/TC-06-BUG-001.md`.
5. A workspace API key may read the summary only if the key is read-scoped (`api_keys.role` = `read`) and only for its own workspace. A non-read-scoped key is `api_key_not_read_scoped`. A key that presents another workspace's id is `workspace_mismatch`.
