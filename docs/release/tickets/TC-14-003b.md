# TC-14-003b: remaining notification gaps and live-region tests

Follow-up of TC-14-003. It was raised by the independent reviews of #190: changes were requested at `92b0c3e`, and the review at `15058e7` approved with follow-ups. These items were left as non-blocking.
Epic E14. 2 points, P2. Depends on TC-14-003. Branch: `tc/TC-14-003b-notification-gaps`.

## Why

TC-14-003 fixed the dialogs and the notification paths that are visible on the main dashboard pages. Some older messages are still silent, never shown, or announced late.

## Acceptance criteria

1. Every error set in these places is shown and announced with `role="alert"` and the `--tc-danger` token:
   - MFA setup failure (`security/page.tsx`);
   - Gmail quick-add label failure (`gmail/page.tsx`);
   - Slack and Gmail disconnect/remove calls, which must check `res.ok`;
   - `sendTest` and `runIngest` network rejections, which need a `catch`;
   - billing portal and checkout (`settings/page.tsx`);
   - the demo-proof error, which must use the danger token.
2. These `role="status"` regions are mounted before their text changes, so the change is announced:
   - `jobs`, `deals`, `controls`, `controls/[id]`, `security-page`;
   - the Slack result regions across tab switches.
   Topbar "Saved" gets an always-mounted `role="status"`. It has no live region today.
3. Playwright tests cover at least these live regions:
   - Slack test result;
   - Slack and Gmail ingest results;
   - questionnaire and demo-proof "Saved";
   - security-page password and policy status.
   Each test asserts the role and that the message stays until the user acts.

## Evidence and sign-off

CI on both events, plus an independent review. Under OD-14 no separate owner sign-off is needed.
