# TC-14-003a — Persistent toast live region and destructive confirm errors

Follow-up to TC-14-003. No schema change. Rollback is reverting this change.

## Behavior

One `role="status"` region (`aria-live="polite"`) and one `role="alert"` region (`aria-live="assertive"`) are mounted in the root layout before any toast exists. Both start empty. A toast does not create its own live region. Its card is inserted into the region that matches its severity: success, info and warning go to the polite region, and errors go to the assertive region. Removing the toast removes that text from the region.

Timing is unchanged. Success, info and warning without an action leave after 4000ms. A toast with an action button does not auto-dismiss. Errors stay until dismissed. Toasts still do not take focus. `prefers-reduced-motion: reduce` still drops the toast opacity transition.

`useDestructiveConfirm` awaits `onConfirm`. A rejection is formatted with `apiErrorAnnouncement`. A thrown TC-11-001 object (`code`, `message`, optional `request_id`) uses the same message rule as the review page's `apiErrorMessage`, including the short request id. The dialog then closes, `busy` is cleared, and focus returns to the control that opened it. The error toast is the assertive, sticky toast. The dialog is not left open behind a disabled confirm button, because that would keep the toast under `inert`.
