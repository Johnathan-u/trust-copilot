# TC-15-049a — Local deal list, create and edit

Status: implemented locally; independent review and exact-head CI qualification pending.
Estimate: 5 points. Parent TC-15-049 remains open.

Authorized scope: [issue #85, comment 6513665053](https://github.com/Johnathan-u/trust-copilot/issues/85#issuecomment-6513665053).
Implementation starts at `91db7baf9ae252b2fb11688aae92c663318cb0c6`, preserving the merged #96 typed local deal contract.

The new `/dashboard/deals` page lists current-session deals and offers create/edit when the current auth context grants `can_admin`. It consumes the existing `/api/deals` GET/POST and `/api/deals/{id}` PATCH methods. Read access does not invent a `can_review` requirement, and write access does not assume owner/viewer role migrations. Backend authorization remains authoritative.

Money remains a decimal string throughout input, requests and display. Currency starts blank and must be supplied explicitly when creating or replacing an amount. No floating-point conversion, default currency, totals, exchange rates or currency catalogue is introduced. Existing amounts with unknown currency remain visible as unknown and can retain their original value during unrelated edits. Typed stages and expected/actual date fields use the existing schema. PATCH ignores null values, so the form explicitly rejects attempts to clear saved money, currency or dates instead of claiming those edits succeeded.

Only a complete, valid, current-workspace list can become the ready or empty state. Malformed, duplicate and foreign-workspace records fail the whole list. A mutation remains pending until the server returns a valid matching typed record; acknowledgment closes the form and reloads authoritative data. A failed reload after a successful mutation has its own message. Failed/uncertain saves retain input and use the same idempotency key for the same operation and payload; changed payloads use a new key. A synchronous guard prevents duplicate submissions. Unsaved modal dismissal requires discard confirmation, and document unload prompts while a draft is dirty. Workspace, user or administrative-permission changes unmount the draft, abort owned work, and prevent old results from appearing in the new context.

The existing deal consumer received only contract checks needed by this page: positive safe integer IDs, real calendar dates and the individual deal's numeric(18,2) range. Analytics aggregation parsing remains unchanged; null currency remains valid on legacy responses.

Verification and limits are recorded in [the evidence README](../../../artifacts/acceptance/TC-15-049a/README.md). No backend/schema/dependency/shared-UI changes, CRM sync/provider work, linked questionnaire/risk workflows, or parent completion are included. TC-20-050, TC-20-053, the full linked workflow and remaining TC-15-049 gates remain open. This child does not supply real-provider qualification.
