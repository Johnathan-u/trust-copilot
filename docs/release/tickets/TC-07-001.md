## Behaviour changes

* **Production** refuses to start with empty, <32-char, low-variety or placeholder `SESSION_SECRET`; MFA, Slack, credential-store and OAuth-state crypto fail closed the same way.
* **Non-production** without `SESSION_SECRET` uses a random per-process key (warning logged): sessions reset on restart; locally encrypted MFA/connector data from the old dev default needs the old key set in `.env` or re-enrolment.
* `S3_ACCESS_KEY` / `S3_SECRET_KEY` are required (no ambient boto3 credential fallback).
* `docker-compose.prod.yml` needs `.env.production` with `DATABASE_URL`, `POSTGRES_USER`, `POSTGRES_PASSWORD`, `MINIO_ROOT_USER`, `MINIO_ROOT_PASSWORD`; `deploy.sh` refuses to run without it.
* `docker-compose.yml` dev credentials are now `${VAR:-dev-default}`: if your `.env` sets a different `POSTGRES_PASSWORD` than the volume was initialised with, DATABASE_URL will now follow `.env`.
* Seed scripts: passwords from `TC_SEED_{DEMO,ADMIN,EDITOR,REVIEWER,SUSPENDED}_PASSWORD` or generated and written to `apps/api/.seed-credentials.local` (0600, gitignored); `TC_SEED_RESET_PASSWORDS=1` resets existing seeded users; seeding refuses `APP_ENV=production` (TC-03-001 removed the former `TC_ALLOW_PRODUCTION_SEED` override). `scripts/e2e-run.js` generates these automatically.
* `/login` one-click demo only when `NEXT_PUBLIC_DEMO_LOGIN_EMAIL` and `NEXT_PUBLIC_DEMO_LOGIN_PASSWORD` are set at build time; otherwise the link is hidden and the demo route shows "not enabled". Marketing pages still link to `/login?demo=true`.
* Logs: `SecretRedactionFilter` on root handlers + JSON formatter redact `tc_session` cookies, bearer/basic tokens, URL credentials, presigned S3 signature params, `password=`/`token=` pairs and secret-named structured fields.
* Live API scripts (`apps/api/tests/test_*_api.py`, `fetch_*.py`, `run_*dataset_test.py`) are manual tools: not collected by pytest; need `TC_API` and `TC_SESSION_SECRET` (local stacks only).
