## AC1 — scanning (current source, reachable history, release artifacts)

`scripts/security/secret_inventory.py` (stdlib only) reports **locations, rule and kind only — never values**.

```
python scripts/security/secret_inventory.py tree              # working tree (exit 1 on any block finding)
python scripts/security/secret_inventory.py history --fail-on never   # every blob reachable from any ref
python scripts/security/secret_inventory.py paths artifacts apps/web/test-results   # release artifacts
python scripts/security/secret_inventory.py all --json out.json
```

* Rules: PEM private keys, AWS/OpenAI/Stripe/GitHub/Slack/Google key formats, JWTs, signed `tc_session` cookies,
  HMAC with literal key, high-entropy literals for secret-named variables, literal env defaults for secret
  names, credentials embedded in URLs, secret-named values in compose/env/shell/PowerShell/Docker files.
  Low-entropy dev defaults are reported as `review`, not `block`.
* Zip archives and Playwright `trace.zip` files are scanned in memory (recursively).
* Regression gate: `apps/api/tests/release/test_secret_inventory.py` fails if any block finding returns to the tree.
* URL schemes are matched case-insensitively; findings are de-duplicated per match span (two URLs on one
  line are two findings, so a downgraded match never hides a blocking one).
* Downgrades (block → `review`, never dropped; each carries a `reason` in the JSON and text output). Both
  apply **only** to the URL-credential rule (`url-embedded-credential`); token formats (AWS, OpenAI, Stripe,
  GitHub, PEM, …) and every other block rule are never downgraded:
  * URL credential whose host is, or is a subdomain of, an RFC 2606/6761 reserved name: `invalid`,
    `example`, `test`, `localhost`, `example.com`, `example.net`, `example.org`. The host taken from the text
    right after the matched `@` must be a plain DNS name and equal the hostname `urllib.parse` derives; an
    authority with more than one `@` or a backslash always blocks. Look-alikes (`example.com.evil.io`,
    `notexample.com`, `test.attacker.com`, a reserved name only in the userinfo/path/query) still block.
  * A Python line whose `# secret-inventory: synthetic` marker is a real comment token (`tokenize`; never
    text inside a string literal), honoured only when a directory component of the path is
    `test`/`tests`/`__tests__`/`e2e`/`fixture`/`fixtures`/`__fixtures__`, and never in application code
    (`apps/api/app/`, `apps/api/alembic/`, `apps/web/{app,components,contexts,lib}/`, `apps/web/middleware.ts`),
    config files (env/yml/toml/…, `*.config.*`, `*.json`, `*.example`), deploy/CI paths (`deploy/`, `infra/`,
    `.github/`, `docker-compose*`, `Dockerfile*`), `.tf`/`.tfvars`/`Makefile`/`.sh`/`.bash`/`.zsh`/`.sql`/`*.env*`
    files, or archive members.

## Behaviour changes

* **Production** API (`app.main`) and worker (`app.worker`) both refuse to start with empty, <32-char, low-variety or placeholder `SESSION_SECRET` (shared `enforce_production_session_secret`); MFA, Slack, credential-store and OAuth-state crypto fail closed the same way. `docker-compose.prod.yml` sets `APP_ENV: production` on api and worker and requires `SESSION_SECRET` with `${SESSION_SECRET:?…}`.
* **Non-production** without `SESSION_SECRET` uses a random per-process key (warning logged): sessions reset on restart; locally encrypted MFA/connector data from the old dev default needs the old key set in `.env` or re-enrolment.
* `S3_ACCESS_KEY` / `S3_SECRET_KEY` are required (no ambient boto3 credential fallback).
* `docker-compose.prod.yml` needs `.env.production` with `SESSION_SECRET`, `DATABASE_URL`, `POSTGRES_USER`, `POSTGRES_PASSWORD`, `MINIO_ROOT_USER`, `MINIO_ROOT_PASSWORD`; `deploy.sh` refuses to run without it.
* `docker-compose.yml` dev credentials are now `${VAR:-dev-default}`: if your `.env` sets a different `POSTGRES_PASSWORD` than the volume was initialised with, DATABASE_URL will now follow `.env`.
* Seed scripts: passwords from `TC_SEED_{DEMO,ADMIN,EDITOR,REVIEWER,SUSPENDED}_PASSWORD` or generated and written to `apps/api/.seed-credentials.local` (0600, gitignored); `TC_SEED_RESET_PASSWORDS=1` resets existing seeded users; seeding refuses `APP_ENV=production` unless `TC_ALLOW_PRODUCTION_SEED=1`. `scripts/e2e-run.js` generates these automatically.
* `/login` one-click demo only when `NEXT_PUBLIC_DEMO_LOGIN_EMAIL` and `NEXT_PUBLIC_DEMO_LOGIN_PASSWORD` are set at build time; otherwise the link is hidden and the demo route shows "not enabled". Marketing pages still link to `/login?demo=true`.
* Logs: `SecretRedactionFilter` on root handlers + JSON formatter redact `tc_session` cookies, bearer/basic tokens, URL credentials, presigned S3 signature params, `password=`/`token=` pairs and secret-named structured fields.
* Live API scripts (`apps/api/tests/test_*_api.py`, `fetch_*.py`, `run_*dataset_test.py`) are manual tools: not collected by pytest; need `TC_API` and `TC_SESSION_SECRET` (local stacks only).
