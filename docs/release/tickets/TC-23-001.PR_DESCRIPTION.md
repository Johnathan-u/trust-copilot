# TC-23-001: Typed scoped deals, rooms, and questionnaire links

Typed deals preserve exact decimal amounts and tenant-scoped references. The review repair makes mutation and idempotency-response publication atomic, preserves all typed values through rollback/re-upgrade, permits explicitly unknown legacy currencies in the web consumer, and makes mixed/unknown-currency totals unavailable instead of adding incompatible amounts.

Original implementation commits remain intact. Repair baseline is `a392f9358fc5f782150d3e262c8d7009fe9641cd`; [assignment](https://github.com/Johnathan-u/trust-copilot/issues/85#issuecomment-6512133723) and [review findings](https://github.com/Johnathan-u/trust-copilot/pull/96#issuecomment-6511935044). No route permissions, dependencies, conversion policy, or provider behavior changed.

## Migration

`tc23001_deal_types` still revises the original branch parent `tc10001_job_leases`. Re-parent separately on the actual landed head after the reserved PR #93 migration. The heads test accepts this revision or any descendant and does not pin the parent id.

A finite legacy float becomes `numeric(18,2)` only when it is in range and exactly the float8 image of its rounded value. Other values remain recoverable in `tc23001_deal_amount_hold`, with the active amount null. Downgrade restores held floats only for unchanged null rows; corrected values win.

Before downgrade removes columns or converts decimals, it locks deals and records exact typed values in `tc23001_deal_state_archive`. Re-upgrade matches row/workspace/creation identity and unchanged projections to restore the exact amount and dates. Older-version edits win. Current ownership, deletion state, and list shape gate reference restoration. Fully restored snapshots are removed; conflicts and invalid/unmatched rows retain their exact snapshots and `restore_issue`. Both recovery tables deliberately survive rollback.

Initial rows and new older-version rows retain the existing backfill: expected date derives from close_date, and unknown currency/actual date/room/documents are not invented.

## Ambiguities resolved conservatively

- No dashboard page called `/api/deals`, so no page import changed. `apps/web/lib/dealConsumer.ts` and its vitest are the web side of the response.
- Currency is the three-letter shape, not a downloaded ISO table.
- Mock CRM sync still stores integer example amounts and does not invent a currency.
- `avg_close_days` stays a day count computed from stored timestamps.
- `win_rate` is null with no closed deals. Empty revenue sums remain `0.00`. Mixed/unknown-currency sums are null with additive currency/unavailable-reason metadata; no conversion is attempted.
- `deal_value_arr` keeps its name. The JSON value is a two-decimal string. `schema_version` is `deals/v1`.
- Idempotency keys are `ws:{workspace}:deals:{action}:{deal id or new}:{raw}`. The owner-fenced response and mutation commit together.
