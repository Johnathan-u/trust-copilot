## Migration

`tc23001_deal_types` revises `tc10001_job_leases`. That is the single alembic head on master. Re-parent by changing that one `down_revision` assignment. The heads test accepts this revision or any descendant and does not pin the parent id.

A stored float is kept only when it is exactly the float8 image of `round(value, 2)`. Those values become `numeric(18,2)`. Any other non-null amount is copied to `tc23001_deal_amount_hold` as its original text with the reason `float value is not exactly representable as numeric(18,2)`, and the deal amount is set null. Nothing is rounded into a different value. Downgrade restores that text exactly. Re-upgrade holds the same text again.

Nothing is invented for old rows. `expected_close_date` is the date part of the existing `close_date`. Currency, actual close, document ids, and room id start null. Downgrade drops those columns. Re-upgrade does not fill them back in.

This migration's slot is after the #85 queue (#73, TC-18-002, TC-07-002, TC-18-001, TC-17-004). Expect a re-parent before merge.

## Ambiguities resolved conservatively

- No dashboard page called `/api/deals`, so no page import changed. `apps/web/lib/dealConsumer.ts` and its vitest are the web side of the response.
- Currency is the three-letter shape, not a downloaded ISO table.
- Mock CRM sync still stores integer example amounts and does not invent a currency.
- `avg_close_days` stays a day count computed from stored timestamps.
- `win_rate` is null when the workspace has no closed-won and no closed-lost deal. Empty revenue sums are `0.00`, the sum of no stored amounts.
- `deal_value_arr` keeps its name. The JSON value is a two-decimal string. `schema_version` is `deals/v1`.
- Idempotency keys are `ws:{workspace}:deals:{action}:{deal id or new}:{raw}` and the claim records an owner token.
