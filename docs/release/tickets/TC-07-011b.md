## Behaviour

This child adds the named test and the parent release note. It does not change upload, classification, authentication, Sentry, or logging. TC-07-011a remains that behaviour.

`apps/api/tests/release/test_log_redaction.py` sends a synthetic filename, reset link, cookie, and source sentence through the records a support engineer would read:

- The four `upload_rejected` warnings from `FileService.upload_raw` and `FileService.upload_trust_request_attachment` (size and extension, for a raw upload and a trust-request attachment). The caller still receives the sanitized filename. The object key does not contain the canary. The HTTP error detail does not contain it.
- `parse_classification_response` and `classify_question_with_llm` when the model text is not JSON and the call raises.
- `_deliver_password_reset` when the mailer rejects the message and when the mailer raises. The mailer is given the reset URL. The warning records leave that URL out.
- One application log line that contains a `tc_session` cookie and a `/reset-password?token=` link, with `job_id` on the record, formatted by `JsonFormatter`. `redact` is applied to the same line. The raw message is the input to redaction. The check reads the formatted line, which is what production emits.
- `log_job_start`, so a pipeline line still carries `job_id`.
- `scrub_sentry_event` on an event that carries the four canaries plus `request_id` and `job_id`. `apps/api/app/main.py` must call that helper from `before_send`.

`request_id` is set in the logging context for the run. The formatted upload warnings, the formatted application line, and the Sentry event must still contain it. `job_id` must still be on the formatted application line, the pipeline line, and the Sentry event. An upload rejection does not invent a `job_id`. The id is required on the records that have one.

The test fails if any canary is present in those records. It fails if `request_id` or `job_id` is missing from the records named above. The canaries are fixed synthetic strings.

`docs/release/tickets/TC-07-011.md` records the same behaviour for support: what stays out of application logs and Sentry, and which ids remain.
