## Problem

## Behaviour

`_same_bytes` (`apps/api/app/worker.py:470`) compares the multiset of `content_hash` and the single `original_file_hash`. The same bytes reconcile and do not insert or delete. A different file is rewritten once by `_replace_questions` (`worker.py:529`). A question that is still in the file keeps its id, so an approved answer stays. A dropped question is deleted only when it has no approved answer, and its draft is deleted with it. A dropped question that is approved is kept and marked `source_location` `not_in_current_file` (`worker.py:568`, constant at `apps/api/app/services/cell_mapping.py:38`). `mapping_version` stays non-negative because `ck_questions_mapping_version_nonneg` forbids `-1` without a migration. Export skips that marker (`export_service.py:232`, `xlsx_writer.py:182`), so the old file hash does not make the workbook stale and the row is not written by the legacy column offset. The review page shows the question and the approved answer with the label `Not in the current file.` (`apps/web/app/dashboard/questionnaires/[id]/page.tsx:33`).

A job whose storage key is no longer the questionnaire's key is `superseded` with reason `input_version_changed` (`worker.py:428`). `GET /api/jobs` exposes `input_version_changed` and `questionnaire_status` (`apps/api/app/api/routes/jobs.py:134-135`). The jobs page prints that flag with the status (`apps/web/app/dashboard/jobs/page.tsx:120`). A parse of the current bytes leaves the flag false.

Two deliveries of the same job take the questionnaire row lock and re-read the questions effect (`worker.py:628`) before inserting. No migration was added.

The runbook is `docs/ops/questionnaire-replay.md`. The parent note is `docs/release/tickets/TC-09-006.md`.
