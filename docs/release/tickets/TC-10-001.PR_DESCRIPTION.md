# TC-10-001: Periodic leases and abandoned-job recovery

A running job now has an owner token and an expiry. The worker that claimed it renews the lease while the job runs. A second worker cannot take a live lease. If the owner is killed, the lease expires and the job goes back through the existing retry classifier, backoff, and attempt cap. A worker that has lost the lease does not commit its result. Side effects that already committed stay behind the TC-10-003 ledger, so the next attempt does not apply them again.

Local branch `tc/core/TC-10-001` off master `6a26d60`. Not pushed. The acceptance README records the commit the tests ran on.

## What master did

`jobs` had no lease columns. `worker_heartbeat` is a process liveness row (TC-03-003), not a per-job owner. `claim_job` locks a queued row, sets `running`, increments `attempt`, and commits. After that, a dead worker leaves the job `running`. Nothing retries it. TC-10-002 and TC-10-003 already make a later attempt safe; they never saw this job.

## Design

* Claim stays `SELECT ... FOR UPDATE SKIP LOCKED`, and the same update stores `lease_owner` (`secrets.token_hex(16)`, same construction as the TC-10-003b idempotency token) and `lease_expires_at`.
* Heartbeat renewal is `UPDATE ... WHERE lease_owner = :owner AND status = 'running' AND lease_expires_at > :now RETURNING id`.
* The job session's commit locks the row first. If the token no longer holds a live lease, the commit is rolled back. The owner audits `job.lease_lost` and does not write `completed` or its own retry.
* Recovery selects expired running leases with `FOR UPDATE SKIP LOCKED` and calls `_handle_job_failure` with retryable `lease_expired`. Attempt count, backoff, exhaustion, and the idempotency ledger are the ones that already exist. Recovery also writes `job.abandoned`. The audit stores an 8-character prefix of the previous token.
* A NULL `lease_expires_at` is not recovered.

## Migration

`tc10001_job_leases` (18 characters, under the `alembic_version.version_num` limit of 32). This migration does not widen that column. Parent at implementation: `tc21005_mapping_version`. Re-parent onto master's head at push time if it has moved. Additive nullable columns and one partial index. Downgrade drops only those. Upgrade, downgrade, upgrade keeps every other jobs column; the lease columns come back NULL.

## Configuration

`JOB_LEASE_SECONDS` default 60, clamped to 10–3600. `JOB_LEASE_HEARTBEAT_SECONDS` default 15, clamped to 1–1200 and forced below the lease. Documented in `docs/release/tickets/TC-10-001.md`, `docs/release/config-contract.md`, `.env.example`, and `docker-compose.prod.yml`.

## Open questions

* A running job with a NULL lease is not reclaimed. That is deliberate: jobs already running at deploy time belong to a worker that does not know about leases. Reclaiming them could run the attempt twice beside a worker that is still going. An operator can fail those by hand.
* An abandoned attempt uses the existing jittered backoff and the existing attempt cap. It is not restarted at once. A poison job therefore cannot hot-loop. With the defaults, a killed worker's job waits out the backoff before the next claim. The release test sets the backoff to 0 so the second worker can claim as soon as the schedule says it may.
* The fence stops a commit after the lease is lost. A side effect that committed while the lease was still valid stays committed. The TC-10-003 ledger makes the retry skip that effect. Work that was only in memory is discarded. There is no signal that interrupts a handler between commits; the next commit is the stop.
* If `JOB_LEASE_HEARTBEAT_SECONDS` is greater than or equal to the lease, it is replaced with `(lease - 1) // 3` so a renewal can land before expiry. The configured number is not used as-is in that case.
* TC-03-005 and TC-06-006 are not merged. This branch does not contain them and does not depend on their code. It is based on master `6a26d60`.
* The migration parent is `tc21005_mapping_version` because that was the single alembic head. It will be re-parented at push time if master has moved. The revision id stays `tc10001_job_leases`. `alembic_version.version_num` stays varchar(32).
