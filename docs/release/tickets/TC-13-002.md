# TC-13-002: preserve the supported workbook structure

Status: implementation on branch `tc/TC-13-002-workbook-fidelity`. Evidence is in
`artifacts/acceptance/TC-13-002/`. Reviewer signoff is still pending; this note
does not accept the ticket.

Dependencies TC-09-002, TC-12-003 and TC-08-006 are not accepted. Placement is
still the question column plus `EXPORT_ANSWER_COL_OFFSET` (default: the next
column). Explicit answer targets remain TC-13-001. This ticket covers what else
in the workbook survives that write, and what is rejected instead of being
silently rewritten.

The tests live in `apps/api/tests/release/test_export_fidelity.py`. Run them
from `apps/api` with `python -m pytest tests/release/test_export_fidelity.py -q`.
Existing `pytest -rs` already collects `tests/release/`, so no workflow change
is required.

## Supported subset

These parts are kept. The fidelity test compares a normalized view of the
OOXML package before and after `create_export_from_questionnaire`. Answer
cells are removed from the sheet comparison because the export is supposed to
write them.

| Part | What is compared |
|---|---|
| Styles | `styles.xml`, resolved per non-answer cell (font name/size/bold/italic/colour, fill, border, alignment, number format). Style indexes are not compared; openpyxl renumbers them. |
| Formulas outside answer cells | Formula text on every sheet, including array formulas. Cached formula results are not compared. |
| Defined names | Name, hidden flag, and target, from `workbook.xml` `definedNames`. |
| Data validation | Type, range, and list formula. Default attributes openpyxl adds (`allowBlank` `1` versus `true`, empty `formula2`) are normalized away. |
| Hidden and very-hidden sheets | `workbook.xml` sheet `state` (`hidden` and `veryHidden`). |
| Images | `xl/media` bytes, plus the drawing anchor (picture, from/to column and row). openpyxl writes pictures only when Pillow is installed. Pillow is not in the runtime lock (no new dependency). After save, picture anchors and media bytes that were dropped are copied back from the original package. |
| Charts | Chart type, title text, and series formula references, plus the drawing anchor. Chart XML itself is rewritten. |
| Merged cells | `mergeCells` references. |

Two fixtures cover that subset:

- An openpyxl-built workbook, created in the test, including a very-hidden
  sheet and an array formula.
- A LibreOffice-authored file checked in at
  `apps/api/tests/fixtures/questionnaires/libreoffice_supported_subset.xlsx`.
  It was produced by LibreOffice 24.2.7.2 headless, not saved by openpyxl:

  ```bash
  soffice --headless --norestore --convert-to xlsx --outdir OUT SEED.xlsx
  ```

  `docProps/app.xml` records `Application` `LibreOffice/24.2.7.2`. The seed
  passed to LibreOffice was built in memory so the conversion would contain
  the supported parts; the bytes under test are the LibreOffice save.
  LibreOffice writes a very-hidden sheet as `hidden`, so very-hidden state is
  asserted on the openpyxl-built fixture. The LibreOffice fixture still
  asserts the hidden sheet LibreOffice actually wrote.

## Unsupported structure

`xlsx_writer.reject_unsupported_workbook` runs at the start of
`create_export_from_questionnaire`. `worker.run_export` lets
`UnsupportedWorkbookStructure` propagate. The job is classified as terminal
`bad_input` with that message. The message names the feature and does not
include part paths, XML, or exception text from the file.

The preflight fails the export when it finds any of:

- macros (`vbaProject`, macro-enabled workbook content type)
- shapes (DrawingML `sp` / `cxnSp` / `grpSp` / `wsp`, non-note VML, header or
  footer drawings)
- form controls (`xl/ctrlProps`, ActiveX, worksheet `controls`, VML buttons
  and the other control object types)
- pivot tables (`xl/pivotCache`, `xl/pivotTables`, workbook `pivotCaches`)
- external links
- slicers (parts or the slicer extension URIs)
- timelines
- sparklines
- embedded objects (`xl/embeddings`, `oleObjects`)
- data connections (`xl/connections.xml`, `xl/queryTables`)
- web extensions
- custom XML parts
- protected ranges
- custom ribbon (`customUI`)
- threaded comments (`xl/threadedComments`, `xl/persons.xml`)
- sheet backgrounds (worksheet `picture`)
- ignored-error extensions

These are the parts openpyxl 3.1.5 drops on a normal load/save, or rewrites
badly enough that the original structure is not the supported subset.
openpyxl's own worksheet reader removes the sparkline, slicer, protected-range,
ignored-error, web-extension and timeline extension URIs.

Not rejected, on purpose:

- `xl/calcChain.xml` and `xl/printerSettings` are caches. Excel and LibreOffice
  rebuild them. Rejecting them would fail ordinary workbooks.
- Cell-comment VML whose shapes are all `ObjectType="Note"`. Comment text is
  preserved and only the note drawing is regenerated. Any other VML shape is
  rejected.
- The x14 data-validation and conditional-formatting extension URIs. Classic
  `dataValidations` are in the supported subset, and a duplicate extension
  record is not treated as a second feature. Conditional formatting is outside
  this ticket's declared subset; a file that only has the classic records is
  not failed by this preflight.

## DOCX fallback

`run_export` still catches unexpected export errors and writes
`*_answers_fallback.docx`. That path stays for corrupt packages and for
writer failures that are not unsupported structure. Removing it would change
exports that are not workbook-structure failures (for example a `.xlsx` name
whose bytes are not a workbook). Unsupported structure is excluded from that
`except` and fails the job instead.

## Configuration

No new setting. `EXPORT_ANSWER_COL_OFFSET` is unchanged.

## Operator note

A failed export whose error says the workbook contains unsupported content did
not produce a substitute document. Remove the named parts (macros, shapes,
form controls, pivot tables, external links, slicers, or the others listed
above) and export again. A download named `*_answers_fallback.docx` is a
different failure: the workbook bytes could not be written, and the DOCX pack
is the question/answer table only.
