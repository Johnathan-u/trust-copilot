## Behavior

Individual answer create/upsert and PATCH checked workspace ownership but did
not require an active questionnaire parent. A same-workspace archived parent
still accepted writes, including a retry after a previously successful write.
The new matrix reproduced ten HTTP 200 responses where a denial was required.

The two handlers now call the existing `require_in_workspace` helper before
answer mutation. Create/upsert validates the question's current active parent;
PATCH validates the answer's current question/questionnaire chain. The existing
foreign-workspace check still runs first, preserving 403 with `Access denied`
for foreign or moved parents, including foreign archived parents. Own archived
or unavailable chains fail with the helper's neutral 404, `Referenced resource
not found`. Missing question/answer objects retain their existing `Question not
found` / `Answer not found` 404 responses. No answer content is returned on denial.

No collection alias, route order, schema or bulk behavior changes are included.
Own success responses, text/status semantics and outcome handling remain:
changed human text clears the model outcome, identical text preserves it,
upsert's empty text keeps existing text, and PATCH's empty text clears it.
Omitted/null PATCH fields and existing custom status strings retain their behavior.
Auth, roles, models, schema, dependencies, generation and UI are unchanged.
