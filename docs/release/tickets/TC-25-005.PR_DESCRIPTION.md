## Behavior

- Preserved request and response fields on `/api/case-studies`. Additive `schema_version` `case-study.v2`.
- `PATCH` cannot set `published` or `in_review`. Use submit, review, publish, and withdraw.
- Current roles: admin writes and publishes, `can_review` approves or requests changes, any member reads, other workspaces get 404. Owner and viewer roles are not added.
- Customer claim is derived. Synthetic is never a customer claim.
- UI: `/dashboard/case-studies`.

## Ambiguities resolved

1. "Before anything can publish" still requires consent when a synthetic study quotes an organization or a result. The published row stays `synthetic_example` and `customer_claim` false. A synthetic study with nothing quoted can publish after review without consent records.
2. "Every quoted organization has permission for each quoted result" is the full set of organizations × results. One missing pair rejects the publish. No partial publication is stored.
3. Organization match is exact after trim. Names are not case-folded.
4. Quoted organizations are `company_name` plus `quoted_organizations`. Quoted results are a non-empty `quote` (`quote`), a non-empty `results` (`results_narrative`), and each metrics key (`metric:<key>`).
5. "Current permissions" means the roles that exist today (`can_admin`, `can_review`, signed-in read), not the owner/viewer model in the product spec.
6. `customer_claim` in the response is derived from status, review, synthetic, publication, and live consent rows. A stored `true` without those facts is not a claim in the response. GET does not write that correction back.
7. "Restart" in the release test disposes the SQLAlchemy pool and reads again. It does not reboot the host or start a second API process.
8. Previously published rows are unpublished by revision `tc25005_case_study_consent` because they have no consent. The upgrade never deletes a case study row. Downgrade copies consents, permissions, review metadata, and a content fingerprint into archive tables that exist only while the database is on the parent revision. The fingerprint covers every parent content column, including industry, company size, and quote attribution. Snapshot `status` / `published_at` are restored only for rows still in the exact post-upgrade state. Re-upgrade compares a snapshot-restored row to that pre-consent status, so a second round trip still recovers it at revision 1. Any other status or fingerprint change returns the row as a draft at revision+1 with review cleared, so the old consent does not cover an edit or an unpublish made on the parent revision. Archive tables are dropped after that restore. A customer claim with no active consent is not resurrected.
9. A non-synthetic study with no quoted organization and no quoted result can finish the workflow. `customer_claim` stays false and `data_basis` stays `unverified`.
10. An admin also has `can_review`, so an admin can approve their own draft. The release test uses the reviewer account for the approval step.
11. Idempotency keys are prefixed with workspace and case id. A key used on a failed publish keeps returning that failure until a different key, or no key, is used.
12. Template metric names such as `hours_saved` remain field names. The template response says they are not results and that the template contains no customer.

## Coordinator rulings (2026-10-27)

- A named organization alone, by name or by logo, counts as a customer claim. Here that is `company_name` or `quoted_organizations`. Consent is required before publish, even when there is no quote and no result. A consented publish of that row is a customer claim. Synthetic rows stay synthetic.
- The conservative organization × result rule stays. One missing pair blocks the whole publish. Follow-up ticket TC-25-005a is per-org attribution, where each result belongs to one organization and needs that organization's consent. TC-25-005a is logged and not implemented in this change.
- Consent stays an operator reference string (`consent_reference`). Signed evidence is TC-26-015. This ticket does not collect or verify a signed document.
- The eight workflow routes and `/dashboard/case-studies` are in `docs/acceptance/scope-freeze.md`, labelled scope-freeze amendment approved by coordinator 2026-10-27. `case_studies` is 14 operations (was 6). The page inventory includes the new page.
- Claims-register row A4 now says: naming an organization is a customer claim and requires consent before publishing. A4 is **Supported** only for the blank template and the consent gate, citing `tests/release/test_domain_case_studies.py`, `tests/test_case_studies.py`, and `artifacts/acceptance/TC-25-005/`. Signed consent evidence (TC-26-015), reviewer signoff, and any real customer name, logo, quote, or result stay **Withheld**. TC-25-005a is not part of that Supported part.
- Round-2 review: GETs are read-only. Content `PATCH` requires `expected_revision`. `consent_reference` on GET is admin-only. Consent revoke, permission grant, permission revoke, delete, and submit-review write audit events. The consent-grant audit records organization, consent id, and revision. The permission-grant audit records consent id, result key, and revision. `consent_reference` is never logged. Delete returns 409 while consent or permission rows exist. Index names on the models match the migration. A separate-reviewer rule is follow-up TC-25-005b. Free-text organization mentions do not open a consent requirement. `GET /template` stays unauthenticated because it is the static blank template.
