## Scope and contract

Source: Sale Plan TC-18-002 and PRODUCT_SPEC; schema and minimum final-submit scope approved in #85 comment 6503678126. This branch owns vendor routes, service, model, migration, related tests and this evidence. Full portal drafts/resume/attachments/required-question completeness remain TC-18-003. No dependencies, web UI, shared auth or live provider calls changed.

Creation validates an ordinary ASCII mailbox, a message of at most 10,000 characters and an optional live same-workspace questionnaire. Current active membership/key and permission are locked and rechecked on every private mutation, including after idempotency claim commits; API-key administration is supported because these operations do not assert human approval. Missing and foreign IDs return equal 404 responses. GET performs no writes.

New requests issue a random grant once and store only its SHA-256 hash. List and idempotency replay retain the `link_token` key as null; the first create/send/resend response includes the raw link. New grants expire after seven days by default; creation accepts 1–90 days. Rotation issues another seven-day grant. Pre-migration raw grants are accepted only within seven days of their recorded creation; this compatibility policy is computed without backfilling provenance. Unknown, expired and revoked grants return the same generic 404 for public GET and submit.

Create supports optional scoped Idempotency-Key; send/resend require it. Each send persists its intent and replay marker before contacting the provider. Replays read the current result without sending again. Console/disabled providers are unavailable. `accepted` means provider acceptance, not mailbox receipt. False/exception outcomes are uncertain. A crash after send leaves durable `sending`; both states prevent further delivery until reconciliation. Explicit resend after a known accepted outcome rotates the old grant. No automatic resend is claimed.

Final submit writes bounded response text (20,000 characters), digest and timestamp under a row lock. Identical retries return the original receipt; changed retries conflict. Only persisted submission establishes completed status. Cosmetic legacy completed strings remain unproven. Public GET retains its metadata-only shape; final submit returns status, timestamp and digest.

## Migration and compatibility

Nullable fields add hash, expiry, revocation, bounded delivery/error state and response provenance. No delivery or submission is inferred for old rows. Matching model constraints/indexes enforce delivery values and all-or-none submitted fields. Downgrade parks populated values and every legacy raw grant in a bounded hold table, clearing the live raw-token lookup before the old app can reopen revoked or expired grants. Re-upgrade restores nondefaults only to the matching original base row. A changed base-row fingerprint during downtime blocks restoration with the hold intact, avoiding attaching prior provenance to changed recipient/content. Deleted-row holds remain retained for reconciliation. Revision id is under 32 characters.

The migration follows the Coordinator queue. Master updates use merge commits; migration parent updates are separate commits. Runtime tests check ancestry through descendant heads and round-trip nondefault data, including a guarded downtime edit.
