# TC-18-002 — outbound vendor requests

Status: implementation in progress; full acceptance is blocked on Coordinator migration and public-submission ownership rulings in #85.

## Contract and allocation

Source: `TrustCopilot_Complete_Sale_Plan(4).zip`, ticket TC-18-002 and PRODUCT_SPEC. TC-10-003 is merged. Branch: `codex/TC-18-002-vendor-requests`; initial master: `5b97a33d0cd43d07ebba901901d5433d7725eb43`. Only vendor-request routes/services/models/tests and this ticket's documentation/evidence are allocated. No web UI, shared infrastructure or live provider calls.

Create/send/revoke/resend must report actual persisted delivery state. Completion requires a submitted response. Missing and foreign resource identifiers return equal 404 responses. GET is read-only. Every mutation needs a permission-denial test. Tests remove all rows they create and assert counts.

## Implementation plan

1. Add PostgreSQL regression tests for existing route boundaries: create normalizes bounded input and rejects malformed addresses, bulk-sized messages, and invalid questionnaire references before writing. PATCH rejects cosmetic completion. GET does not mutate persisted rows. Both existing mutations enforce current admin permission.
2. Run tests against unchanged production code and record failures. Implement the allocated route validation and completion guard with no schema change. Preserve existing successful creation/list response keys.
3. Once the Coordinator schedules a migration, add durable expiry, revocation, delivery-attempt outcome and submitted-response metadata with a lossless downgrade/upgrade test. Keep legacy state explicit. Do not claim a recorded `completed` string is evidence of submission.
4. Once minimal `vendor_response.py` submission ownership is ruled on, connect completion to authenticated token submission, replay-safe persistence and revocation/expiry checks. Add failure/restart/retry tests and preserve read-only GET. Full public portal work stays on TC-18-003 unless reassigned.
5. Verify the focused tests and affected existing suite, then the full backend suite. Record actual tested commit, environment and every failure. Obtain independent code review before the PR. TC Coordinator alone merges.

## Review focus

- Duplicate retries cannot create duplicate requests or delivery attempts.
- Missing, foreign and deleted questionnaire references cannot leak existence or change persisted state.
- Provider timeout or development stub cannot become confirmed delivery.
- Expired/revoked grants cannot expose or accept a submission; GET cannot persist lifecycle transitions.
- Failed persistence cannot leave a successful-looking response or an orphaned idempotency claim.

## Boundaries still pending

The schema has no expiry, revocation, delivery or response fields. Migration and public-response route changes await #85 scheduling/scope ruling. API-only work cannot establish frontend consumer acceptance. Deterministic provider doubles establish local control paths only, not real delivery qualification.
