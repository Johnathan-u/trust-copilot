## Review focus

- Duplicate retries cannot create duplicate requests or delivery attempts.
- Missing, foreign and deleted questionnaire references cannot leak existence or change persisted state.
- Provider timeout or development stub cannot become confirmed delivery.
- Expired/revoked grants cannot expose or accept a submission; GET cannot persist lifecycle transitions.
- Failed persistence cannot leave a successful-looking response or an orphaned idempotency claim.

## Approved lifecycle design (Coordinator ruling 6503678126)

All schema/model changes and the minimum final-submit route are approved. Initial migration parent is the reviewed master head; it will be re-parented separately when the Coordinator calls the landing slot. Schema downgrade preserves non-null lifecycle columns in a hold table, following the existing gap-evaluation migration pattern; upgrading restores non-default data. Legacy rows receive no inferred delivery or submission.

New requests issue a random bearer token once and persist only its SHA-256 hash. List and idempotency replay responses cannot reconstruct it and return null for `link_token`; the first create/send/resend response contains the link. Existing raw legacy tokens remain valid until rotation or revocation. Sending or resending rotates the token. Revocation and expiry are checked on both public GET and final submit, with the same generic 404 as an unknown token. GET never writes.

Creation accepts an optional Idempotency-Key. Delivery actions require a key and persist a delivery intent before contacting the configured email provider. Replay reads the durable outcome and never sends twice. Console/disabled providers report unavailable. Provider acceptance is `accepted`, not proof of mailbox receipt; false/exception/interrupted outcomes are uncertain and are never automatically retried. Explicit resend is allowed after a known accepted outcome, but an uncertain/in-progress attempt requires reconciliation before another attempt.

New grants expire after seven days by default; creation permits 1–90 days. Message limit is 10,000 characters; final response limit is 20,000 characters. Ordinary ASCII mailboxes are supported; unsupported/control-containing addresses fail validation. Database bounds match the API for new lifecycle fields. Final submit records the response text, SHA-256 digest and submission timestamp in one locked transaction; identical retries return the original receipt, changed retries conflict. No draft/resume, attachments or required-question completeness claims are included.

The public GET retains its existing metadata shape. Final submit returns only completion status, timestamp and response digest. Private list retains existing keys and adds lifecycle state. Completion comes only from persisted submission; old cosmetic `completed` rows remain unproven. API-key administration remains supported, because vendor request operations do not assert a human approval identity.
