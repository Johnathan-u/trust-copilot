# TC-06-002h — Authorize explicit references before manual job retry

Status: **implemented locally; independent review and migrated PostgreSQL/CI pending**.
Parent: TC-06-002. Base: `90146e0cfe2220beb3e43f98f6073262f7c0abfb`.

The [implementation ruling](https://github.com/Johnathan-u/trust-copilot/issues/85#issuecomment-6532920880)
continues the existing #85/6517430971 claim. Stored-auth HTTP intake reproduced
11 unsafe payload cases: a foreign, moved, missing, archived or hard-deleted
questionnaire/document, or a mismatched explicit workspace, was requeued and
recorded `job.manual_retry` without querying either parent table.

The bounded repair changes only `app/services/job_control.py`. After the existing
missing-job, status and idempotency checks, and before any mutation, retry checks
explicit object-payload fields. `workspace_id`, `questionnaire_id` and `document_id`
must be positive JSON integers within the database integer range. Booleans, null,
strings including numeric strings, floats, lists, objects and invalid integer IDs
are rejected without coercion. The workspace must equal the locked job's workspace;
the existing unchanged `require_in_workspace` helper resolves both supplied parent
references against their current workspace and active state.

Invalid references roll back and use the existing missing outcome, producing the
same `404 {"detail":"Job not found"}` as a foreign or missing job. No job update or
audit is written. Unexpected database errors and non-404 helper failures propagate.
Reference-free legacy objects, absent payloads, malformed/non-object legacy JSON,
cancellation, prior result/error metadata and existing status/idempotency precedence
remain unchanged. This does not add worker execution validation or alter artifact
projection, routes, schemas, providers, dependencies or shared reference helpers.

## Acceptance evidence

The new suite runs actual HTTP routes, stored sessions, current membership/custom
permissions, database queries and audits. Only `get_db` is wired to the isolated
store. It contains 103 SQLite controls and 104 migrated PostgreSQL cases; the extra
PostgreSQL case preserves the actual partial-index idempotency-conflict behavior.
SQLite creates actual model tables and asserts FK enforcement. No index, constraint,
trigger or schema is replaced to simulate PostgreSQL.

Checks include inaccessible/currently changed parents, explicit malformed reference
types, two simultaneous references, current-principal denial, successful retry of
all five job kinds from failed/cancelled states, preserved legacy payloads, own-job
cancellation and repeat cancellation, neutral foreign/missing job responses, and
status/idempotency precedence. Unexpected helper/database failures have explicit
propagation controls.

Every denial compares full-row hashes across twelve authentication/source/job/audit
tables and permits only SELECT statements. Successful retry verifies the exact
changed job columns and single actor/prior-attempt audit, preserving all unrelated
rows. Fixture creation and HTTP flushes record exact owned IDs; child-first cleanup
removes only those IDs and checks the original complete snapshot.

Fresh red/green evidence: 47 regressions fail on the unchanged base, including an
observed HTTP 200 instead of 404; the final 103 SQLite cases pass after the repair.
All 207 new cases and 15 unchanged cancellation tests collect. See
[verification](../../../artifacts/acceptance/TC-06-002h/verification.txt).

Local PostgreSQL is unavailable. The required full-suite attempt exits 3 before
execution, with localhost connection refused. The 104 PostgreSQL cases, legacy DB
checks, independent review, and exact-head `build`/`web-release-e2e` on both push and
pull request remain gates. This child does not close TC-06-002 or TC-06-003, qualify
external providers, or establish release readiness.
