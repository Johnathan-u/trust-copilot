## Contract and implementation

- GET `/api/evidence-gaps` consumes `evidence-gap-ownership/v1`. Unknown versions,
  malformed rows and duplicate row IDs fail explicitly rather than appear empty.
  Null reasons are valid. Priority, age and owner presence come from the API.
- Permissions require `can_review`; CSV export additionally requires `can_export`.
  Changing workspace remounts both reports, clears prior data and aborts reads.
- Gap and coverage reads fail independently. Polling pauses while the tab is hidden.
  Failed refreshes retain a labelled saved snapshot, except 401/403/404 responses,
  which clear the prior data. Retry clears errors on successful acknowledgement.
- Search, status and priority filters apply to all returned gaps, with 25-row pages.
  Export includes all filtered rows, snapshot time and row count, with human labels
  and CSV formula protection. It does not export identifiers or unreturned fields.
- Coverage uses the existing versioned control-coverage contract. The page explains
  that questionnaire coverage is not certification or control compliance, gives
  numerator/denominator context, all-history scope and retrieval freshness.
- Chart margins fit narrow layouts. Charts have equivalent expandable tables;
  trend data is labelled cumulative historical answer records.

## API dependencies and accepted scope

- #83 merged at master `80607881320e1fa2c6416c55730eb98a56449f26`. Open gap
  decisions use POST `/api/evidence-gaps/{id}/decision` with `can_admin`;
  resolution uses POST `/api/evidence-gaps/{id}/resolve` with `can_review`.
  Each decision is confirmed; acceptance/dismissal do not imply evidence qualifies.
- Resolution offers bounded, searchable approved evidence from this workspace via
  `/api/evidence-search`, filtered to the control when supplied. Approval alone is
  not eligibility: the server checks freshness and actual control/question backing.
- A write is shown as successful only after a versioned response matches the gap,
  workspace and intended status. Resolve additionally requires `resolved: true`.
  Notification failure is reported separately without undoing a confirmed result.
- The same exact intent/body retains its idempotency key after an ambiguous failure;
  changed decisions or evidence use different keys. Rejected requests keep the
  choice and display safe errors. Refresh gaps reconciles concurrent decisions.
  Old in-flight reads cannot overwrite an acknowledged write; workspace teardown
  aborts and ignores late writes. Confirmation receives keyboard focus on success.
- Gap rows link to an existing questionnaire when the API supplies its identifier.
  Recommendations consume TC-21-007b `evidence_ids`, `control_ids`, `question_ids`
  and TC-21-007c `question_sources: [{ question_id, questionnaire_id }]`.
  Evidence opens a read-only detail from `/api/compliance/evidence/{id}`;
  control sources link to the existing `/dashboard/controls/{id}` route.
  Question disclosure reads only its explicitly mapped questionnaire with the
  current `workspace_id`, verifies its identity and unique matching question,
  and shows the exact question text plus the existing questionnaire route.
  There is no questionnaire scan, guessed parent ID, or invented source route.
- Recommendation IDs must be positive safe integers and source lists must be
  unique. Question pairs must reference the reported `question_ids`; malformed
  provenance fails the coverage read rather than silently dropping suggestions.
  Legacy absent provenance and missing question mappings remain visibly
  unavailable. Empty live-source lists keep the title and suggestion count.
  Counts retain their API meaning and are not changed to source-list lengths.
- Source reads begin only when disclosed, time out after 15 seconds, and support
  retry after safe denied/missing/failed responses. Evidence must match both the
  requested ID and active workspace. Question content and navigation stay hidden
  when the returned questionnaire or question does not match. Closing a source,
  changing workspace, or removing the report aborts and ignores late responses.
  Existing review permission and coverage refresh denial behavior remain intact.
- Recommendations remain available with zero questionnaire questions (including
  control-only gaps). Source references do not assert evidence qualification.
- No shared UI, auth context, Sidebar, backend, migrations, dependencies or provider
  calls changed. The earlier increment added `ui-23.spec.ts` to the CI spec list
  under Coordinator ruling 6503678126; the AC6 follow-up changes no workflow.
  Passing screenshots and axe output are attached to the Playwright HTML report.
