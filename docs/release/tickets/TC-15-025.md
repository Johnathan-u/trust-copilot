# TC-15-025 — Compliance coverage and evidence gaps

This is the Coordinator-authorized read-only increment on #85. It does not close
the full ticket: recommendation provenance and mutation integration are pending.

## Contract and implementation

- GET `/api/evidence-gaps` consumes `evidence-gap-ownership/v1`. Unknown versions,
  malformed rows and duplicate row IDs fail explicitly rather than appear empty.
  Null reasons are valid. Priority, age and owner presence come from the API.
- Permissions require `can_review`; CSV export additionally requires `can_export`.
  Changing workspace remounts both reports, clears prior data and aborts reads.
- Gap and coverage reads fail independently. Polling pauses while the tab is hidden.
  Failed refreshes retain a labelled saved snapshot, except 401/403/404 responses,
  which clear the prior data. Retry clears errors on successful acknowledgement.
- Search, status and priority filters apply to all returned gaps, with 25-row pages.
  Export includes all filtered rows, snapshot time and row count, with human labels
  and CSV formula protection. It does not export identifiers or unreturned fields.
- Coverage uses the existing versioned control-coverage contract. The page explains
  that questionnaire coverage is not certification or control compliance, gives
  numerator/denominator context, all-history scope and retrieval freshness.
- Chart margins fit narrow layouts. Charts have equivalent expandable tables;
  trend data is labelled cumulative historical answer records.
