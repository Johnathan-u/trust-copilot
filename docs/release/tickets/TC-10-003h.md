# TC-10-003h: answer write locking, versioning and duplicate rows

Follow-up of TC-10-003. It collects the non-blocking items from the independent post-merge reviews of #202 (`a2b39c8`) and #204 (`2893ff7`, renamed TC-10-003f).
Epic E10. 5 points, P1. Depends on TC-10-003. Branch: `tc/TC-10-003h-answer-locking`.

## Acceptance criteria

1. Lock scope:
   - Answer writes for a questionnaire use one advisory lock per questionnaire, or the routes set a `lock_timeout` and return 409 when generation holds the lock.
   - `PATCH /answers/bulk` caps `question_ids`.
   - Bulk against generation can't deadlock into a 500.
   - PostgreSQL's shared lock table can't be exhausted by one request or job.
2. Approve and PATCH carry a version or `updated_at` precondition and return 409 when the answer changed since the reviewer loaded it.
3. A unique index on `answers.question_id`, with a dedupe backfill and a rollback test. Alternatively, readers such as `questionnaires.py:367` choose a duplicate deterministically, and the decision is documented.
4. The `isinstance(db, Session)` branches no longer skip the write guard for a session wrapper that isn't a `Session` subclass.
5. Barrier-thread tests cover the parse and index `FOR UPDATE` paths.
6. Each code item has a test that fails without the fix.

CI on both events, plus an independent review. Under OD-14 no separate owner sign-off is needed.
