# TC-04-001d: OAuth state binding, OIDC nonce and PKCE, provider claim hardening

Follow-up of TC-04-001. It collects the provider and protocol items that the independent reviews of #193 (heads `68ed30d`, `75cb6d7` and `138e047`) left as non-blocking. The state, nonce and PKCE gaps predate #193. The unused `OIDC_DEFAULT_WORKSPACE_ID` is a result of #193. None of these is one of the takeover fixes in TC-04-001. The verification-abuse, rollout and web items are in TC-04-001c. This ticket was first registered as TC-04-001b in tracker revision 15. That ID already belonged to the workspace creation limiter work (#65, `docs/release/bugs/TC-04-001b.md`), so it was renamed.
Epic E04. 3 points, P1. Depends on TC-04-001. Branch: `tc/TC-04-001d-oauth-hardening`.

## Acceptance criteria

1. The Google and GitHub callbacks compare the signed `state` with the browser's state cookie and reject a mismatch, which blocks login CSRF. The OIDC flow uses a `nonce` and PKCE (S256), and the callback validates both.
2. Provider claims:
   - OIDC never uses `preferred_username` as an email.
   - ID.me's `verified` claim is not treated as email verification.
   - OIDC linking by email is limited to email domains configured for that issuer, or needs an explicit operator mapping. An admin at one identity provider can't assert another tenant's address and be linked to that account.
   - Linking by email to an existing account revokes that account's sessions, or requires a password reset when the password was set before verification.
3. `OIDC_DEFAULT_WORKSPACE_ID` is marked deprecated in the config contract, and setting it logs a warning.
4. Each code item has release tests that fail without the fix.

## Evidence and sign-off

CI on both events, plus an independent review. Under OD-14 no separate owner sign-off is needed.
