## Defect and repair

The citation composer already scoped its requested control to the authenticated
workspace, but loaded each linked evidence item by ID alone. An owned control
with a link to another workspace's evidence exposed that evidence's ID, title,
source and approval state plus link verification/confidence metadata. The foreign
row also inflated evidence counts and citation strength. The answer endpoint
reused that projection and included foreign approved evidence in its answer bundle.

The evidence lookup now requires both the linked evidence ID and the already
authorized workspace ID before any citation fields, counts or strength are
computed. Existing same-workspace results are preserved. Foreign/missing controls
still return 404 on `GET /api/citations/control/{control_id}`; the existing
`POST /api/citations/answer` behavior omits them from an otherwise valid answer
bundle. No route, response schema, role, authorization dependency, framework
catalog, migration or database guard is changed.

## Acceptance

The new `test_authorization_core_citations.py` runs eight scenarios against each
of SQLite and migrated PostgreSQL:

- Mixed local/foreign links expose exactly the local approved/pending fields and
  calculate counts/strength only from those local rows.
- Foreign-only links expose no evidence and contribute no count or strength.
- Valid local links retain approval status, confidence, verification timestamps
  and strong citation results.
- Mixed answer control IDs retain authorized controls and approved local
  citations while excluding foreign controls, missing controls and foreign evidence.
- Missing/foreign control endpoint semantics remain unchanged.
- Anonymous, suspended and removed-member contexts cannot read either endpoint.

Tests use actual stored users, session rows, signed cookies, current memberships,
HTTP routes and service queries. Only the database dependency selects the owned
test connection; authentication and service behavior are not replaced. Every
HTTP call compares hashes of every column in the relevant persisted tables.
Fixture cleanup deletes only recorded inserted IDs in foreign-key order and
requires the full pre-fixture table hashes to match. No global difference deletion,
sequence reset, foreign-key disablement or trigger bypass is used.

SQLite runs explicitly enable foreign keys. They are local service/HTTP controls,
not PostgreSQL migration/trigger qualification. The PostgreSQL cases use the
existing migrated test database. If that database rejects a synthetic cross-link,
the test fails at insertion so the protection can be reported separately; it does
not bypass the guard or silently substitute a different test.
