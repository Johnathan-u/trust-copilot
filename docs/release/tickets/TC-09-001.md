# TC-09-001: Correct numbered uppercase and multi-section detection

Status: implemented on `tc/TC-09-001-question-detection`. Not merged. No migration.

## Baseline

On `6af195d` the questionnaire parser already walked every sheet, remembered the current section, and saved a question when a cell matched the question patterns. The golden SOC 2, ISO 27001 and vendor-DD workbooks already parsed. Two gaps remained.

A cell was classified as a section heading before it was classified as a question. Any all-caps sentence, and any line shaped like `1. Something`, was therefore a heading. Numbered questions and questions written in capitals were stored as the section title of whatever followed them, or dropped. Question marks other than `?` (`？`, `؟`, `¿`, the Greek question mark) were not treated as questions.

A workbook that could not be opened produced no rows. The parse job then stored the questionnaire as `parsed` with a count of zero. A readable workbook that contained only headings did the same. Neither was a review or a failure.

## What changed

A cell is a question when it contains a question mark in any script, or when the words after a leading `Q12.` / `1.` start with a question or request verb. A short all-caps title such as `ADDRESS VERIFICATION` stays a heading, as do numbered titles with no question word and no question mark (`1.0 CONTROL ENVIRONMENT`, `1. ACCESS CONTROL`). The heading check still runs first, and it now refuses a cell that is a question, so that cell does not replace the section for the rows after it. Each sheet still starts with no section.

The same detector is used for XLSX, DOCX and PDF. The numbered PDF sample that previously kept only the unnumbered question now keeps all three questions under `SECTION A: ACCESS CONTROL`. The recorded PDF baseline for that sample was updated to that output. Evidence parsing of a corrupt spreadsheet is unchanged: it still yields nothing.

A questionnaire workbook that cannot be opened raises `WorkbookUnreadable`. The message is fixed: `Workbook is corrupt or unreadable. Re-export it as an .xlsx file and upload it again.` It is a `ValueError`, so the job ends `failed` with `bad_input` and is not retried. The questionnaire status becomes `failed`, and `parse_metadata` is `{"count": 0, "error": <that message>}`. The path and the parser exception are not stored.

A readable workbook with no questions is not failed. The job completes, the questionnaire status becomes `needs_review`, and `parse_metadata` is `{"count": 0, "questions": [], "review": "No questions were detected in this workbook. Review the file or upload a corrected copy."}`. No classification run is started.

The questionnaire page shows that error or review sentence under the status.

## Runbook

* **Questions missing under the wrong section.** A numbered or all-caps question used to be swallowed as the next section. Re-parse the workbook. Headings such as `1. ACCESS CONTROL` and `ADDRESS VERIFICATION` are still headings.
* **Upload shows Needs review and no questions.** The file opened and no question was found. Check that the questions are in the sheet, not only in a header row, then upload a corrected file.
* **Upload shows failed.** The file is not a readable spreadsheet. The stored message is the sentence above. Re-export it as `.xlsx` and upload that. This is not a retryable job error.
* **Corrupt evidence spreadsheet.** Evidence indexing still skips a spreadsheet it cannot open. This ticket does not change that path.

No new configuration.
