# TC-04-004b — Current absolute session policy and remembered issuance cap

Status: implemented locally; independent review, PostgreSQL and exact-head CI qualification pending. Estimate: 5 points. Claim and technical ruling: [#85 comment 6514687779](https://github.com/Johnathan-u/trust-copilot/issues/85#issuecomment-6514687779). Base: approved strict-session source `a97b947454b63d849097207b5f79a01323b06d3a`.

This child covers the current absolute session-lifetime portion of TC-04-004-AC2 and remembered issuance in TC-04-006-AC1. The frozen product contract requires current server-side policy and immediate denial of inappropriate sessions after policy changes. Previously, a one-day workspace policy issued a 30-day remembered cookie; an older stored session remained authorized after the policy was shortened; and switching workspaces renewed the same session's signed expiry.

The current workspace limit is now read from the database on human authentication and combined with signed expiry and `UserSession.created_at`. UTC-naive stored timestamps retain their existing UTC meaning. Missing, unusable or future creation times deny the human session; the exact creation-time deadline is exclusive. The existing default remains seven days. Policy lookup failure returns an unavailable denial instead of falling back to a longer default. API keys retain their separate existing authority path. Account-only onboarding retains workspace-zero handling with the default lifetime and existing route restrictions; MFA enrollment retains its restricted permissions and respects the workspace cap.

Remember-me controls browser persistence without increasing the existing tenant/default lifetime. Password and MFA-completion flows check policy before creating a session or consuming the MFA challenge. Workspace switching checks the target's current deadline before success and limits replacement expiry to both the remaining target deadline and original signed expiry. Failed target checks leave stored rows and the cookie unchanged.

Runtime changes are limited to `core/auth_deps.py`, `api/routes/auth.py` and the narrowly authorized absolute-expiry option in `core/session.py`. No schema, migration, new setting/default, persisted remember choice, browser-persistence switch repair, idle timer/warning, provider flow redesign, role expansion or typed-principal work is included. The full parent tickets remain open.

The new `tests/release/test_remember_policy.py` has 88 cases: 44 SQLite and the same 44 PostgreSQL counterparts. Real routes, password hashing, TOTP, signed cookies, current memberships and stored rows exercise successful issuance, policy tightening, expiry boundaries, invalid timestamps, workspace switching and existing API-key/account-only exceptions. The policy-query error controls inject only the database execution failure; they do not mock authentication or policy decisions. Denials assert full-row invariants; fixture-owned cleanup retains exact count checks and full-row preservation of external data. Tests generate their synthetic password at runtime and are explicitly marked integration.
