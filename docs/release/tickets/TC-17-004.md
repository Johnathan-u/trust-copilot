# TC-17-004 — reviewed FAQ authoring and publication

Initial base: `76ae791`. Assignment and schema approval: #85, Coordinator ruling 6503678126. Migration slot 6; parent will follow current master at publication and be re-parented when the Coordinator schedules landing.

## Design and implementation plan

- Preserve existing authenticated CRUD response fields, adding an explicit revision, review/publication state, synthetic marker and same-workspace source-evidence identifiers. Legacy rows have NULL provenance and cannot be published. Default templates stay synthetic until content is verified and explicitly approved.
- Add bounded immutable content snapshots per revision and source links. Enforce source ownership in both service checks and database guards, including parent workspace moves. Approval requires a real current human reviewer and approved live evidence. Publishing requires the current approved revision. Edits invalidate approval/publication; stale action revisions conflict. Read-only published projection omits entries whose support has become unavailable.
- Add approve, publish, withdraw and revision-history API operations. Existing admin writes stay admin-only; reviewers may approve. Explicit action retry returns the same persisted revision without duplicate audit events. Create optionally uses the existing durable idempotency ledger with body-fingerprint conflict detection.
- New nullable lifecycle columns preserve legacy rows. New content and reference fields are bounded at API and DB boundaries. Downgrade archives review/version/source data; upgrade restores it only when the retained parent content and ownership still match. Edits made during rollback create a fresh draft revision; retained history remains readable. No invented review or publication metadata.
- First add failing schema and PostgreSQL route regressions. Implement the contract, run focused/related/full checks, record exact tested SHA and independent review. CI supplies pinned pgvector16; local PostgreSQL is unavailable. TC Coordinator alone merges.

## Review focus

Foreign/missing/deleted evidence is indistinguishable; draft/templates never become public via a listing; edits or evidence withdrawal cannot keep a stale publication visible; retries cannot duplicate review audit; downgrade/re-upgrade with non-default values preserves history without restoring stale approval after downgraded edits.
