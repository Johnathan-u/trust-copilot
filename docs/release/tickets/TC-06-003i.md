# TC-06-003i — Trust article administrative ownership

Bounded child of TC-06-003. Original intake:
[#85/6517430971](https://github.com/Johnathan-u/trust-copilot/issues/85#issuecomment-6517430971).
Active claim:
[#85/6532815699](https://github.com/Johnathan-u/trust-copilot/issues/85#issuecomment-6532815699).
Base: `90146e0cfe2220beb3e43f98f6073262f7c0abfb`.
Status: local SQLite controls pass; independent review and PostgreSQL CI remain required.

Create computed an authorized effective workspace but used the unnormalized request
value for both duplicate lookup and persistence. Omitting the workspace or sending
null therefore created an unowned article. Sending zero passed the computed scope
check but attempted an invalid foreign key. The PATCH and DELETE guards explicitly
exempted unowned articles, allowing any workspace administrator to modify or delete
them; PATCH also returned their private content.

The repair uses the already-computed workspace for the duplicate lookup and stored
article, and requires exact current ownership for PATCH and DELETE. Per the
coordinator's bounded ruling, the existing `body.workspace_id or session workspace`
fallback remains unchanged, including zero. Explicit nonzero foreign workspaces
retain 403, missing articles retain 404, and existing null-owned articles fail
closed with 403 on administrative mutations. No legacy article is reassigned.

Acceptance coverage:

- Omitted, null, zero and explicit-own creation bind ownership, preserve creator
  access, and put the same effective workspace in the existing audit log.
- Duplicate slugs in the effective workspace fail before writes; foreign and
  null-owned slugs do not block an owned article.
- Foreign, moved, null-owned, deleted and missing article mutation requests cannot
  alter rows. Own changes preserve response fields and real acknowledgment cascades.
- Actual stored sessions, current membership and custom admin permissions remain
  authoritative. Stale admin cookies, role loss, suspension, removed membership,
  revoked/expired sessions and a SID belonging to another user cannot authorize writes.
- Public published reads, signed read isolation and policy acknowledgment scope
  retain their existing behavior. Their handler and schema ASTs are unchanged.
- Every denial/read permits only SELECT statements and preserves complete rows in
  ten relevant tables. Success cases assert the exact changed row IDs. Cleanup uses
  exact fixture-owned IDs and restores the entire pre-fixture snapshot.
