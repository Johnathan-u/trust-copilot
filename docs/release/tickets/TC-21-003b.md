# TC-21-003b: keep verified status honest when evidence changes, and lock the control row

Follow-up of TC-21-003. It collects the non-blocking items from the independent reviews of #197 and #198 (heads `4d105d1`, `352e033` and `e3a4aaa`).
Epic E21. 5 points, P1. Depends on TC-21-003. Branch: `tc/TC-21-003b-verified-recheck`.

## Why

TC-21-003 demotes a verified control when a user unlinks its last qualifying evidence. A control can still stay `verified` with no qualifying evidence in these cases:
- the evidence is rejected;
- the evidence expires;
- the evidence's document is deleted;
- the retention job deletes it.

Verify, unlink and remediation also read and then write without a row lock.

Deploy note for TC-21-003: the first control-engine evaluation after that change rewrites many snapshot statuses, which shows as a one-off wave of `drift_detected` on the timeline.

## Acceptance criteria

1. After evidence rejection, document deletion and retention deletion (`retention_service.py:140`), any control that is `verified` and no longer has qualifying evidence is demoted to `implemented`. Its stamps are cleared, the legacy row follows, and the demotion event carries `previous_status` and `reason`.
2. Expiry: a scheduled re-check demotes a verified control once its qualifying evidence has expired, in the same way as criterion 1.
3. Verify, unlink, link and the remediation loop lock the control row (`with_for_update()`), so concurrent requests can't leave a control verified without evidence. Two simultaneous remediation submits for the same pair return a clean result, not a 500.
4. Tests:
   - a fault-injection test for the demotion rollback path (a failing `_record_event` → 409, link still present, control still verified);
   - a suspended-owner test for legacy detach;
   - a test that `last_verified_at` is kept when the flag doesn't change;
   - a real two-thread test for criterion 3.
5. Stamps and audit:
   - A PATCH to `verified` sets `verified_at` and `verified_by_user_id` (`compliance_controls.py:446-454`), like the verify route.
   - Every unlink emits an audit event, not only a demotion.
   - The audit page has a label for `compliance.control.implemented` demotion events.
6. In `artifacts/acceptance/TC-21-003/README.md`, the gap table and the `## SHA` paragraph describe the final commit and list the review items.
7. Each code item has a test that fails without the fix.
