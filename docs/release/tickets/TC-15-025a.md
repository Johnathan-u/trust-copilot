## Failure and diagnosis

Master `8f0cc07872057007d635e7bee17687f5fadc696b` had 239 passing browser cases
and one failure in run `41003220218`, web job `123892180051`, artifact
`12954536591`. The permission-revocation case timed out clicking Refresh gaps
after its target was removed. The artifact already showed the private data
cleared and the section error focused.

A confirmed gap decision focuses its acknowledgment and starts an automatic
reload. The original test enabled a 403 response after acknowledgment focus,
before that reload necessarily completed. That automatic request could therefore
correctly clear the private snapshot and remove Refresh gaps during the manual
click. The artifact's click began less than one second after navigation, before
the separate 60-second polling interval could run.

## Repair and acceptance

1. Hold the post-decision GET explicitly. In the existing manual-refresh case,
   release its successful response and wait for distinct content supplied only
   by that response before enabling denial and clicking Refresh gaps.
2. Add an automatic-refresh case that returns 403 on the held post-decision GET.
   Both cases retain acknowledgment focus, private-title redaction, dialog
   clearing, successful retry, restored title and absence of stale acknowledgment
   or dialog. Both verify that denial removes Refresh gaps. Release the request
   in cleanup even when an assertion fails.
3. Preserve every existing case and assertion, with no forced clicks, delays,
   timeout changes or skipped checks. Independently review the final commit and
   require both build and web-release-e2e on push and pull_request for that exact
   head before the coordinator merges; then verify master.
