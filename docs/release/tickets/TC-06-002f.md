The existing individual question, questionnaire queue and batch routes forwarded
IDs to an unscoped routing service. Real stored-session HTTP probes exposed a
foreign answer's ID, confidence, status and stored reason. Moving or archiving
the parent did not revoke these reads. Hard deletion correctly cascaded the
children, but the handler returned a success-shaped missing-question error.

Four added lines reuse `require_in_workspace`: one import and one guard before
each service call. The question/queue must have a current active questionnaire
in the authenticated workspace. Every batch ID is checked before any routing
projection runs. Foreign, moved, archived, deleted and missing references receive
the existing neutral `404 {"detail":"Referenced resource not found"}`.

Own response bodies and routing decisions are unchanged. Empty batches remain
empty successes; duplicates retain their counts and repeated details. The current
session-only permission remains, including an active member whose custom role
has no permission flags. Threshold handlers, service logic, schema and workflow
statuses are unchanged.
