Status: implemented locally; independent review and exact-head CI are pending.

## Contract

Every `recommended_evidence` row from `GET /api/compliance-coverage` gains
`question_sources: [{question_id, questionnaire_id}]`. IDs come from the stored
question and its current same-workspace, nondeleted questionnaire. Pairs are
unique and sorted by question ID. A recommendation without live questions has
an empty list. Both titled evidence gaps and insufficient-answer fallback
suggestions use the same scoped parent lookup.

Existing `question_ids`, recommendation counts, other response fields, routes,
review permission and read-only behavior remain unchanged. No migration,
dependency or new endpoint is needed. This supplies the missing parent ID for
the existing TC-15-025 AC6 questionnaire drill-down; frontend qualification is
separate work.

## Implementation plan

1. Add failing provenance assertions for actual parent association, deduplication,
   foreign/deleted/missing exclusion, titled recommendations and fallback rows.
   Extend the existing PostgreSQL route regression's read-only assertions.
2. Extend the existing scoped question lookup to return question-to-questionnaire
   pairs. Attach pairs to both recommendation paths while retaining prior fields.
3. Run focused local projection/unit tests, collection and lint; attempt the
   strict PostgreSQL suite and report any infrastructure limit. The coordinator
   obtains independent review and exact-head CI before publishing completion.

## Review focus

- Derive the parent from `Question.questionnaire_id`, never a gap's independent
  questionnaire field or a generated identifier.
- Do not expose foreign, soft-deleted or nonexistent question targets.
- Repeated gaps/answers preserve counts while emitting each question once.
- Keep sourceless rows visible with empty provenance arrays.
- GET must not change row counts or source timestamps.
