## Behavior

NDA approval, rejection and revocation, plus share deactivation, previously
looked up records by ID alone. An administrator in workspace A could mutate
workspace B's record and receive its requester/buyer metadata. Foreign approval
also minted a usable public token; rejection, revocation and deactivation
disabled the foreign capability. The intake reproduced these paths with actual
stored-auth SQLite HTTP requests, including records moved from A to B.

The four service lookups now require an explicit workspace argument and filter
by both ID and current workspace before mutation or projection. Their routes
pass the authenticated workspace. Foreign and moved IDs return the existing
missing/deleted response: NDA actions use 404 with `Request not found`; share
deactivation uses 404 with `Not Found`.

Existing admin permissions and transition behavior remain unchanged. NDA actions
still accept every existing status; approval rotates the token and applies the
requested duration, rejection/revocation preserve token fields, and repeated
share deactivation remains successful. Scoped lists, token expiry and public
token validation/access are unchanged. A valid foreign token is deliberately a
valid unauthenticated capability, rather than an administrative authorization.

The only existing-test edits add seven NDA service workspace arguments and one
share service workspace argument. No assertions or fixtures were changed.
The public request's existing workspace-1 policy, unused `get_space` helper,
create/reference policies, schema, providers, dependencies, roles and UI are
outside this increment.

## Acceptance evidence

It uses actual routes, stored users/memberships/sessions, expiring signed cookies
and enforced foreign keys. Only `get_db` is wired to the fixture. No auth,
service, token-generation or SQL mocks replace the required database run.

All four mutations cover own/foreign/moved/deleted/missing objects, current
admin permission and removed/suspended membership or removed session. Controls
also preserve all five NDA statuses, approval duration bounds, token rotation,
repeat deactivation, public valid/unknown/expired/disabled capabilities and
scoped lists. Denials compare the public token outcome and full-row hashes/counts

Cleanup deletes only exact owned IDs in FK order and compares the complete
original snapshot. Collection does not create fixtures or connect to a database.
