# TC-21-007b Provenance on coverage recommendations

**Status:** implemented locally. Not pushed. Framework catalogs stay **BLOCKED** pending **TC-01-007**. No migration.

`tickets/TC-15-025.md` is not in this checkout, and `/home/box/shared/trustcopilot-package` is not mounted. The behavior below follows the stated AC6: each `recommended_evidence` row gains real source ids from stored rows in the same workspace.

## Response

`GET /api/compliance-coverage` stays read-only and stays on review. `control_coverage.schema_version` stays `compliance-coverage-controls/v1`.

Each recommendation keeps `title` and `improves_questions`. It also has:

| Field | Contents |
| --- | --- |
| `evidence_ids` | Live evidence items in this workspace. An item tied to a deleted or other-workspace document is omitted. |
| `control_ids` | Workspace controls in this workspace. |
| `question_ids` | Questions whose questionnaire is in this workspace and is not deleted. |

Ids come from open evidence-gap rows that share the recommendation title (`question_id`, `control_id`, `evidence_refs`). When two gaps share a title and each names a live question, `improves_questions` is 2 and `question_ids` contains both ids. When there is no titled gap, the fallback suggestion uses the insufficient answer's question id. A recommendation with no live source is kept, with empty lists, so `title` and `improves_questions` do not disappear. Nothing invents an id.

`improves_questions` is still the open-gap count for that title, or the insufficient-answer count for a fallback. It is not rewritten to the length of `question_ids`.
