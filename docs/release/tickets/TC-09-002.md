# TC-09-002 Persist per-question original workbook answer-cell mapping

Status: implemented on this branch. Not merged. The change includes a database
migration and waits for Claude's review.

## Behaviour

Each parsed question now stores:

| Field | Meaning |
| --- | --- |
| `content_hash` | SHA-256 of the normalized question text that is saved. Same text, same hash. A different question text produces a different hash. |
| `original_file_hash` | SHA-256 of the original file bytes. Re-importing the same bytes keeps it. Any byte change, including a question edit, changes it. Null on rows saved before the file bytes were hashed. |
| `sheet` | Worksheet name for XLSX. Null for CSV, DOCX and PDF. |
| `question_cell` | Where the question was read. |
| `answer_cell` | Explicit cell that later export should write. Null when the file does not name an answer column. |
| `mapping_version` | Ruleset that chose the answer cell. |

The current ruleset is `CELL_MAPPING_VERSION` in
`apps/api/app/services/cell_mapping.py`, and that value is **1**. Rows that
already existed stay at **0**, which means no explicit answer cell was stored.
Raise the constant when the header rules change. Do not reuse a version for a
different rule. A new import stores the constant. It does not increment a row
only because the question text changed: text drift is `content_hash`, and file
drift is `original_file_hash`.

The answer column comes from a header cell whose whole value is Answer,
Response, Reply, or one of the other labels in `column_role`. It is never
`question column + 1`. An Owner column between Question and Answer is not the
target. A sheet with no answer header keeps `answer_cell` null rather than
guessing the next column.

`EXPORT_ANSWER_COL_OFFSET` is unchanged. This ticket stores the target.
Writing approved answers into that cell is still the export ticket's job.

There is no new configuration key.

## Formats

| Input | Question cell | Answer cell |
| --- | --- | --- |
| XLSX with Question / Owner / Answer headers | A1 reference of the question column, for example `B2` | A1 reference of the answer column, for example `D2`, on every sheet that uses that header |
| XLSX with an Answer header and no Question header | The cell the existing left-to-right scan already used | Same row, answer column. The question column is unchanged |
| XLSX with no answer header | The cell the existing scan used | Null |
| CSV with the same headers | A1 reference. There is no sheet (`sheet` is null). `source_location.type` is `csv` | Same rule as XLSX |
| DOCX paragraph | `paragraph:{n}` (1-based paragraph index) | Null. A paragraph has no answer cell |
| DOCX table with Question / Owner / Answer headers | `T{table}R{row}C{col}` | The answer column in that table, not the owner column |
| PDF | `page:{n}` added when the question is saved. The PDF parser's own page locator is unchanged | Null. A PDF is not an original-workbook round trip |

CSV parsing runs when a stored questionnaire file ends in `.csv`. The shared
upload allow-list is unchanged and still does not accept `.csv`, so a new
upload of a CSV file is still rejected. XLS remains on the existing
spreadsheet path.

Empty workbooks, unreadable XLSX bytes and empty CSV files produce no questions.

## Migration

`question_cell_mapping` revises `tc17003_security_claims`. It does not import
the application package.

Upgrade adds `content_hash`, `original_file_hash`, `sheet`, `question_cell`,
`answer_cell` and `mapping_version` on `questions`. `mapping_version` is not
null and defaults to 0, with check `mapping_version >= 0`. Existing rows are
backfilled from the text and `source_location` already stored: the content
hash is the SHA-256 of that stored text (not re-normalized), and sheet plus
question cell are read when the locator JSON parses. The answer cell and file
hash stay null. Invalid JSON does not fail the migration.

Downgrade copies those columns into `question_cell_mapping_hold` and then
drops them. Question text and `source_location` stay. Upgrade restores held
values for questions that still exist, then backfills only rows whose content
hash is still null. A held row whose question was removed stays in the hold
table.

## Questionnaire detail

`GET /questionnaires/{id}` returns the six fields on each question. The
questionnaire page shows the sheet, question cell, answer cell, ruleset
version and a short text hash. The full hashes are on the source cell's
tooltip.
