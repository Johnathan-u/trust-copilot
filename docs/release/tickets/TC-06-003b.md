## Behavior

Golden-library detail, lineage, update, review and reuse previously queried by
ID alone. A workspace A session could read B's answer/lineage and increment B's
reuse count; an A administrator could change B's answer or mark it reviewed.
The read-only intake reproduced these behaviors in 38 actual stored-auth,
FK-enforced SQLite HTTP probes, including records moved from A to B.

The five service lookups now require an explicit workspace argument and filter
by both ID and current workspace before projection or mutation. The five routes
pass their authenticated workspace. Foreign and moved IDs match the existing
missing/deleted behavior: lineage returns 404 with `Golden answer not found`;
the other four return 404 with `Not Found`.

Existing permissions remain: detail/lineage/reuse require a valid session;
update/review require admin permission. Valid status and field behavior remains
unchanged, including arbitrary existing update-status strings, omitted/null
field handling, review from all existing statuses, the `review_cycle_days or 90`
expiry rule, and reuse counts independent of status. List, expiring and similar
queries are unchanged. Approval route/service production code is unchanged.

The only existing-test edits add explicit workspace arguments to five golden
service calls and eight golden-service update calls in approval tests. No
assertions were removed. No source/reference eligibility, create-time reference
validation, schema, provider, dependency, role or UI changes are included.
