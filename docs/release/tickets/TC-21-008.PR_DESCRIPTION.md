## Migration

`tc21008_alert_records` revises `tc02001a_parent_ws_move`. It adds `compliance_alerts` and `uq_compliance_alerts_one_active` on `(workspace_id, condition, source_ref) WHERE status = 'active'`. Downgrade parks rows in `tc21008_alert_hold`. This needs a migration slot before it can be pushed. `alert_acknowledgments`, `evidence_gaps`, and `in_app_notifications` cannot store the condition, lifecycle, and source revision without overloading those tables.

## Ambiguities

A coverage alert has a fingerprint in `source_revision` because coverage has no revision column. `GET /active` reads stored active rows and does not recompute.
