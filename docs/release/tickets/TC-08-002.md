# TC-08-002: Report unsupported and empty evidence honestly

This file records the implementation. It does not accept TC-08-002. AC1 and AC2 stay unverified until an independent reviewer accepts them. No migration was added. No customer document is in the fixture or the evidence. The children TC-08-002a and TC-08-002b are implemented here and are not counted toward DONE by this file.

## What the check does

A corrupt evidence workbook, a legacy `.doc` or `.xls`, an unreadable `.docx`, and a non-PDF file with no extracted text fail the same way a PDF scan, password, or corrupt file already failed. The stored text is a fixed reason plus a next action. The document status is `failed`. It is not `indexed`. The text does not include the file bytes, the storage key, or a path.

`.doc` and `.xls` are rejected before python-docx or openpyxl is called, so the message is the same when those libraries are installed and when they are not. A `.doc` no longer becomes `Package not found at '<path>'` with job code `internal_error`.

The runbook is `docs/ops/evidence-format-errors.md`. There is no new setting.

## Contract

`GET /api/documents` still returns `index_error` on the document row. `GET /api/jobs/{id}` still returns `error` and `error_code`. For these failures `error_code` is `bad_input` and `retryable` is false, as it is for the PDF failures. The documents page already shows `index_error` when status is `failed`. No response field was added. No migration.
