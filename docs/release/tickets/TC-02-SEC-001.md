# TC-02-SEC-001 CI hardening: read-only workflow token

Every workflow under `.github/workflows` now runs with a read-only `GITHUB_TOKEN`:

- `ci.yml`: workflow-level and `build` job `permissions: contents: read`; the `build` checkout sets
  `persist-credentials: false` (`web-release-e2e` already had both).
- `deploy.yml`: workflow-level `permissions: contents: read`; `build` keeps `contents: read` and goes
  from `packages: write` to `packages: read` because its images are built with `push: false` and
  never leave the runner. `deploy` gets `contents: read`. Both checkouts set
  `persist-credentials: false`. Triggers and steps are unchanged.
- A job that genuinely needs a write scope must grant it at job level, explain why in a comment and
  be added to `ALLOWED_JOB_WRITES` in `apps/api/tests/release/test_workflow_permissions.py`.
  `contents: write` and `pull_request_target` are rejected outright.

Verification: `python -m pytest tests/release/test_workflow_permissions.py -q` from `apps/api`.
Rollback: revert the PR; no persisted state changes.
