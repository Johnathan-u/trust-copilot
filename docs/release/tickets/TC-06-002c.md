## Defect and contract

An authorized workspace-A caller could PATCH an owned questionnaire mapping with a workspace-B control or tag ID. The endpoint returned 200 and persisted the unauthorized reference; a missing reference produced a foreign-key error and HTTP 500. The existing guarded `/api/ai-mappings/question-preferences` POST rejected the same foreign reference with 404. The questionnaire mapping PATCH also allowed updates after its parent questionnaire was archived or moved to another workspace.

Only `update_questionnaire_mapping` and its required import change. Before looking up the mapping or modifying any field, the handler calls the existing, unchanged `workspace_refs.require_refs` helper for the current questionnaire and every supplied nonzero control/tag ID. This establishes that the parent exists, belongs to the current workspace and is not soft-deleted; controls must belong to that workspace; tags may belong to that workspace or be global. Missing, foreign and unavailable references return the same existing 404 body: `{"detail":"Referenced resource not found"}`. No status, approval, source, framework, reference or timestamp change occurs first, including in mixed-validity requests.

The mapping itself still must match its ID, parent questionnaire and workspace. An unknown or foreign mapping ID beneath an authorized parent retains the existing `Mapping not found` 404. The successful response fields and existing `require_can_edit` permission remain unchanged.

Compatibility is intentional:

- Omitted and explicit-null fields retain their existing behavior; supplied zero control/tag IDs clear those references.
- An empty framework key clears the existing framework preference. Framework keys remain labels with the existing handling; this child does not introduce a new catalog rule.
- All existing statuses remain supported: `suggested`, `approved`, `rejected`, `manual`.
- A supplied control value, including zero, still promotes a currently suggested mapping to manual, sets source to manual and approves it. An explicit non-suggested status retains the prior source behavior.
- Authorized controls, workspace tags and global tags continue to work for existing admin/editor roles.

No other endpoint, shared helper, authentication, role, model, schema, migration, generation, dependency or CI configuration changes are included. This child does not repair pre-existing stored mapping rows or broaden its scope to other read/generation paths.

Only `get_db` is injected; authorization and reference lookups are not mocked.

Coverage includes authorized control/tag changes, global tags, all statuses/source behavior, omitted/null/zero values, mixed-validity requests, foreign/missing references, targets moved to another workspace, archived/moved/physically removed/missing/foreign parents, mapping identity scoping, anonymous access, role downgrade after cookie signing, removed membership and revoked session. Physical parent removal uses the real FK cascade; SQLite foreign keys stay enabled. No constraint/trigger bypass or sequence reset is used.

Rejected requests assert both unchanged pending ORM state and complete before/after rows across 16 relevant domain/authentication tables. The snapshot also catches an assignment autoflushed by a later validation query, without hiding it behind a rollback. Successful updates compare every row and column, allowing only the specified mapping fields and its update timestamp.
