## Reproduced defects

Real password login with `remember_me=false` issued a session-only cookie, but
workspace switch added `Max-Age=86400` and creation added `Max-Age=604800`.
The same upgrade occurred after non-remembered MFA login and account-only
onboarding. The stored SID and creation timestamp did not change. These four
negative controls failed; two remembered-login controls passed.

Separately, workspace creation replaced a one-day signed expiry with a new
seven-day expiry. A stored-auth HTTP control still received `/auth/me` success
at the original expiry plus one second. This was an absolute-lifetime defect,
independent of whether the browser cookie persisted.

## Bounded contract

- Newly issued human sessions carry signed `cookie_persistent` boolean metadata.
  Password and MFA login preserve their existing submitted choice. Account-only
  onboarding, restricted MFA re-enrollment login and re-enrollment completion
  remain session-only. The common Google/GitHub/Microsoft/OIDC/ID.me issuer keeps
  its existing persistent choice; provider flows and UI are unchanged.
- Switch and creation persist the browser cookie only when the signed value is
  exactly `true`. Absent or malformed legacy values remain valid authentication
  metadata but reissue session-only. Neither token expiry nor incoming cookie
  headers can establish the unknown old choice. The original SID and all stored
  session fields, including creation time, remain unchanged on context reissue.
- Creation checks the existing current-workspace deadline before inserting a
  workspace. Within the creation transaction it also checks the new workspace's
  actual policy, then signs the earliest permitted absolute expiry. It checks
  the clock again before commit. Policy/signing/expiry failures roll back staged
  rows and issue no cookie. The normal creation policy, cap, throttle, membership
  and response contract are retained.
- Existing switch absolute-expiry handling remains intact. Reissue never turns
  the remaining age into a fresh lifetime. HttpOnly, SameSite, path and production
  Secure behavior remain unchanged.
- No schema, new settings, idle timeout, provider behavior, OAuth UI, role model
  or broader principal architecture changes. Registration, invite acceptance,
  email verification and password reset do not issue sessions; password change
  retains its existing current session rather than minting one.

## Verification and remaining gates

The new stored-auth suite has 96 cases, 48 SQLite and 48 PostgreSQL. It covers
every human issuance family, switch/create, exact-boolean and legacy metadata,
cookie attributes, a fresh HTTP client's session-cookie discard semantics,
signed/current/new-workspace expiry limits, signing-clock advances, denied
requests and full-row invariants on policy failures. Existing fixtures own and
delete exact rows; foreign rows remain unchanged. The shared OAuth issuer is
tested directly after its identity step, not against live providers.

Local combined verification passes 174 cases: 48 new and 126 existing policy,
principal, strict-session and MFA controls. Unit verification passes 714 tests
with 11 existing skips. Formatting, lint and diff checks pass. The existing
switch/signing-clock test now starts with a real remembered login so its
Max-Age assertion remains meaningful; all eight original assertion ASTs remain
unchanged.

Required PostgreSQL execution exits 3 locally because localhost:5432 refuses
connections. No PostgreSQL or real-browser restart qualification is claimed.
Independent review and #131 integration remain required; all four exact-head
CI jobs must pass before coordinator merge. This child does not complete
TC-04-006: idle policy, multi-browser logout/expiration warnings and full release
browser acceptance remain open. Evidence is in
`artifacts/acceptance/TC-04-006a/`.

The change needs no migration. Older signed cookies continue to authenticate;
their next reissue follows the conservative session-only legacy rule. Reverting
runtime changes restores the reproduced behavior and is not a security fix.
