## Problem

The trust-request attachment download does not call `validate_storage_key` and does not set `nosniff`. No test sends an expired session to the document, export, and attachment downloads. Claude's #306 comment 6998916540 also folds in three checks: `ensure_buckets` never checks that an existing or production bucket is private; `document_content` has no `deleted_at` filter, so an archived document still streams; the export responses lack `nosniff`, as well as the attachment route.

## Acceptance criteria

1. On the attachment download, reject a stored key that fails `validate_storage_key` and set `X-Content-Type-Options: nosniff`. Set `nosniff` on the export responses as well.
2. An expired session and a revoked workspace session are 401 on the document, export, and attachment downloads. An archived document does not stream.
3. `ensure_buckets` checks that an existing or production bucket is private.
4. Document the behaviour in this file.

## Behaviour

The attachment download calls `validate_storage_key` before `download_stream`. A failing key is 400, the detail does not echo the key, the response sets `X-Content-Type-Options: nosniff`, and the object is not read. The attachment stream sets the same header. Both export download responses set it. The document stream already did.

An expired session and a workspace-revoked session are 401 on the document, export, and attachment downloads. An archived document is not streamed, and its list row has no preview URL.

`ensure_buckets` checks an existing bucket and refuses a public ACL or a public policy. A new bucket is created with a private ACL and a full public-access block. In production the block must be fully on when the store can answer, and an unsupported call fails startup unless `S3_PRIVACY_ATTESTATION` is `unsupported-store-private`. That value skips only the unsupported call. A supported call that shows public access still fails. `BucketNotPrivate` is not swallowed.

The runbook is `docs/ops/private-downloads.md`. The parent note is `docs/release/tickets/TC-07-008.md`.
