## Problem

The verify-email page confirms a link and a 6-digit code, and it offers Sign in. A second verify of an address that is already verified is 400 after the token is deleted. Expired, invalid, and network are not three different announced messages. The raw token stays in the address bar and in the verify request URL. Priority is P2 because the parent is P2.

## Acceptance criteria

1. Treat an address that is already verified as success on both the link and the 6-digit code.
2. Keep expired, invalid, and network as three different announced messages, announce loading and the final status, and keep the raw token out of the address bar and the verify request URL.
3. Document the behaviour in this file.
