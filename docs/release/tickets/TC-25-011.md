# TC-25-011 Evidence-backed demonstration proof summaries

Schema version: `1` on `proof_summary` and on the demo-proof package.

## What a caller gets

`GET /api/demo-proof` is read-only. It still returns `sample_questionnaire`, `coverage_report`, `gap_list`, `walkthrough` and `live_stats`. Those sample blocks are a synthetic placeholder. Each one has `origin: synthetic`, `basis: not_measured`, `commercial_traction: false`, `data_basis: synthetic_example`, and a data window with `applicable: false`. The read does not insert or update a snapshot.

`POST /api/demo-proof` stores one snapshot for the caller's own workspace and returns the same package. Repeating it with unchanged evidence returns the stored JSON. It does not write another workspace and it does not change evidence rows. The dashboard button uses this POST.

The same response adds `proof_summary`. That object is the demonstration summary:

- Measured facts are counts of rows stored for the current workspace. `origin` is `real` and `basis` is `measured`. The data window is UTC.
- A successful count of zero is `state: no_data` when the workspace has no stored rows in the window, or `state: measured` with value `0` when other facts in that summary were found.
- A source that cannot be read is `state: unavailable` and `value: null`. It is not reported as zero.
- Customers, revenue, traffic and commercial usage are `state: unsupported` with `value: null`.
- `commercial_traction` is false on the package, the summary and every fact. A workspace count is never commercial usage. No consented source is wired up. A consented source would come only from the owner's pending case-study consent decision, which is not this ticket. Until that decision exists, these counts stay `commercial_traction: false`.

`live_stats` is copied from the proof summary. `questions_answered` still counts stored questions, and `legacy_field_notes` says so.

## Data window and time zone

Storage and reporting stay in UTC. That is an engineering call for this ticket. A display time zone can be added later. It does not change the stored timestamps or the summary window.

Omit both `window_start` and `window_end` to use the span of the stored rows that were included (minimum and maximum `created_at`, read as UTC). When there are no rows, the window start and end are null.

Set both bounds to an ISO-8601 timestamp with a numeric offset. Offsets are normalized to UTC before they are stored. A naive timestamp, a single bound, or an end before the start returns HTTP 400 `invalid_window` with `code`, `message`, `request_id`, `retryable: false` and `field_errors`. Naive `created_at` values already stored by older models are read as UTC.

Records outside the requested window are excluded and counted under `exclusions.outside_window`. Deleted questionnaires and documents are excluded. They are not proof.

## Persistence, retry and rollback

The summary is stored in `demo_proof_summaries` by POST. The idempotency key is a hash of the summary body without `summary_id`, `generated_at`, `content_hash` or `idempotency_key`. Repeating the same POST, including after a new database session, returns that stored JSON. A later GET of the same evidence returns that stored JSON and does not write.

Adding or changing evidence changes the hash and stores a new snapshot. Older snapshot ids keep the previous JSON. `GET /api/demo-proof/summaries/{id}` reads one snapshot for the current workspace. Another workspace receives `summary_not_found`.

There is no backfill. Upgrade creates an empty table and does not rename or overwrite existing rows. The migration file does not import application code. A snapshot is written on the next authorized POST from the rows that exist then. The revision id is `tc25011_demo_proof_summaries`. `down_revision` is `tc21001_framework_catalog_rights` after master PR #8. PR #25 (tc25005) is also re-parenting onto that revision. Whichever merges second re-parents again. The numeric id `076` is not used. Downgrade to the parent revision removes only this table. That drops derived snapshot data. Source questionnaires, documents, evidence, and exports stay, and the next POST rebuilds a snapshot from them. Snapshot history is not restored:

```bash
cd apps/api
alembic downgrade tc21001_framework_catalog_rights
alembic upgrade head
```

Questionnaires, documents, evidence and exports stay. Snapshot history is not reconstructed.

A stored snapshot whose JSON cannot be parsed returns `summary_unreadable` and is not replaced with a new figure.

## Who can read it

The route uses the current session or API key and checks membership again.

- A current admin, editor or reviewer signed in as a member of the session workspace can read. That is a human session, not an API key.
- A workspace API key may read the summary only when `api_keys.role` is `read`, and only for that key's own workspace. `read` is the read scope because `api_keys.role` is the only scope field. Editor, reviewer, admin and any other role are not read-scoped. Those keys get HTTP 403 `api_key_not_read_scoped`. The members API still mints only editor, reviewer and admin keys. This ticket does not add a create path for a read key.
- `workspace_id` on the query must match the key's or the session's workspace. Any other id is HTTP 403 `workspace_mismatch`, including a read-scoped key that presents another workspace's id.
- No session is HTTP 401 with the existing `detail` body.
- A suspended member is HTTP 403 with the existing suspended detail.
- A removed member, or a session with no workspace, is HTTP 403 `not_a_member`.

## Foreign references

Evidence, exports and evidence gaps that point at a missing, deleted, or other-workspace object are left in the database and left out of the counts. The summary status is `partial`, with `foreign_reference_rejected`. The failure lists the local record id and the reason. It does not include the other workspace's filename or document id.

Database foreign keys still allow a document, questionnaire, question or answer id from another workspace. This ticket reports those rows. It does not rewrite them. The defect report is `docs/release/bugs/TC-06-BUG-001.md`.

## Legacy sample endpoints

`GET /api/demo-proof/questionnaire`, `/coverage`, `/gaps` and `/walkthrough` stay. They still return the synthetic sample. Removing them is follow-up ticket TC-25-011a (deprecate the legacy sample endpoints after clients move to `proof_summary`). TC-25-011 does not remove them.

## UI

`/dashboard/demo-proof` loads `GET /api/demo-proof` and renders `apps/web/lib/demoProofSummary.mjs`. The screen shows each fact's value, origin, basis, data window and the text "Not commercial traction". No-data facts display "No data". Unsupported facts display "Unsupported". The sample questionnaire is listed as a synthetic placeholder and its coverage numbers are not shown. A payload that claims commercial traction is not shown.
