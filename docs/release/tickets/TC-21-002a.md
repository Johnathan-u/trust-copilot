# TC-21-002a Unique canonical key and verified-status sync

**Status:** implemented. No framework text was added. Framework catalogs stay blocked pending TC-01-007.

## Uniqueness

`controls` and `workspace_controls` each have a partial unique index on `(workspace_id, canonical_key)` where `canonical_key` is not null.

Rows written before TC-21-002 still have a null key. Those rows are not backfilled, and several null keys in one workspace remain allowed.

A dirty database can already contain two non-null keys for the same workspace, because concurrent creates were not constrained. The migration keeps the oldest row's key. Later rows keep their status, name, and evidence. The cleared key is stored in `tc21002a_key_hold` so downgrade can put it back. Downgrade drops the unique indexes first, restores those keys, then drops the hold table.

An insert that loses the unique index is retried once and updates the row that won. It does not insert a second canonical key. An advisory lock is not used. The partial index is enough.

Migration `tc21002a_canonical_uniq` revises `tc21002_control_contract`. It does not import the application package.

## Verified status

`POST /api/compliance/controls/{id}/verify` still requires review. It sets the compliance row to `verified` and calls `sync_workspace_row`. That copies lifecycle `verified` onto the paired legacy control. The legacy `status` column has no verified value, so it is stored as `implemented`.

GET does not write. A control id from another workspace is 404.

## Ambiguities

- Null canonical keys are outside the unique index. Historical rows are not given a key.
- Duplicate non-null keys are resolved by keeping the oldest id. The later key is cleared and remembered for downgrade. The row itself is not deleted.
- A unique-index conflict retries the upsert once. A second conflict is not swallowed.
- `verified` still projects to legacy status `implemented`.
- `GET /api/compliance/controls/stats` has no control id. With no session workspace it returns zero counts. Id routes return 404 for another workspace.
- Suggest-evidence does not persist. It stays a review route.
