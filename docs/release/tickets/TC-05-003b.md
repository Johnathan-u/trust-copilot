## Contract and reproduced defect

The frozen [PRODUCT_SPEC](../../planning/PRODUCT_SPEC.md), identity section, bounds
custom-role grants by creator authority. TC-05-003 AC2 prohibits custom-role
escalation and lists these member/invite/key entry points. The definition-only
parent explicitly leaves these grant paths open.

A stored custom administrator with only `can_admin=true` can otherwise assign
itself builtin admin, assign another member a higher existing role, create an
accepted admin invitation, or issue an admin bearer key. The reconstructed matrix
fails 24 grant-ceiling assertions against the unchanged parent while 35 controls
pass, including real console invitation acceptance and bearer authorization.

## Bounded behavior

Only three `members.py` handlers and a minimal adapter change at runtime. The
adapter resolves current-workspace role permissions and reuses the existing actor
permission-snapshot ceiling before mutation. Invitations and keys treat all
enabled flags as new grants. Reassignment checks permissions absent from the
target's previous role, preserving unchanged grants and reductions.

Requested custom-role flags are loaded directly once. The existing boolean
permission resolver catches lookup failures as false, which must not be interpreted
as a target role with no grants. A target lookup error now propagates before any
mutation; existing invalid-role validation still returns its original 400.

Existing email/role/duplicate validation, neutral missing/foreign member 404s and
the last-admin guard retain their order and behavior. Builtin administrators retain
their supported operations; limited custom administrators may grant held flags.
Stale cookie role claims never supply the actor's permissions.
