## Behaviour

An export stays in the format the client requested (`xlsx` by default, or
`docx` when the request body says so).

- **XLSX render failure.** A corrupt workbook, a writer exception, or a source
  that is not an `.xlsx` file (DOCX, DOC, PDF, XLS) fails the job with
  `export_xlsx_failed` and the fixed message "The XLSX export could not be
  written. No substitute file was produced." No DOCX, CSV, or other file is
  uploaded. The exception text, paths, and storage details are not stored.
- **Storage failure.** If the rendered bytes cannot be uploaded, the job fails
  with `export_storage_failed` and the fixed message "The export could not be
  stored. No substitute file was produced." The rendered file is not replaced
  with another format.
- **Explicit DOCX.** A DOCX pack or an in-place DOCX write runs only when the
  client asked for DOCX. If that write cannot be produced (including when
  `python-docx` is not installed), the job fails with `export_docx_failed` and
  does not return CSV under a DOCX name.
- **Stale cell mapping.** When a question stores a file hash that is not the
  hash of the workbook being exported, or a ruleset of version 1 or newer
  whose question cell text, sheet or answer cell no longer matches, the XLSX
  export fails with `export_mapping_stale` and the fixed message "The workbook
  no longer matches the stored cell mapping. No answers were written." No
  workbook is uploaded and no answer is written into a neighboring cell. The
  message does not include the question text, the hashes or the cell
  addresses. A current version-1 mapping writes only the stored answer cell,
  not the question column plus `EXPORT_ANSWER_COL_OFFSET`. Rows with mapping
  version 0 and no file hash keep that offset.
- **Unsupported workbook structure** (TC-13-002) still raises
  `UnsupportedWorkbookStructure` and is still classified as terminal
  `bad_input`. It is not converted into a DOCX.
- **Failed export record.** The failure is committed on its own database
  connection so the worker's rollback of the attempt does not drop it. The row
  has `status=failed`, a filename whose extension is the requested format, and
  a sentinel `storage_key` ending in `.failed`. That key is not an uploaded
  object. The fixed code and message are the job's `error_code` and `error`.
  `GET /exports/records` returns those fixed strings and does not echo a stored
  exception. `GET /exports/records/{id}/download` returns 409 with the same
  code and message and does not stream a file.
- **Successful download.** The object content type matches the filename
  (spreadsheet for `.xlsx`, word-processing for `.docx`). The job result
  records `sha256`, `content_type`, and `filename`. The download response
  sends that content type, a `Content-Disposition` name with the same
  extension, and `X-Content-SHA256`. The header is the stored digest. If the
  stored digest does not match the object bytes, the download is 409
  `export_storage_failed` and the bytes are not returned. Exports written
  before a digest was stored still download by filename extension.

A completed export record for the same job is still reused on retry
(`outcome=already_applied`), and its recorded hash is kept. A failed record
does not count as a completed file; a later successful attempt updates that
row.

## Configuration

No new setting and no migration. `EXPORT_ANSWER_COL_OFFSET` is unchanged.
`export_records` keeps its current columns: the failure code lives on the
linked job, and the sha256 lives in the job result JSON. The jobs API still
drops extra result fields and returns only the canonical record id and
storage key.

## Operator note

A failed XLSX export did not produce a substitute document. The export list
shows status `failed` and the fixed message above. Do not look for
`*_answers_fallback.docx`. A 409 `export_mapping_stale` means the workbook
bytes or the mapped cells no longer match the stored mapping; re-import the
workbook before exporting again. Retrying after the workbook or storage
problem is fixed writes the requested format and records its sha256. If the
download responds 409 `export_storage_failed` for a completed export, the
stored file does not match the recorded hash and should not be treated as the
export.
