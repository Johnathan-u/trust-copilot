## Problem

The backfill treats only `object_version == 1` as complete. A re-rendered export at version 2 or higher, with a correct hash, is counted as pending, and `--execute` rewrites the object and resets the version to 1. The object is stamped before the row commits, so an interrupted `--execute` needs a documented re-run. A document moved with `reassign_parent_workspace` keeps its old storage key; the download is refused and the backfill counts the row as `disagreed`, which is the closed failure, and the runbook did not say so.

## Acceptance criteria

1. A row whose hash, media type, and positive object version already agree with the object's bytes, metadata, and workspace is skipped and counted as already complete, for documents and for exports. It is not rewritten and its version is not reset. A foreign key or a mismatched hash keeps today's refusal.
2. `docs/ops/storage-checksums.md` says an interrupted `--execute` is fixed by running the command again. A test shows a re-run after a simulated interruption (object stamped, row not committed) converges without resetting versions.
3. The same runbook section says a moved document keeps its old key, the download stays refused, and the backfill counts `disagreed`. A test asserts that count and does not weaken the refusal.

## Scope

P2 follow-up from the #353 review. No migration. It does not change the DONE count. It does not relax a 409 or the workspace, hash, version, or media-type checks.

## Behaviour

`backfill_storage_checksums` counts `already` when `content_sha256`, the checksum media type, and a positive `object_version` match the object bytes and, when the store reports it, the object metadata and the workspace. Documents compare `object_media_type`. Exports compare `content_type`. Version 2 or higher is included. Dry-run and `--execute` leave that object and that version as they are.

A key whose workspace does not match the row is still `disagreed`. A recorded hash that does not match the bytes, and an export whose job hash does not match, are still `mismatched`. A missing object is still `missing`. Null hashes are still filled with version 1 only when the row is not already complete. `--execute` still stamps the object before the row commit. The ops note says to run the command again if that run is interrupted. The second run does not reset a version that already agrees.

`reassign_parent_workspace` still does not rewrite the storage key. The download is still 409 `The stored file could not be verified.` with `X-Content-Type-Options: nosniff`, and the backfill still counts `disagreed`.
