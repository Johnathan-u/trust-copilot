# TC-19-001 Wire real Slack and Gmail providers by configuration

**Status:** implemented in code. Real Slack and Gmail sandbox qualification is **BLOCKED**.

**Epic:** E19 Slack, Gmail, and notification delivery.

## Behavior

`APP_ENV` is the process runtime. `MESSAGE_PROVIDER_RUNTIME_MODE` (`production` or `development`) selects the Slack and Gmail providers when `APP_ENV` is not `production`. `MESSAGE_PROVIDER_DEV_STUB` (`true`/`false`, also `1`/`0` and `yes`/`no`) is the explicit dev-stub flag.

| Runtime | Dev-stub flag | Result |
|---|---|---|
| production (`APP_ENV=production`, or `MESSAGE_PROVIDER_RUNTIME_MODE=production`) | unset or false | `HttpSlackProvider` and `HttpGmailProvider` |
| production | true | Startup preflight fails. Factories raise. No stub is returned and no delivery is reported. |
| production | `MESSAGE_PROVIDER_RUNTIME_MODE=development` | Preflight fails. Production cannot be downgraded to the stub. |
| development | unset or true | Labelled development stub (`provider_mode=dev-stub`, `provider_label=development-stub`) |
| development | false | HTTP providers |
| any | invalid mode or flag | Preflight fails. The stub is not selected. |

HTTP calls go through `OutboundHttpSeam` (fixed allowlist: `slack.com`, `gmail.googleapis.com`, `www.googleapis.com`, `oauth2.googleapis.com`; HTTPS port 443; no redirects; timeout; 1 MiB response cap) and `BoundedRetrySeam` (at most 3 attempts). Denied, missing-scope, and other non-retryable failures stop on the first attempt. Rate limits, timeouts, transport errors, and HTTP 5xx retry. Exhaustion is `ok: false` with `exhausted: true`.

Typed `error_code` values: `denied`, `missing_scope`, `rate_limited`, `unknown`, `not_implemented`, `unsupported`, `dev_stub_forbidden`. A failure is never `ok: true`. `list_channels` and `list_labels` do not return an empty list when the provider denied the call.

Not this ticket (explicit result, no network call):

- Slack `conversations.history`, `conversations.replies`, and `files.info` — `not_implemented` (TC-19-003). The old `AttributeError` fallback that invented stub messages for the HTTP provider is gone. The development stub still returns its labelled three-message fixture.
- Gmail threaded send — `not_implemented` (TC-19-007).
- OAuth install, state, and PKCE — `OAuthStatePkceSeam` returns `not_implemented` (TC-05-004, TC-19-002, TC-19-005). Connect still accepts a pasted token.
- Gmail attachment ingest still stores filename metadata only. The HTTP attachment GET returns bytes or a typed error, not empty bytes on failure (TC-19-006 owns filename and ingest).

Development stub sends keep `ok: true` so existing local tests still record a log row, and they set `delivered_to_provider: false`. The Slack test response says the message was not delivered to Slack. The Slack, Gmail, and notifications pages show a development-stub banner. A stub method called while the runtime is production returns `dev_stub_forbidden` and is not logged as sent.

Status, connect, channel, and label responses add `provider_mode`, `provider_label`, `runtime_mode`, `dev_stub`, and `provider_preflight_ok`. No database migration.
