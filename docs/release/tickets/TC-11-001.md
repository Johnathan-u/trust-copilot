# TC-11-001: typed model responses and failures

Status: implemented on `tc/core/TC-11-001` and held unmerged (Coordinator ruling Q1). Its
depends_on (TC-08-003, TC-08-004, TC-10-003, TC-09-002) are not DONE. Evidence is in
`artifacts/acceptance/TC-11-001/`.

## Behaviour
- **Typed outcomes** (`app/services/model_outcomes.py`, `ModelOutcomeCode`). Every generated
  answer now records one of:
  `grounded`, `grounded_unverified`, `no_evidence`, `model_abstained`, `model_refusal`, `model_malformed_output`,
  `model_unavailable`, `model_timeout`, `model_rate_limited`, `model_quota_exhausted`,
  `model_server_error`, `model_request_rejected`, `model_credentials_missing`,
  `model_credentials_invalid`, `model_error`.
  Each code has one safe, operator-written message, a `retryable` flag and a `fatal` flag
  (`OUTCOME_CATALOG`). Provider bodies are never read into messages.
- **Cache hits are never `grounded`** (Coordinator review). `grounded` is reserved for a draft
  the model produced in this run. A draft reused from the answer cache gets
  `grounded_unverified`, with the message "Draft answer reused from an earlier run. Its citations
  have not been re-checked against the current evidence. Verify them before approving." It is
  not a failure (HTTP 200, not retryable, not fatal). It is counted separately in
  `job.result.stats.outcomes`, and the zero-citation sweep relabels it to `no_evidence` exactly
  like `grounded`. Legacy `status=draft` and the answer text are unchanged, so exports are
  unaffected. This stays until claim-level citation checks (TC-11-003) and version-scoped caches
  (TC-08-004) land; those tickets decide whether a re-validated cache hit may be reported as
  `grounded`. A cached model abstention keeps `model_abstained`, which makes no grounding claim.
- **Classification** (`classify_provider_exception`) uses exception type and HTTP status only:
  401/403 → credentials invalid; 404 → model unavailable; 408/timeout → timeout; 429 → rate
  limited (or quota exhausted when the provider code is `insufficient_quota`); 400/413/422 →
  request rejected; 409/5xx/connection → server error; anything else → `model_error`.
- **Response envelope**: no choice or empty content → malformed; `message.refusal` or
  `finish_reason == "content_filter"` → refusal. Answer text starting with refusal phrases
  ("sorry", "i cannot", "as an ai", ...) → refusal; error/HTML/JSON-like text → malformed; the
  model's own "insufficient evidence" wording → `model_abstained` (distinct from `no_evidence`,
  which means retrieval/gating found nothing and no model call was made).
- **Fatal failures stop the job explicitly.** Missing key, rejected credentials, unavailable
  model and exhausted quota raise `ModelCallError` (a `ValueError` subclass; `str()` is the safe
  message). The batched path no longer falls back to one call per question after a fatal error,
  no further batches are submitted, the retry wrapper never retries fatal errors, and an
  embedding credentials/model failure stops the run before any completion call. Answers already
  written keep their typed `outcome_code`.
- **Transient failures** (timeout, 429, 5xx, unknown) keep the legacy per-question behaviour:
  status `insufficient_evidence`, text "Insufficient evidence.", `insufficient_reason=llm_error`,
  plus the typed `outcome_code`. `job.result.stats.outcomes` counts every outcome so a run that
  completed with provider failures is visible.
- **Persistence** (migration `076_tc11001_model_outcome_codes.py`, revision id
  `tc11001_model_outcome_codes`, down_revision `075`; additive, nullable): `answers.outcome_code`,
  `jobs.error_code`. Legacy rows stay NULL. Manual text edits clear `outcome_code`.
  The revision id is descriptive, not `076`, because TC-25-005 also adds a migration after 075.
  Whichever of the two merges second adds an alembic merge revision (or re-points its
  down_revision); a simulated collision gives two heads that merge cleanly
  (`artifacts/acceptance/TC-11-001/migration_collision_check.txt`). A scratch DB that was
  migrated with the pre-rename branch (`version_num = '076'`) must be re-stamped once:
  `UPDATE alembic_version SET version_num = 'tc11001_model_outcome_codes' WHERE version_num = '076'`.
  Rollback: `alembic downgrade 075`.
- **Worker**: for typed model failures `job.error` is the safe message and `job.error_code` the
  code; the same safe text goes to the failure log, ALERT log, audit event, admin notification
  and `documents.index_error`. Other exceptions keep the legacy `str(e)` (see Deferred).

## Shared error schema (`app/core/api_errors.py`)
`ApiError = {code, message, request_id, retryable, field_errors?}` (PRODUCT_SPEC ApiError).
- HTTP: `{"detail": "<legacy text>", "error": ApiError}`; `detail` is kept for compatibility.
  `POST /api/exports/generate/{id}` without a key → 503 with `error.code =
  model_credentials_missing`. Unhandled `ModelCallError` in any route → catalog HTTP status
  with the same body. Every response carries `X-Request-ID`.
- Jobs: `GET /api/jobs/{id}` adds `error_code` and `error_detail` (ApiError). `request_id` is
  the enqueuing request's ID (stored in the job payload) or, for legacy jobs, the polling
  request's ID. Failed jobs without a code report `job_failed` with a generic message.
- Answers: `GET /api/questionnaires/{id}` answer objects add `outcome_code` and `outcome`
  (ApiError shape).
- UI (`dashboard/review/[id]`): generate errors and failed-job toasts prefer
  `error.message (ref <request_id>)`. Every answer whose outcome is not `grounded` shows the
  outcome message as a badge, including `grounded_unverified` (`VERIFIED_GROUNDED_OUTCOME`).

## Configuration
No new settings. `OPENAI_API_KEY` semantics are unchanged.

## Operator / help note
| Code | What to do |
|---|---|
| `model_credentials_missing` | Set `OPENAI_API_KEY` for API and worker, restart. |
| `model_credentials_invalid` | Rotate/replace the key; check org/project access. |
| `model_unavailable` | Check the configured completion/embedding model name and account access. |
| `model_quota_exhausted` | Restore provider billing/quota, then re-run. |
| `model_rate_limited`, `model_timeout`, `model_server_error` | Re-run later (retryable). |
| `model_refusal`, `model_malformed_output`, `model_abstained` | Review/answer manually; add evidence. |
| `no_evidence` | Upload or scope evidence documents. |
| `grounded_unverified` | The draft came from the answer cache. Check its citations against the current evidence before approving. |
Quote the `ref` request ID when escalating; logs carry `code=... provider_status=...
exception_type=...` without provider text.
