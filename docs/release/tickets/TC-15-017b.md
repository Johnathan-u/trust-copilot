# TC-15-017b — Questionnaire list contract

Parent: TC-15-017. Registered from issue #85 comment 6901076574. Open. Not accepted. Not counted toward DONE.

The parent page was merged as progress. The list API still returned every row in one array and omitted question counts, review counts, job ids, job progress, `needs_review`, and a mapping-confirmation path. This child supplies that contract. It does not change job-detail projection, upload limits, deletion, or CI workflow files. `e2e/release/ui-16.spec.ts` already runs in `web-release-e2e` with `--require-spec`, `--min-tests 14`, and `--axe-dir`.

## Acceptance criteria

1. `GET /api/questionnaires` without `page`, `page_size`, `sort`, or `order` still returns a JSON array, newest `created_at` first, then `id` descending. Callers that do not send those parameters keep a list.
2. Sending any of `page`, `page_size`, `sort`, or `order` returns one page: `items`, `page`, `page_size`, `total`, `sort`, and `order`. `page` is 1-based. `page_size` is 1 to 100 and defaults to 25. `sort` is `created_at`, `filename`, `status`, or `id`. `order` is `asc` or `desc`. A missing partner uses those defaults. An unknown sort or order, `page` outside 1..1000000, or `page_size` outside 1..100 is HTTP 400. The page does not reorder rows in the browser.
3. Every row reports `question_count`, `review_reviewed`, `review_total`, `job_id`, `job_status`, `job_progress`, `mapping_ambiguous`, `mapping_confirmation_url`, and `needs_review`.
4. `question_count` and `review_total` are the number of stored questions. `review_reviewed` is how many of those questions have an answer whose status is `approved`.
5. `job_id` and `job_status` are the newest `parse_questionnaire` job in the same workspace whose payload names that questionnaire. `job_progress` is the newest `generated`/`total` pair on a `parse_questionnaire` or `generate_answers` job for that questionnaire, using the same integer rules as job history. A malformed payload or result is skipped. Another workspace's job is ignored. Stored result text is not copied onto the row.
6. `needs_review` is true when the questionnaire status is `needs_review`.
7. `mapping_ambiguous` is true when this workspace has a `suggested` mapping for the questionnaire. The confirmation URL is `/dashboard/questionnaires/{id}/confirm-mapping`. Otherwise the flag is false and the URL is null. A suggested mapping stored for another workspace does not count.
8. `GET /api/questionnaires/{id}/mapping-confirmation` requires a reviewer in the same workspace and lists only that questionnaire's suggested mappings. `POST` the same path requires an editor, approves every named suggested mapping, and changes nothing when any id is missing, duplicated, or not suggested. A reviewer receives 403 on POST. The wrong workspace receives 403.
9. `/dashboard/questionnaires` requests page 1, page size 25, sort `created_at`, order `desc`, and offers sort and page controls. It shows Needs review, uses a row job id when the newest jobs page does not include that job, and links Confirm mapping at the confirmation path. `/dashboard/questionnaires/{id}/confirm-mapping` lets an editor confirm the suggested mappings and lets a reviewer read them.

## What this ticket does not change

No database migration. `GET /api/jobs/{id}` still has no `progress` key. Backend role checks stay the existing reviewer and editor dependencies. CI workflow files are unchanged. Permanent deletion, the upload size limit, and CSV acceptance stay as TC-15-017 left them.
