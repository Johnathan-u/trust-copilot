## Behaviour

Line numbers are the ones in this change.

**One sentence.** `UnsupportedWorkbookStructure` still builds the export sentence (`apps/api/app/services/xlsx_writer.py:221-230`). `reject_unsupported_workbook` is unchanged in shape (`xlsx_writer.py:691-695`). `create_export_from_questionnaire` still calls it before it loads the workbook (`xlsx_writer.py:976`).

**Feature labels.** OOXML parts keep the labels export already used (`macros`, `shapes`, and the rest of `_DETECTORS`). A file that is not an OOXML zip is named when its OLE directory has `EncryptionInfo` or `EncryptedPackage` (`encryption`) or a BIFF `Workbook` or `Book` stream (`legacy .xls`) (`xlsx_writer.py:641-649`, called from `unsupported_workbook_features` at `:678-680`). A compound file with neither name is not a workbook feature. A corrupt file that is not one of those shapes still has no feature list.

**Intake.** `POST /api/questionnaires/upload` reads the bytes and, for a `.xlsx`, `.xlsm`, or `.xls` name that is within the size limit, calls `reject_unsupported_workbook` before `upload_raw` (`apps/api/app/api/routes/questionnaires.py:156-164`, `:212-219`). The HTTP 400 `detail` is `str` of that exception. Nothing is uploaded, and the handler does not commit a questionnaire or a parse job. Another workspace is still 403 before that read (`questionnaires.py:186-187`).

`iter_questionnaire_sheets` calls the same function before openpyxl (`apps/api/app/services/xlsx_parser.py:52-55`). A macro workbook openpyxl can open therefore never yields rows. An encrypted package or a legacy `.xls` raises `UnsupportedWorkbookStructure` instead of the generic `WorkbookUnreadable` sentence. A file that is not one of those shapes and cannot be opened still raises `WorkbookUnreadable`.

If a parse job is already holding a stored object, `run_parse_questionnaire` hits that parser raise before it inserts questions. `_handle_job_failure` stores the same sentence on the questionnaire (`apps/api/app/worker.py:531-545`, `:1415-1428`). The job stays terminal `bad_input`.

**Upload screen.** The questionnaire upload notice uses `mutationFailureNotice` (`apps/web/app/dashboard/questionnaires/page.tsx:754-759`). That helper keeps a `detail` string when it is not one of the four mapped failures (`apps/web/lib/api-error.ts:313-323`). The preflight sentence does not match those patterns, so the notice shows it. `apps/web/tests/unit/api-error.test.ts` locks the macros, encryption, and legacy `.xls` sentences. A questionnaire row that later carries `parse_metadata.error` shows that text on the list when it is at most 500 characters (`page.tsx:220-226`, `:1500-1503`) and on the detail page (`apps/web/app/dashboard/questionnaires/[id]/page.tsx:305`, `:337-347`). The sentence is shorter than 500 characters.

**What stops where.** Intake of `.xlsx`, `.xlsm`, and `.xls` stops on every label export already stops on, plus `encryption` and `legacy .xls`. Export of an `.xlsx` still stops on that same function, so the sentences match. A `.xlsm` name that has none of those features is still refused by the extension allowlist and is not stored. Evidence-document upload is not this path. No new configuration. No migration.
