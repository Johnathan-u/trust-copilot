## Cause and bounded repair

Master CI run `41020852388` reached backend tests and reported 4,512 passed,
one failed and one skipped. The reported session-persistence failure compared
`Max-Age=86400` with `86399`; an earlier branch exposed the same one-second
discrepancy at the new-workspace default bound.

Workspace creation computes `Max-Age` from the signed absolute deadline and the
integer clock at issuance. The test compared that immutable response header with
a later wall-clock reading. Crossing a second while returning or observing the
response makes the later remaining lifetime one second smaller. A controlled
advance after the real HTTP response reproduces that false failure for all three
deadline sources. The preceding exact signed-expiry and session-id checks pass.

The existing parametrized test now captures and freezes the issuance second with
its existing `monkeypatch` fixture. It requires exact equality between cookie
`Max-Age` and deadline minus that issuance second. It retains the exact signed
deadline, session identity, authenticated request before expiry, and HTTP 401 at
the deadline. An added direct token check at the deadline also proves token
validation rejects the expired token, independently of browser cookie disposal.

There are no production-code, dependency, policy, fixture, skip, or CI changes.
There is no TTL tolerance. Password authentication, signing, workspace creation,
stored sessions, and HTTP authorization still run through the real existing code.
