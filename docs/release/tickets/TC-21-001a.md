# TC-21-001a Framework catalog follow-ups

Follow-ups after the Coordinator merged PR #8 (squash `b0a49e4` on master). No new Alembic revision. The chain stays `075` → `tc21001_framework_catalog_rights` → `tc11001_model_outcome_codes`.

`framework_ids_for_exact_name` is unchanged.

## 1. Index drift on `framework_catalog_events.id`

**Resolution.** `FrameworkCatalogEvent.id` is `primary_key=True` without `index=True`. The primary key is already indexed. `index=True` made autogenerate want `ix_framework_catalog_events_id`, which `tc21001_framework_catalog_rights` does not create. Dropping the flag removes that drift, so this ticket adds no migration.

Confirmed with Alembic `compare_metadata` against the test database at head: no add/remove/change operation names `framework_catalog_events`. The model metadata has no extra index on `id`.

## 2. `rights_ticket` removed from customer API responses

**Resolution.** List items (`_virtual_blocked`, `serialize_framework`) and enablement errors (`_error`) no longer include `rights_ticket`. The response model drops the field, so it is absent rather than null. Provenance returned by those responses also omits the key.

`TC-01-007` stays in server logs (`framework enablement refused … rights_ticket=%s`), on the stored `frameworks.rights_ticket` column, in stored provenance JSON, and in `docs/release/tickets/TC-21-001.md`.

The release tests assert `rights_ticket` is absent from the list item, its `source_provenance`, and the enablement error, and that `TC-01-007` is not in those JSON bodies.

## 3. Rights column

**Resolution.** The Rights column renders `catalogRightsLabel`, which is always `Pending content licensing`. It does not render `rights_status` (`blocked_pending_rights`, `dev_test_only`, or any other stored value). `frameworkCatalog.test.ts` covers that label.

## 4. Dead code

**Resolution.** Removed:

- `hasLegacyListFields` and `LEGACY_LIST_FIELDS` in `apps/web/lib/frameworkCatalog.ts`
- the unreachable `rights_ticket === FRAMEWORK_RIGHTS_TICKET` branch in `isProductionCatalogEnabled`, and the unused `FRAMEWORK_RIGHTS_TICKET` export
- `reconcile_catalog` in `apps/api/app/services/framework_catalog.py` (nothing called it; GET and enable do not write catalog rows)

No test existed only to call `reconcile_catalog`. The vitest no longer calls `hasLegacyListFields`. Name lookups still use `framework_ids_for_exact_name`.
