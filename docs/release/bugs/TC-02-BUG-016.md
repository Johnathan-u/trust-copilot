# TC-02-BUG-016 Permissions catalog test depends on shared users

## Symptom

`tests/release/test_domain_compliance_frameworks.py::test_permissions_deny_enable_and_anonymous_list` passes alone and in the default suite order. It fails when the full `apps/api` suite runs in reverse:

```text
AssertionError: assert 'editor' == 'reviewer'
tests/release/test_domain_compliance_frameworks.py: membership.role
```

The same failure happens on master `1a0e614`. No other test in that file failed in that reverse run.

## Root cause

The test logged in as the shared `reviewer@trust.local` and `editor@trust.local` users and asserted that the reviewer's workspace-1 membership role was still `reviewer`.

`_ensure_test_data` creates that membership once per session and does not put the role back if a later test changes it. `tests/test_phase_d_slack.py::test_disabled_slack_does_not_fire` loads the first user who is not `demo@trust.local` (the shared reviewer, when the session seed created demo first) and patches that membership to `editor` without restoring it.

In collection order the Slack test is after the catalog test, so a forward run never sees the change. In reverse order the Slack test runs first and the catalog test then observes `editor`.

The HIPAA catalog row was a second implicit dependency (the migration seed, not this test). The reverse failure stopped on the role assertion before that lookup.

## Fix

The test now creates its own workspace (`slug=tc02-bug016`), reviewer, and editor, sets those roles and `suspended=False` on every run, and ensures a `catalog_key=HIPAA` row exists with `enablement_state=blocked` and `production_catalog=false` before the denied enable calls. The workspace insert advances `workspaces_id_seq` first, because the seed migration writes workspace id 1 explicitly and a fresh database would otherwise reuse id 1.

Assertions are unchanged: anonymous list and enable are 401, the reviewer membership role is `reviewer`, reviewer and editor can list and are refused enable with 403 (`Insufficient permissions` for the reviewer), the audit event count does not change, and the HIPAA row stays blocked and non-production.

Other tests in the file passed in the reverse suite and were not changed.
