# TC-02-BUG-018 Close stale open evidence gaps on regeneration

**Epic:** E21 Compliance controls, mappings and gaps (touches E11 answer generation, E12 answer review) · **Type:** Bug follow-up · **Priority:** P2
**Origin:** Follow-up logged in #36 (TC-02-BUG-015, merged `ce4d861`).

## Symptom

`generate_gaps_for_questionnaire` (`apps/api/app/services/evidence_gap_service.py`) only added one open `missing_evidence` gap per answer that was insufficient at the time. It never closed a gap when:

- the answer later became sufficient (regenerated with direct evidence, or edited or approved by a reviewer), or
- the question was removed from the questionnaire.

So open gaps drifted out of date and overstated missing evidence in the gaps view, the open-gap recommendations in compliance coverage, the export pack, demo proof, benchmarks and the executive dashboard.

## Fix

### Generator

The generator now reconciles a questionnaire's gaps on every run. All of its work happens in one transaction under `pg_advisory_xact_lock(150015, questionnaire_id)`. The lock is now taken **before** the answers, questions and gaps are read, and the old early return when nothing is insufficient is gone, so a run with zero insufficient answers can still close gaps.

A gap is closed only when it is `status == "open"` and `gap_type == "missing_evidence"`, and one of these is true:

| Reason code | Condition |
|---|---|
| `question_removed` | `question_id` is NULL (the FK is `ON DELETE SET NULL`) or no longer belongs to the questionnaire. |
| `answer_sufficient` | The question has at least one answer row and **no** answer row has status `insufficient_evidence`, `rejected` or `flagged` (`GAP_BLOCKING_ANSWER_STATUSES`). `draft` and `approved` are sufficient. |

Closing sets `status = "resolved"` and sets `updated_at` to the closure time. Rows are never deleted. TC-02-BUG-018 recorded the code and time by appending the note below. TC-02-BUG-018a stores them in `closed_at` and `close_reason` instead and leaves `reason` unchanged.

**Left open / untouched:**

- **Rejected or flagged answers:** a human or the system judged the answer not good enough, so the gap stays open. With several answer rows, one rejected, flagged or insufficient row keeps the gap open even if another row is a draft.
- **User decisions:** `accepted` and `dismissed` gaps are never closed or reopened, and they still block a duplicate gap for the same question.
- **Model-failure placeholders:** an answer with `insufficient_reason == "llm_error"` or a `model_*` outcome neither opens nor closes a gap. An open gap on such a question stays open, unchanged.
- **Unanswered questions:** a question with no answer row yet keeps its open gap.

**Reopening.** If an answer becomes insufficient again after its gap was resolved, a **new** open gap is created and the resolved row stays as history. A resolved gap does not count toward the duplicate check; every other gap (of any type) still does, as before.

**No route reopens a resolved row.** No handler under `apps/api/app/api` sets a `resolved` gap back to `open`. `update_evidence_gap_status` accepts a target of `open`, `accepted` or `dismissed` and does not look at the current status, but nothing in the API calls it (or `bulk_update_by_title` or `list_evidence_gaps`). A later insufficient answer opens a new gap; the resolved row stays history.

**Concurrency.** With the lock taken first, overlapping runs serialize. The second run sees the first run's commit, so a stale gap is resolved once (its note is not appended twice) and there is exactly one open gap per insufficient question.

**Return value.** `{"generated": n, "total_insufficient": m, "resolved": r}`. The only caller, answer generation, reads `generated` only.

### Closure note format (historical; TC-02-BUG-018a no longer appends it)

The original `reason` text is kept byte for byte. The note is appended on its own final line:

```text
<original reason, unchanged>
[resolved on regeneration: <code> at <UTC ISO-8601, seconds>Z]
```

Example:

```text
No workspace evidence supports an answer to this question. Reason code: no_citations.
[resolved on regeneration: answer_sufficient at 2026-10-27T14:30:15Z]
```

- `<code>` is `question_removed` or `answer_sufficient`.
- The timestamp equals the `updated_at` written in the same transaction, truncated to seconds.
- If `reason` was NULL the note is the whole value.
- Parse it with the last line of `reason` and the prefix `[resolved on regeneration: ` (`RESOLUTION_NOTE_PREFIX`); helpers are `resolution_note()` and `append_resolution_note()` in `evidence_gap_service.py`.

TC-02-BUG-018a (`docs/release/bugs/TC-02-BUG-018a.md`) is implemented. New closures write `closed_at` and `close_reason` and do not append this note. The migration parses a last line in this form to backfill rows that already have it, and leaves `reason` unchanged.

### Gap totals shown to users and buyers

`resolved` is not a gap any more. Every user- or buyer-facing gap total excludes it, and views that break gaps down by status report it separately:

| Service | Output | Change |
|---|---|---|
| `export_pack_service.generate_evidence_bundle` (export pack, buyer-facing) | `evidence_gaps` list | Resolved rows are not listed. New `evidence_gaps_resolved` count. |
| `demo_proof_service._collect_gaps` (`evidence_gaps_stored` metric, `evidence_gaps_identified`) | metric `value` / `numerator` | Resolved rows are excluded and counted under `exclusions.resolved` (this metric only). |
| `benchmark_service._evidence_metrics` | `evidence_gaps` | Excludes resolved. New `evidence_gaps_resolved`. |
| `executive_dashboard_service._content_metrics` | `evidence_gaps` | Excludes resolved. New `evidence_gaps_resolved`. |
| `evidence_gap_service.gap_summary` (per-status counts) | `total` | `total` = open + accepted + dismissed. `resolved` is its own key and is not added to `total`. |

Already correct and unchanged: `compliance_coverage` recommendations filter `status == "open"`. `list_evidence_gaps` returns rows with their status (an optional status filter), so it is a list rather than a total.

## Status model, without a migration

`evidence_gaps.status` is `String(20)` with no check constraint. This change:

- adds a system-only value, `GAP_STATUS_RESOLVED = "resolved"`, plus `ALL_GAP_STATUSES`;
- leaves the user-settable `GAP_STATUSES`, used by `update_evidence_gap_status` and `bulk_update_by_title`, unchanged, so a user cannot set `resolved`;
- records the time in `updated_at`. TC-02-BUG-018 also appended the delimited note above; TC-02-BUG-018a stores the code and time in `close_reason` and `closed_at` instead.

TC-02-BUG-018 added no migration and no partial unique index (a separate decision that needs a dedupe migration). TC-02-BUG-018a adds `closed_at` and `close_reason`.

## Resolved decisions

1. **Closure record:** TC-02-BUG-018 used `updated_at` plus an appended, delimited note, with the original reason intact. TC-02-BUG-018a replaces that for new closures with `closed_at` and `close_reason`. Historical notes stay in `reason` and are what the migration backfill parses.
2. **Totals:** fixed in this change. Any total presented to users or buyers as gaps (export pack, demo proof, benchmark, executive dashboard) excludes resolved gaps; per-status views list resolved separately. One test per service.
3. **Rejected / flagged answers:** keep the gap open. Close only when the question was removed or has an answer that is sufficient (not rejected, flagged or insufficient). Tested for both.
4. **Bug index:** TC-02-BUG-015, 016 and 018 are added to `docs/bugs/TC-02-BUGS.md`.
5. **Reopening a resolved gap through the API:** resolved. No route sets a resolved gap back to `open`. `update_evidence_gap_status` would accept that target, but no handler in `app/api` calls it. A later insufficient answer opens a new gap; the resolved row stays history.

## Acceptance criteria

- **AC1:** Regenerating after an answer becomes sufficient closes its open gap: status `resolved`, original reason intact, `updated_at` updated. TC-02-BUG-018a records the code and time on `close_reason` and `closed_at`. A rejected or flagged answer keeps it open.
- **AC2:** Manually accepted or dismissed gaps and `llm_error` placeholders are untouched. Concurrent runs still yield exactly one open gap per insufficient question.
- **AC3:** Export pack, demo proof, benchmark, executive dashboard and `gap_summary` totals exclude resolved gaps and report them separately.
