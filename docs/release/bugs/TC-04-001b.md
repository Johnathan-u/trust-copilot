# TC-04-001b Workspace creation limiter and creation-policy read

## Rate limiter

`POST /api/workspaces` uses the shared limiter. Without `REDIS_URL` that limiter is in-memory
and per-process. The Redis backend fails open on store errors for every other route. In
production this route fails closed: HTTP 503, detail
`Workspace creation is temporarily unavailable. Try again later.`, and `Retry-After`.
Development and test still allow the request and log a warning. The warning does not include
store addresses or secret values.

## `GET /api/workspaces/creation-policy`

Requires a signed-in user (401 otherwise). The body is exactly
`{"can_create_workspace": <bool>}`. The boolean is the same signup-policy decision as
`POST /api/workspaces` (`_may_create_workspace`): invitation-only allows an active owner/admin
or a verified deployment operator; self-signup also allows a verified user. The per-user cap
and the hourly throttle are not included. Those remain 409 and 429 on POST.
