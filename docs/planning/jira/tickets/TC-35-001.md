**Goal:** On top of the parent organization from TC-32-010, give MSP staff roles that work across the client workspaces their MSP manages.

**Acceptance criteria**

1. An MSP organization has MSP admin and MSP analyst roles; MSP admins manage staff and client workspaces, analysts work inside assigned clients only.
2. MSP staff access to a client workspace is resolved server-side from current membership on every request (no trust in stale cookies).
3. Client users never see other clients of the same MSP, the MSP's staff list, or MSP-level settings.
4. Removing an MSP staff member revokes access to every client workspace immediately.
5. Every cross-client action is written to the audit log with MSP, staff user and client workspace.

**Definition of done:** tests at the path above pass in CI, including negative cross-tenant cases; reviewed by someone other than the implementer; migration has upgrade and rollback evidence.\
Workflow: see SCRUM-35.
