**Goal:** MSP staff jump between clients quickly without ever mixing up whose data they are looking at.

**Acceptance criteria**

1. Header switcher lists the MSP's clients with search; recent clients first.
2. The current client's name and logo are always visible; switching clients shows a brief confirmation.
3. Switching refreshes all cached data, open forms warn about unsaved changes, and no previous client's data remains on screen (extends TC-16-002).
4. Deep links include the client workspace so a link opened by another MSP user lands in the right client or is denied.

**Definition of done:** Playwright spec passes including the no-data-bleed check; reviewed by a second person.\
Workflow: see SCRUM-35.
