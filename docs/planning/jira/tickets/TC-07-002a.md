**Why:** Owner sign-off OD-13 (2026-11-06, `docs/acceptance/release-decisions.md`) accepted TC-07-002 on the condition that production sets four distinct keyrings. Today production only checks keyrings that are set, and any unset keyring falls back to a key derived from `SESSION_SECRET` (`v0-legacy`).

**Acceptance criteria**

1. In production, the config contract (`apps/api/app/core/config_contract.py`) refuses to start unless `SESSION_KEYRING`, `OAUTH_STATE_KEYRING`, `MFA_KEYRING` and `CONNECTOR_KEYRING` are all set, strong, and different from each other and from `SESSION_SECRET`. Error messages name the variable but never show its value. Development and test behaviour is unchanged.
2. `docker-compose.prod.yml`, `.env.example` and the generated `docs/release/config-contract.md` require all four keyrings. Release tests cover each refusal: missing, weak, duplicate, and equal to `SESSION_SECRET`.
3. An operator runbook (`docs/ops/key-rotation.md`) explains three things: how to rotate keys in production (run the rotation tool on a copy, then cut over), how to back up keyrings, and how to recover a workspace whose only admin is locked out of MFA (a database-level procedure with an audit record).

**Evidence:** CI release tests plus the runbook. An independent reviewer signs off; under OD-14 no separate owner sign-off is needed.
