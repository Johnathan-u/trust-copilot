**Goal:** When a client forwards a questionnaire to the MSP, the MSP drops it in one place and it lands in the right client. The MSP doesn't have to switch into the client first.

**Acceptance criteria**

1. A "New questionnaire" button in the MSP header opens one upload dialog: file (XLSX, DOCX, PDF, CSV), client (searchable), requester company, due date.
2. On submit, the file is parsed in the chosen client's workspace (same pipeline as a normal upload). The MSP gets a link straight to it.
3. If a file name or requester matches a previous questionnaire for a different client, the dialog warns before submitting, to prevent sending a file to the wrong client.
4. Uploads to a client workspace the user cannot access are rejected by the API, not just hidden in the UI.
5. Works by keyboard and at 360 / 768 / 1440 px.

**Definition of done:** Playwright spec passes, including the wrong-client warning and the API rejection. Reviewed by a second person.\
Workflow: see SCRUM-35.
