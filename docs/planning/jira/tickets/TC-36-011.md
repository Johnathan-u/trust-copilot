**Goal:** Prove that a white-labelled MSP's clients never see TrustCopilot. One leaked logo in a PDF sent to an MSP's client is the fastest way to lose that MSP.

**Acceptance criteria**

1. One account-level switch, "Hide TrustCopilot branding from my clients", turns white-label on for everything at once: exports, trust page, emails, portal, error pages, file metadata.
2. A release test creates a branded MSP and a client, then runs the full flow: upload, generate, approve, export XLSX/DOCX/PDF/evidence pack, trust page, all emails, 404/500 pages.
3. The test fails if "TrustCopilot" (any case), the TrustCopilot logo hash, or the default favicon appears in any HTML, email, file text or file metadata (author, producer, creator) a client user can get.
4. Allowed exceptions (e.g. the legal sub-processor list) are kept in one reviewed allowlist file, with a reason for each.
5. The test runs in CI on every PR that touches templates, exports or the web app.

**Definition of done:** tests pass and are wired into CI. A deliberately added "TrustCopilot" string in a template makes the test fail. Reviewed by a second person.\
Workflow: see SCRUM-35.
